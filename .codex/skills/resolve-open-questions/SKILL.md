# resolve-open-questions

`docs/frontend/tasks/<フォルダ名>/NN_open_questions.md` に溜まった未決事項（設計書の【要確認】項目、Codexの仮決定事項）を、ユーザーへの確認を通じて正式決定にするスキル。

## 手順

1. **対象ファイルの確定**: パスが指定されていなければ `docs/frontend/tasks/**/*open_questions.md` を列挙し、どのファイルかユーザーに確認する。
2. **ファイルを読む**: 対象ファイル全文を読み、「## 未決事項」節にある `- [ ]` 項目をすべて抽出する。既に `- [x]` の項目は対象外。未決事項が0件なら、その旨を報告して終了する。
3. **1件ずつユーザーに確認する**: plan mode中のユーザー入力要求ツール（request_user_input相当）を使い、未決事項を1件ずつ順番に問いかける。まとめて質問しない。質問文には該当項目の全文（出典セクションがあれば含む）を提示し、選択肢が自明でなければ自由記述で決定内容を求める。「## Codexによる仮決定ログ」に対応する仮決定が既にある場合は、それを判断材料として質問文に含める。
4. **回答が得られ次第、都度ファイルに追記する**（全件終わるのを待たない）:
   - 「## 未決事項」節: 該当項目を `- [x]` に変更する。
   - 「## Codexによる仮決定ログ」の直前に「## ユーザーによる決定事項」節を新設（未作成の場合のみ）し、以下の形式で追記する:
     ```markdown
     ## ユーザーによる決定事項

     - [x] <未決事項の要約>: <決定内容の1〜2行要約>
     ```
   - 対応する仮決定が「## Codexによる仮決定ログ」に既にある場合、それが今回の決定と食い違うなら一言添えて明示する（例: 「※仮決定から変更」）。
5. **完了報告**: 全項目の確認が終わったら、決定した内容を短くユーザーに要約する。決定内容が既存実装（Codexが仮決定に基づいて書いたコード）と食い違う場合は、該当タスクファイルの再着手が必要になりうる旨を一言添える。

## 注意点

- ユーザーの回答をそのまま丸めず、決定内容として実装に使える粒度（具体的な値・方針）に要約する。曖昧な回答は追加で聞き返す。
- ファイル内の他の節（タスク一覧・テストリストなど）は変更しない。このスキルの責務は open_questions.md の確定のみ。
