## エピック1: 結合環境の起動

### ストーリー 1.1: 単一コマンドでのフルスタック起動 🔵

**信頼性**: 🔵 *PRD 検証方法・ヒアリングQ5より*

**私は** 開発者 **として**
**`docker compose up` を実行するだけでfrontend・backend・dbを一括起動したい**
**そうすることで** 個別にサービスを立ち上げる手間なく結合動作確認ができる

**関連要件**: REQ-001, REQ-101, NFR-201

**詳細シナリオ**:
1. 開発者がリポジトリルートで `docker compose up` を実行する
2. `db` コンテナが起動し、ヘルスチェックに成功する
3. `backend` コンテナが `db` のヘルス成功を待って起動する
4. `frontend` コンテナ（nginx）が起動し、ホストの80番ポートでリクエストを待ち受ける

**前提条件**:
- Docker / Docker Composeがインストールされていること
- `backend/.env` 等、必要な環境変数ファイルが用意されていること

**制約事項**:
- `backend`・`db` はホストにポートを公開しない

**優先度**: Must Have

### ストーリー 1.2: バックエンド・DBへの直接アクセス遮断 🔵

**信頼性**: 🔵 *ヒアリングQ5・REQ-401より*

**私は** 開発者 **として**
**backendとdbにホストから直接アクセスできないようにしたい**
**そうすることで** 本番同様にfrontend経由のみのアクセス経路をローカルで再現し、意図しない直接アクセスを防げる

**関連要件**: REQ-201, REQ-401, NFR-101

**詳細シナリオ**:
1. 開発者が統合用docker-composeで環境を起動する
2. ホストマシンから `localhost:8080`（backend）や `localhost:5432`（db）へ接続を試みる
3. ポートが公開されていないため接続できない

**前提条件**:
- 統合用docker-composeが `ports:` を設定していないこと

**優先度**: Must Have

## エピック2: フロントエンド・バックエンド間のAPI疎通

### ストーリー 2.1: 同一オリジンでのAPI呼び出し 🔵

**信頼性**: 🔵 *PRD nginx設定例・ヒアリングQ4より*

**私は** 開発者 **として**
**ブラウザからfrontendにアクセスした際、CORS設定なしでbackend APIを呼び出したい**
**そうすることで** クロスオリジン設定の手間や不整合なく結合動作確認ができる

**関連要件**: REQ-007, REQ-008, REQ-009, REQ-102

**詳細シナリオ**:
1. 開発者がブラウザでfrontend（例: `http://localhost`）にアクセスする
2. フロントエンドJSが `/api/v1/...` への相対パスでAPIリクエストを発行する
3. nginxが `/api/` 宛のリクエストを `http://backend:8080/api/` へリバースプロキシする
4. backendがレスポンスを返し、ブラウザ上で結果が表示される

**前提条件**:
- `frontend/src/api/client.ts` のデフォルトURLが相対パス `/api/v1` に変更されていること
- nginxの `/api/` プロキシ設定が正しく構成されていること

**優先度**: Must Have

### ストーリー 2.2: SPAルーティングのフォールバック 🟡

**信頼性**: 🟡 *PRD nginx設定例（`try_files $uri /index.html`）から妥当な推測*

**私は** 開発者 **として**
**フロントエンドの任意のルート（例: `/settings`）に直接アクセス・リロードしても正しく表示したい**
**そうすることで** SPAのルーティングを結合環境でも違和感なく確認できる

**関連要件**: REQ-008

**詳細シナリオ**:
1. 開発者がブラウザで `http://localhost/settings` に直接アクセスする
2. nginxは該当する静的ファイルが存在しないため `index.html` を返す
3. フロントエンドのReact Routerがクライアントサイドでルーティングを解決する

**前提条件**:
- nginx設定に `try_files $uri /index.html` が含まれること

**優先度**: Should Have

**備考**: PRDのnginx設定例に基づく推測。実際のReact Router構成での動作確認が必要
