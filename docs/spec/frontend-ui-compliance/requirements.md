# フロントエンドUIデザイン準拠 要件定義書（軽量版）

## 概要

現行フロントエンド実装(`frontend/`)を、`docs/frontend/ui/`のモックアップ（Obsidianライクな3ペイン・ダークUI）の視覚デザインに準拠させる。対象範囲はデザイントークン・レイアウト構造・コンポーネントの視覚表現に限定し、機能要件（画面構成・API連携・データ項目）は対象外とする。

Propertiesパネルの中身（key-value/タグ/関連付け/スタッフ/マイリスト所属の具体的な表示ロジック）は今回のスコープ外とし、3ペインレイアウトの構造（右側のカラム確保）とパンくず/タイトルバーのみを対象とする。

## 主要機能要件

**【信頼性レベル凡例】**:
- 🔵 **青信号**: PRD・設計文書・ユーザヒアリングを参考にした確実な要件
- 🟡 **黄信号**: PRD・設計文書・ユーザヒアリングから妥当な推測による要件
- 🔴 **赤信号**: PRD・設計文書・ユーザヒアリングにない推測による要件

### 必須機能（Must Have）

- REQ-001: `frontend/src/index.css`のデザイントークン（背景色・ボーダー・文字色・単一アクセント色・フォント・角丸）を`docs/frontend/ui/_shared.css`の値に合わせて再定義する 🔵 *PRD「デザイントークン移行方針」表より*
- REQ-002: media_type別アクセントカラー（`--accent-anime`等8色）は既存実装のまま維持し、`_shared.css`の単一アクセント色（`--accent`）とは独立したトークンとして共存させる 🔵 *ヒアリング回答「両立（推奨）」より*
- REQ-003: `Sidebar.tsx`をモックアップ準拠に拡張する — ブランドロゴ、ナビ項目の件数バッジ、サブカテゴリのインデント階層、「ライブラリ」セクション見出し、「設定」の下部固定配置 🔵 *PRD「全体一覧」節より*
- REQ-004: `MediaCard`コンポーネントをモックアップ準拠に更新する — カバー画像プレースホルダ（グラデーション）、media-typeバッジのオーバーレイ表示、★お気に入りアイコン、ステータスドット（進行中/完了/未着手の色分け） 🔵 *PRD「全体一覧」節・共通コンポーネント表より*
- REQ-005: 全体一覧画面にフィルタバー（`.chip`によるステータス/タグ絞り込み + 検索ボックス）とタイトルバー右上の「＋ 作品を追加」ボタンを実装する 🔵 *PRD「全体一覧」節より*
- REQ-006: `RootLayout.tsx`を`.app-shell`グリッド構造（sidebar / main、詳細画面のみ+properties列分の空間）に変更する 🔵 *PRD共通コンポーネント表「3ペインApp Shell」より*
- REQ-007: アイテム詳細画面にパンくずリスト、タイトルバー右の「編集」「削除」ボタン、カバー画像・タイトル・原題・概要セクションを実装する 🔵 *PRD「アイテム詳細」節より*
- REQ-008: 検索・追加画面の検索結果リストをモックアップ準拠（サムネイルプレースホルダ + タイトル + 等幅フォントのサブ情報）に更新する 🔵 *PRD「検索・追加」節より*
- REQ-009: 手動追加・編集フォームを2カラムグリッド（`.form-grid`）、必須マーク、エラー表示、フィールドヒント、下部操作ボタン群に対応させる 🔵 *PRD「手動追加・編集フォーム」節より*
- REQ-010: 設定画面を左タブ+右パネルのレイアウト（APIキー管理/インポート/エクスポート）に更新し、APIキー管理は`.kv-card`表示に対応させる 🔵 *PRD「設定」節より*
- REQ-011: 共通ボタンバリアント（`.btn`, `.btn-accent`, `.btn-ghost`, `.btn-sm`, `.btn-danger`）とタグピル（`.tag-pill`）、空状態（`.empty-state`）を実装する 🔵 *PRD共通コンポーネント表より*

### スコープ外（今回対象としない）

- Propertiesパネルの中身（key-value行、タグ一覧、カテゴリ一覧、関連付け一覧、スタッフ一覧、マイリスト所属一覧の具体実装） 🔵 *ヒアリング回答「この理解でよい」より次回以降*
- シーズン/話数のグループ表示（`.group-block`等、アニメ・ドラマ向け詳細UI） 🟡 *Propertiesパネル同様、詳細表示の作り込みとして次回以降と推測*
- レスポンシブ最適化（`_shared.css`の`@media (max-width: 980px)`準拠範囲を超えるもの） 🔵 *PRD「やらなくていいこと」より*
- ライトモード等のテーマ切替 🔵 *PRD「やらなくていいこと」より*
- モックアップにない新規ビジュアル要素の追加 🔵 *PRD「やらなくていいこと」より*

### 基本的な制約

- REQ-401: 機能要件（画面構成・API連携・データ項目等）は変更しない。視覚表現の変更に留める 🔵 *PRD「対象範囲」より*
- REQ-402: shadcn由来の`oklch`系トークン（`--primary`, `--card`等）は`_shared.css`の対応する色に上書きする 🔵 *PRD「デザイントークン移行方針」より*

## 簡易ユーザーストーリー

### ストーリー1: デザイントークンの統一

**私は** フロントエンド開発者 **として**
**アプリ全体の背景色・文字色・アクセント色・フォント・角丸をモックアップ準拠のトークンに統一したい**
**そうすることで** 今後の画面実装がモックアップと視覚的に一致した基盤の上で行える

**関連要件**: REQ-001, REQ-002, REQ-402

### ストーリー2: 全体一覧画面の視覚準拠

**私は** MediaVaultの利用者 **として**
**サイドバーのナビゲーション階層・件数バッジ・MediaCardのビジュアル（カバー/バッジ/お気に入り/ステータス）を見たい**
**そうすることで** モックアップ通りの見やすい一覧画面を利用できる

**関連要件**: REQ-003, REQ-004, REQ-005, REQ-006

### ストーリー3: 詳細・検索・フォーム・設定画面のレイアウト準拠

**私は** MediaVaultの利用者 **として**
**アイテム詳細の3ペイン構造・検索結果一覧・フォームの2カラムレイアウト・設定画面のタブ構成を、モックアップと同じ見た目で利用したい**
**そうすることで** 各画面を一貫したデザインで操作できる

**関連要件**: REQ-006, REQ-007, REQ-008, REQ-009, REQ-010

## 基本的な受け入れ基準

### REQ-001: デザイントークンの再定義

**Given（前提条件）**: `frontend/src/index.css`に旧トークン（`--bg-base`, `--text-secondary`等）が定義されている
**When（実行条件）**: `_shared.css`準拠の値（`--bg-app: #1e1e1e`等）に置き換える
**Then（期待結果）**: アプリ全体の背景・文字・アクセント・角丸がモックアップと同一の視覚結果になる

**テストケース**:
- [ ] 正常系: 全体一覧・詳細・設定の各画面でダーク背景(`#1e1e1e`系)・単一アクセント色(紫系)が表示される
- [ ] 主要な異常系: media_type別アクセントカラーが引き続き各MediaCardのバッジ等で正しく表示される（トークン統一による色の巻き込み事故がない）

### REQ-004: MediaCardの視覚表現

**Given（前提条件）**: 一覧画面にアイテムが表示されている
**When（実行条件）**: MediaCardをレンダリングする
**Then（期待結果）**: カバー画像プレースホルダ、media-typeバッジ、★お気に入りアイコン、ステータスドットが表示される

**テストケース**:
- [ ] 正常系: お気に入り=true のアイテムで★アイコンが表示される
- [ ] 主要な異常系: ステータス未設定（none）の場合グレーのステータスドットが表示される

### REQ-006: 3ペインApp Shell

**Given（前提条件）**: `RootLayout.tsx`が現状2カラム（sidebar/main）構成である
**When（実行条件）**: 詳細画面表示時に`.app-shell.has-properties`相当のグリッド構造を適用する
**Then（期待結果）**: 右側にproperties列分の空間（`--properties-w: 300px`）が確保される（中身の実装は次回以降）

**テストケース**:
- [ ] 正常系: アイテム詳細画面で3カラムのグリッドレイアウトが表示される
- [ ] 主要な異常系: 一覧画面等properties列不要の画面では2カラム構成のまま崩れない

## 最小限の非機能要件

- **パフォーマンス**: デザイントークン変更によるレンダリング性能の劣化がないこと（既存のCSS変数置き換えのみのため影響は限定的） 🟡 *変更範囲がCSSトークンレベルに留まることからの妥当な推測*
- **アクセシビリティ**: 色変更後もコントラスト比がWCAG 2.1 AA基準を満たすこと（`tech-stack.md`記載の既存品質基準を踏襲） 🔵 *tech-stack.md品質基準より*
