## エピック1: コレクションを検索・理解する

### ストーリー 1.1: 所蔵を確認する（US-01）🔵

**信頼性**: 🔵 *PRD §5 US-01より*

**私は** コレクション所有者 **として**
**作品名や条件を自然言語で指定し、自分の MediaVault に登録済みか確認したい**
**そうすることで** 重複購入や重複登録を避け、手元にある作品をすぐ利用できる

**関連要件**: REQ-010, REQ-011, REQ-012, REQ-013, REQ-014, REQ-143

**詳細シナリオ**:
1. 利用者が会話の中で「〇〇って持ってたっけ？」と尋ねる
2. AI が `search_library` をタイトル指定で呼び出す
3. MCP が本題・原題・別名を対象に MediaVault-api を検索する
4. MCP が候補一覧（ID・メディア種別・公開年・状態・タグ）と該当件数を返す
5. 同名作品が複数ある場合、AI が候補を提示して利用者に選ばせる

**前提条件**:
- MediaVault-api が稼働している
- MediaVault-api が別名・原題検索に対応している（[prep.md](prep.md) PREP-02）

**制約事項**:
- 返却件数は既定20件・上限50件（REQ-143）
- 0件の場合も外部カタログ検索の結果と混同されない形で返す

**優先度**: Must Have

### ストーリー 1.2: 作品についてAIへ相談する（US-02）🔵

**信頼性**: 🔵 *PRD §5 US-02より*

**私は** コレクション所有者 **として**
**作品の基本情報だけでなく、ファイル・リンク・関連作品・スタッフ・シーズンや巻も含めてAIに理解してほしい**
**そうすることで** 視聴先確認、比較、調査を一度の会話で進められる

**関連要件**: REQ-020, REQ-021, REQ-022, NFR-002, NFR-005

**詳細シナリオ**:
1. AI が `search_library` で対象 Item を特定する
2. AI が `get_item_context` を Item ID 指定で呼び出す
3. MCP が `GET /items/{id}` に加え、関連・マイリスト・グループ・キャスト・ファイル・リンク・トレーラーを**並列に**取得する
4. MCP が各セクションについて「未登録」「取得失敗」を区別した構造化データを返す

**前提条件**:
- 対象 Item が MediaVault に存在する

**制約事項**:
- 集約APIは実装せず、MCP側で複数API合成する（ヒアリング2026-08-07で確定）
- 一部の取得が失敗しても、取得できた情報は返す

**優先度**: Must Have

---

### ストーリー 1.3: 次に見る・読む候補を相談する（US-09）🔵

**信頼性**: 🔵 *PRD §5 US-09より*

**私は** コレクション所有者 **として**
**「未視聴のお気に入り映画」「積読の短い本」など、自分のコレクションを材料にAIへ候補を選んでほしい**
**そうすることで** 一般的な推薦ではなく、実際に所有しているものから選べる

**関連要件**: REQ-010, REQ-013, REQ-090, REQ-144

**詳細シナリオ**:
1. AI が `collection_overview` で全体像（メディア種別別・状態別・お気に入り件数、最近の追加・更新）を把握する
2. AI が `search_library` を条件付きで呼び出し、候補集合を取得する
3. MCP が候補と根拠となるメタデータ、および該当件数を返す
4. 推薦の判断自体は呼び出し元 AI が行う

**制約事項**:
- MCP は推薦を生成しない（REQ-144）
- 未登録の属性を推測値として返さない

**優先度**: Must Have

## エピック2: 作品を登録する

### ストーリー 2.1: 外部カタログから作品を追加する（US-03）🔵

**信頼性**: 🔵 *PRD §5 US-03・`GET /items/search` / `POST /items/import` の実装より*

**私は** コレクション所有者 **として**
**タイトルを伝えるだけで外部APIから候補を検索し、確認した作品を MediaVault へ追加したい**
**そうすることで** 画面を移動して検索・転記する手間がなくなる

**関連要件**: REQ-030, REQ-031, REQ-032, REQ-033, REQ-112, REQ-117, NFR-003, NFR-202

**詳細シナリオ**:
1. AI が `search_library` で未登録であることを確認する
2. AI が `search_external_catalog` をメディア種別と検索語で呼び出す
3. MCP が候補（タイトル・公開年・種別・プロバイダー・プロバイダー固有ID）を返す
4. AI が候補を提示し、利用者が1件を選択する
5. AI が `import_external_item` をプロバイダー固有ID + プロバイダー名で呼び出す
6. 既にインポート済みなら重複を作らず既存 Item を返す

**前提条件**:
- 対象メディア種別のプロバイダーAPIキーが MediaVault に設定済み（[prep.md](prep.md) PREP-06）

**制約事項**:
- 対象が一意に確定する前に登録しない
- ローカル検索と外部検索はツール名・説明・レスポンスのすべてで区別する

**優先度**: Must Have

### ストーリー 2.2: 手元の資料をすばやく記録する（US-04）🔵

**信頼性**: 🔵 *PRD §5 US-04より*

**私は** コレクション所有者 **として**
**外部APIに存在しない個人資料、同人作品、ローカルファイルなどを会話から手動登録したい**
**そうすることで** 後回しにして記録を失うことを防げる

**関連要件**: REQ-040, REQ-041, REQ-114, EDGE-004, EDGE-103

**詳細シナリオ**:
1. AI が `create_item` をタイトルとメディア種別で呼び出す
2. 任意でファイルパス、URL、タグ名、マイリスト名を同じ呼び出しに含める
3. MCP が Item を作成し、続けて関連付けを実行する
4. 一部が失敗した場合、作成済み Item ID と、成功・失敗・未処理の内訳を返す

**制約事項**:
- タイトルが空白のみの場合は登録しない

**優先度**: Must Have

## エピック3: 記録・整理する

### ストーリー 3.1: 視聴・読了・プレイ状況を記録する（US-05）🔵

**信頼性**: 🔵 *PRD §5 US-05・§15.1「`update_consumption` の対象項目」より*

**私は** コレクション所有者 **として**
**「昨日見終わった」「読み始めた」「評価は8点」のような発話から、状態・日付・評価・お気に入りを更新したい**
**そうすることで** 体験直後に少ない手間で記録を残せる

**関連要件**: REQ-050, REQ-051, REQ-052, REQ-110, REQ-142, NFR-203, EDGE-106

**詳細シナリオ**:
1. AI が `search_library` で対象を解決する
2. 1件に確定できなければ候補を提示し、更新しない
3. AI が自然言語の日付を `YYYY-MM-DD` に変換する
4. AI が `update_consumption` を Item ID 指定で呼び出す
5. MCP が更新前後の値を返し、AI が利用者へ示す

**制約事項**:
- 対象は UUID でのみ指定できる（タイトル指定は受け付けない）
- 日付の自然言語解釈は MCP ではなく MCP クライアントの責務
- `status` は `not_started` / `in_progress` / `completed` の3値のみ

**優先度**: Must Have

### ストーリー 3.2: コレクションを整理する（US-06）🔵

**信頼性**: 🔵 *PRD §5 US-06・§15.1「タグ・カテゴリ・マイリストの自動作成」より*

**私は** コレクション所有者 **として**
**「積読タグを付けて」「夏休みに見るリストへ追加して」のように名前で整理したい**
**そうすることで** タグ・カテゴリ・マイリストのIDを意識せず管理できる

**関連要件**: REQ-060, REQ-061, REQ-111, REQ-113, NFR-004, EDGE-003

**詳細シナリオ**:
1. AI が `organize_item` を Item ID とタグ名・カテゴリ名・マイリスト名で呼び出す
2. MCP が `GET /tags` 等で名前から ID を解決する
3. 一致するものがなく `create_if_missing` が指定されていなければ「候補なし」として返す
4. `create_if_missing` が指定されていれば作成してから付与する
5. 結果で新規作成分と既存分、既に付与済みだったものを区別して返す

**制約事項**:
- 既定では新規作成しない
- 同じ付与を繰り返しても重複を作らない

**優先度**: Must Have

---

### ストーリー 3.3: 作品同士の関係を記録する（US-07）🔵

**信頼性**: 🔵 *PRD §5 US-07・§15.1「関係種別」・ヒアリング2026-08-07より*

**私は** コレクション所有者 **として**
**原作と映像化作品、続編、DLC、引用元などを関連付けたい**
**そうすることで** メディアをまたいで作品を辿れる

**関連要件**: REQ-070, REQ-071, REQ-072, REQ-113, EDGE-005

**詳細シナリオ**:
1. AI が `search_library` で関係元と関係先の両方を解決する
2. AI が `relate_items` を2つの Item ID と関係種別で呼び出す
3. MCP が関係を登録し、向きと種別を明示して返す
4. 同一の関係が既にあれば重複を作らない

**前提条件**:
- MediaVault-api の `relation_type` ENUM が6種別に拡張済み（[prep.md](prep.md) PREP-01）

**制約事項**:
- 関係種別は固定一覧のみ。利用者定義の種別は扱わない

**優先度**: Must Have

---

### ストーリー 3.4: 視聴先・参照先を記録する（US-08）🔵

**信頼性**: 🔵 *PRD §5 US-08・ヒアリング2026-08-07より*

**私は** コレクション所有者 **として**
**配信サービス、公式サイト、Jellyfin、Calibre-Web、トレーラーなどのURLを作品へ追加したい**
**そうすることで** 次に利用するときの入口を MediaVault へ集約できる

**関連要件**: REQ-080, REQ-081, REQ-116

**詳細シナリオ**:
1. AI が `add_access_link` を Item ID・URL・用途で呼び出す
2. 用途が配信リンクかつプラットフォームが対応一覧にあれば `streaming-links` へ登録する
3. 対応一覧にない場合は通常リンク（`item-links`）へフォールバックし、そのことを結果に含める
4. トレーラー用途なら `trailers` へ登録する

**制約事項**:
- 不正なURLは登録しない
- 対応プラットフォームは `netflix` / `amazon_prime` / `disney_plus` / `dmm_tv` / `apple_tv` の5種

**優先度**: Must Have

## エピック4: 運用と安全性

### ストーリー 4.1: 認証された経路からのみ操作させる 🔵

**信頼性**: 🔵 *PRD §10・§15.1「外部・内部経路の認証」・ヒアリング2026-08-07より*

**私は** コレクション所有者（システム管理者として） **として**
**MCP エンドポイントを認証必須にしたい**
**そうすることで** MediaVault-api が無認証であっても、AIエージェント経路からの不正操作を防げる

**関連要件**: REQ-115, REQ-122, NFR-101, NFR-102, NFR-103, NFR-104, REQ-145

**詳細シナリオ**:
1. MCP プロセスが起動時に `MCP_AUTH_TOKEN` を検証し、未設定なら起動を失敗させる
2. `/mcp` への全リクエストで Bearer トークンを定数時間比較する
3. 不一致・欠落は 401 を返し、ツールを実行しない
4. `/healthz` のみ認証対象外とする

**優先度**: Must Have

---

### ストーリー 4.2: 接続状態を確認する 🔵

**信頼性**: 🔵 *PRD §7.1・ヒアリング2026-08-07より*

**私は** コレクション所有者 **として**
**MCP から MediaVault-api へ到達できているかを確認したい**
**そうすることで** ツールが失敗したときに原因を切り分けられる

**関連要件**: REQ-100, REQ-120, EDGE-001

**詳細シナリオ**:
1. AI が `health` を呼び出す
2. MCP が `GET /api/v1/health` を叩き、到達可否と応答時間を返す
3. あわせて mediavault-mcp のバージョンを返す

**優先度**: Must Have

### ストーリー 5.2: 長時間処理を依頼・監視する（US-11）🔵

**信頼性**: 🔵 *PRD §5 US-11・§7.2より*

**私は** KnowledgeHub または自動化エージェント **として**
**全文抽出、索引更新、リンク解決などを非同期で依頼し、完了まで監視したい**
