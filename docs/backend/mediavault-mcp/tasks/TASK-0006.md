## タスク概要

環境変数から設定を読み込む `Config` を実装し、起動時の必須項目検証を行う。

秘密情報（`MCP_AUTH_TOKEN` / `INTERNAL_API_KEY`）は `Debug` 出力でマスクされる `SecretString` に包み、ログや panic メッセージへの漏洩を型レベルで防ぐ。

## 実装詳細

### 1. Config 構造体 🔵

**信頼性**: 🔵 *[interfaces.rs](../design/interfaces.rs) の `Config` 定義より*

**実装ファイル**: `backend/mediavault-mcp/src/config.rs`

| 環境変数 | 必須 | 既定値 | 用途 |
|---|---|---|---|
| `MCP_AUTH_TOKEN` | ✔ | — | Bearer 認証トークン（REQ-122）🔵 |
| `MEDIAVAULT_API_BASE_URL` | ✔ | — | api のベースURL 🔵 |
| `INTERNAL_API_KEY` | — | 空 | 内部API用（NFR-103）🟡 |
| `MCP_BIND_ADDR` | — | `0.0.0.0:8081` | 待受アドレス 🟡 |
| `MCP_CONNECT_TIMEOUT_SECS` | — | `3` | 接続タイムアウト（NFR-006）🟡 |
| `MCP_REQUEST_TIMEOUT_SECS` | — | `15` | 全体タイムアウト（NFR-006）🟡 |
| `MCP_EXTERNAL_TIMEOUT_SECS` | — | `30` | 外部カタログ検索用（NFR-006）🟡 |

`INTERNAL_API_KEY` を必須にしない理由 🟡: MVP のツールは公開API（`/api/v1/*`、認証不要）のみを使う。内部APIを使う機能が追加された時点で必須化を検討する。

### 2. SecretString 🟡

**信頼性**: 🟡 *[interfaces.rs](../design/interfaces.rs) の設計上の追加型。REQ-145 / NFR-103 を型で担保するための手段*

**実装ファイル**: `backend/mediavault-mcp/src/config.rs`

```rust
pub struct SecretString(String);

impl SecretString {
    pub fn expose(&self) -> &str { &self.0 }
}

impl std::fmt::Debug for SecretString {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        f.write_str("SecretString(***)")
    }
}
```

- `Display` は実装しない（誤って `{}` で出力されることを防ぐ）🟡
- `Clone` は実装するが `Serialize` は実装しない 🟡
- 値の取り出しは `expose()` のみ。名前で意図を明示する 🟡

### 3. 起動時検証 🔵

**信頼性**: 🔵 *REQ-122「未設定または空文字の場合、起動に失敗しなければならない」より*

```rust
pub fn from_env() -> Result<Config, ConfigError>
```

検証内容:

| 項目 | 検証 | 理由 |
|---|---|---|
| `MCP_AUTH_TOKEN` | 未設定・空文字・トリム後空を拒否 | REQ-122 🔵 |
| `MEDIAVAULT_API_BASE_URL` | 未設定を拒否、`url::Url` でパース可能か検証 | 起動後に全ツールが失敗するのを防ぐ 🟡 |
| `MCP_BIND_ADDR` | `SocketAddr` としてパース可能か | 同上 🟡 |
| タイムアウト値 | 正の整数としてパース可能か、0でないか | 同上 🟡 |

**既存 api との差異** 🔵

**信頼性**: 🔵 *[design-interview.md](../design/design-interview.md) 事前調査より*

既存の `mediavault-api/src/middleware/api_key_auth.rs` は `std::env::var(...).unwrap_or_default()` で読み、空文字なら常に401を返す。この方式は設定漏れが「認証が通らない」という形でしか現れず気付きにくい。MCP では**起動時に失敗させる**ことで設定漏れを即座に検知する。

### 4. トークン長の下限チェック 🟡

**信頼性**: 🟡 *NFR-101 を実効的にするための実装上の判断。要件に明記はない*

極端に短いトークン（`"a"` など）は総当たりに耐えられない。32文字未満の場合に警告ログを出す（起動は失敗させない）。

### 5. .env.example の作成 🔵

**信頼性**: 🔵 *[prep.md](../spec/prep.md) PREP-05 より*

**実装ファイル**: `backend/mediavault-mcp/.env.example`

実値を含めず、生成方法（`openssl rand -base64 48`）をコメントで示す。

## 注意事項

- **環境変数のテストは並列実行で干渉する**。Rust のテストは既定でスレッド並列であり、`std::env::set_var` はプロセス全体に作用する。`Config` を「環境変数を読む関数」と「値から構築する関数」に分離し、後者を単体テストの主対象にすることで干渉を避ける 🟡
- edition 2024 では `std::env::set_var` が `unsafe` になっている（既存 `api_key_auth.rs` のテストでも `unsafe` ブロックが使われている）🔵
- `SecretString` は自前実装とする。`secrecy` クレートの導入は依存を増やすだけの価値があるか実装時に判断してよい 🟡
