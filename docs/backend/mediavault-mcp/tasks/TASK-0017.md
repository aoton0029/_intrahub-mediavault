## タスク概要

`search_external_catalog` で選ばれた候補を MediaVault へ登録する。**最初の書き込み系ツール**であり、ここで確立する書き込みツールのパターン（annotation、冪等性、結果の構造）を以降の5ツールが踏襲する。

要点は**409 の冪等化**（REQ-112）。既にインポート済みの作品を重複登録せず、既存 Item を返す。

## 実装詳細

### 1. ツール定義 🔵

**信頼性**: 🔵 *[mcp-tools.md](../design/mcp-tools.md) 4. のパラメータ表より*

**実装ファイル**: `backend/mediavault-mcp/src/tools/import_external_item.rs`

- 引数: `media_type`（必須）、`external_id`（必須）、`provider`（任意）🔵 *`POST /items/import` の `ImportByIdRequest` より*
- annotation: `readOnlyHint: false`、`destructiveHint: false` 🔵 REQ-004
- 説明文（AI向け）:
  > `search_external_catalog` で見つけた候補を MediaVault へ登録する。**利用者が候補を1つ選んでから**呼ぶこと。

### 2. api 呼び出し 🔵

**信頼性**: 🔵 *[items.md](../../mediavault-api/items.md) `POST /items/import` より*

```
POST /api/v1/items/import
{ "media_type": "...", "external_id": "...", "provider": "..." }
```

api 側が対応プロバイダから詳細を再取得し、`CreateItemRequest` を構築して登録する。MCP は詳細情報を組み立てない 🔵

### 3. 409 の冪等化 🔵

**信頼性**: 🔵 *REQ-112・[dataflow.md](../design/dataflow.md) 機能3・「冪等化する409の一覧」より*

409 `ITEM_ALREADY_IMPORTED` を受けたら、既存 Item を特定して `outcome: success` + `already_existed: true` で返す。

**既存 Item の特定方法** 🟡

**信頼性**: 🟡 *[design-interview.md](../design/design-interview.md) 残課題「暫定」より*

api は 409 のレスポンスに既存 Item の ID を含まない（[items.md](../../mediavault-api/items.md) のエラー仕様より）。そのため MCP 側で探す必要がある。

| 案 | 内容 | 課題 |
|---|---|---|
| A. `GET /items?media_type=X` を走査 | 全ページを辿って `external_id` 一致を探す | 件数が多いと重い |
| B. 特定を諦める | `already_existed: true` のみ返し `item` は null | AI が後続操作の `item_id` を得られない |

**推奨**: A を採用しつつ、走査するページ数に上限（例: 5ページ=100件）を設ける。見つからなければ `item: null` + `already_existed: true` で返し、AI に `search_library` での検索を促す 🟡

**将来**: PRD §8 の「重複候補検索API」が実装されればそちらへ切り替える。

**409 の特定処理が失敗した場合** 🟡: 「登録は行われなかったが既存 Item は特定できなかった」ことが分かる形で返す。エラーにはしない（重複がないこと自体は成功）。

### 4. 結果の構造 🔵

**信頼性**: 🔵 *[interfaces.rs](../design/interfaces.rs) `ImportExternalItemResult`・REQ-051（書き込み結果の検証可能性）より*

```json
{
  "outcome": "success",
  "item": { /* ItemSummary */ },
  "already_existed": false,
  "error": null
}
```

`item.item_id` により、AI が続けて `organize_item` を呼べる（US-03 の「必要に応じてタグやマイリストを付与」）🔵

### 5. その他のエラー 🔵

**信頼性**: 🔵 *[items.md](../../mediavault-api/items.md) `POST /items/import` のエラー一覧より*

| api の応答 | `outcome` | `retriable` |
|---|---|---|
| 400 `VALIDATION_ERROR`（`external_id` 空）| `error` | false 🔵 |
| 404（プロバイダ側で対象が見つからない）| `not_found` | false 🔵 |
| 422 `API_KEY_NOT_CONFIGURED` | `error` | false 🔵 |
| 502 `EXTERNAL_API_TIMEOUT` / `EXTERNAL_API_ERROR` | `error` | true 🔵 |

**リトライしない** 🔵 *[architecture.md](../design/architecture.md) 可用性「書き込みは自動リトライしない」より*

`retriable: true` は AI への情報提供であり、MCP 自身は POST を再送しない。

## AIエージェント向け要件

### 検索結果をそのまま渡せる 🔵

**信頼性**: 🔵 *NFR-003・REQ-031 より*

`search_external_catalog` の候補の `external_id` / `provider` / `media_type` を、変換せずそのまま引数にできること。AI が値を組み替える必要があると誤りが混入する。

### 重複が事故に見えない 🔵

**信頼性**: 🔵 *REQ-112・PRD §6 原則6 より*

既にインポート済みの場合、AI が「エラーが起きました」ではなく「その作品は既に登録済みです」と伝えられること。`already_existed` フラグと `outcome: success` の組み合わせでこれを実現する。

### 登録前の確認は行わない 🔵

**信頼性**: 🔵 *PRD §15.1「書き込み前の利用者確認」・§10 より*

このツールは呼ばれたら登録する。確認フローは MCP クライアントの責務であり、MCP 側で「本当によいですか」を返さない。説明文で「利用者が候補を選んでから呼ぶ」と促すに留める。

## 注意事項

- **最初の書き込み系ツール**。annotation の付け方、`retriable` の判断、リトライしない方針を、以降の5ツールが参照するパターンとして丁寧に作る
- 409 の既存 Item 特定は暫定実装。走査が重くなる場合は `item: null` を返す判断に倒し、AI に `search_library` を促すほうが健全 🟡
- **書き込み系はリトライしないこと**。接続エラーでも POST を再送しない。二重登録は取り消せない（削除系ツールがない）
- api 側の重複判定は (media_type, external_id) の組み合わせ 🔵 *[items.md](../../mediavault-api/items.md) より*。`provider` は判定に含まれない点に注意
