## タスク概要

`GET /api/v1/items` に、検索条件に該当する総件数を返す手段を追加する。

現行は keyset ページネーションを採用しており、`COUNT(*)` を意図的に避けて `total` を返していない。この設計意図を壊さないよう、**オプトイン方式**で件数取得を追加する。

MCP の `search_library`（TASK-0013）が US-09「選定条件と該当件数が分かる」を満たすための前提。

- **後続タスク**: [TASK-0013: search_library ツール実装](TASK-0013.md)

## 完了条件

## 実装詳細

### 1. `include_total` クエリパラメータの追加 🔵

**信頼性**: 🔵 *[prep.md](../spec/prep.md) PREP-03「既定では COUNT を実行しない設計にする」より*

**実装ファイル**: `backend/mediavault-api/src/models/item.rs`（`ListItemsQuery`）

```rust
pub struct ListItemsQuery {
    // ... 既存フィールド ...
    /// true のときのみ COUNT(*) を実行し pagination.total を返す
    pub include_total: Option<bool>,
}
```

**オプトインにする理由** 🔵

**信頼性**: 🔵 *[items.md](../../mediavault-api/items.md)「件数の総数（total）は返さない（COUNT(*)クエリを避けるため）」より*

現行の設計は COUNT 回避が明示的な意図である。既定で COUNT を実行すると、既存フロントエンドの一覧表示すべてに性能影響が及ぶ。

### 2. COUNT クエリの構築 🟡

**信頼性**: 🟡 *実装上必要となる処理。具体的な構築方法は既存のクエリビルダ実装に依存する*

フィルタ条件（`media_type` / `tag_id` / `category_id` / `is_favorite` / `status` / `title` / `year`）は本体クエリと**完全に同一**にし、keyset カーソル（`after_created_at` / `after_id`）と `limit` だけを除外する。

条件の二重管理を避けるため、WHERE 句の構築を共通関数へ切り出す。

**実装ファイル**: `backend/mediavault-api/src/repositories/`（items リポジトリ）

### 3. レスポンス型の拡張 🔵

**信頼性**: 🔵 *[items.md](../../mediavault-api/items.md) の pagination 仕様より*

```json
{
  "pagination": {
    "limit": 20,
    "has_more": true,
    "next_after_created_at": "...",
    "next_after_id": "...",
    "total": 42
  }
}
```

`total` は `Option<i64>` とし、`#[serde(skip_serializing_if = "Option::is_none")]` を付けて未指定時はフィールドごと省略する。既存レスポンスの形を変えないため 🟡

### 4. API仕様書の更新 🔵

**信頼性**: 🔵 *完了条件より*

**実装ファイル**: `docs/backend/mediavault-api/items.md`

`include_total` の説明と、既定で COUNT を実行しない理由を記載する。

## 単体テスト要件

### テストケース1: include_total 指定時に total が返る 🔵

**信頼性**: 🔵 *完了条件より*

**Given**: 条件に該当する Item が42件、`limit=20`
**When**: `GET /items?media_type=anime&include_total=true`
**Then**: `data` は20件、`pagination.total` は42

### テストケース2: 未指定時は total が返らない 🔵

**信頼性**: 🔵 *完了条件「既定では COUNT を実行しない」より*

**Given**: 同上
**When**: `GET /items?media_type=anime`
**Then**: `pagination` に `total` フィールドが存在しない

### テストケース3: フィルタが COUNT に反映される 🔵

**信頼性**: 🔵 *完了条件「条件に該当する全件数」より*

**Given**: 全100件、うち `is_favorite=true` が12件
**When**: `GET /items?is_favorite=true&include_total=true`
**Then**: `total` は12（100ではない）

### テストケース4: カーソル指定時も total が変わらない 🔵

**信頼性**: 🔵 *完了条件「ページネーションの影響を受けず」より*

**Given**: 該当42件
**When**: 2ページ目を `after_created_at` / `after_id` 付きで取得する
**Then**: `total` は42のまま

### テストケース5: 0件時 🔵

**信頼性**: 🔵 *受け入れ基準 TC-014-01（0件時の扱い）より*

**Given**: 該当なし
**When**: `include_total=true`
**Then**: `data` は空配列、`total` は0（エラーにしない）

### テストケース6: include_total=false 🟡

**信頼性**: 🟡 *境界ケースとして妥当な推測*

**When**: `include_total=false` を明示指定
**Then**: 未指定時と同じ挙動（`total` なし）

## 注意事項

- **TASK-0002 と同一のクエリ構築箇所を触る**。TASK-0002 を先に完了させ、WHERE 句共通化のリファクタリングを一度で済ませる

- 代替案として TASK-0004 の `GET /collection/overview` に条件付き件数を持たせる方法もあったが、任意のフィルタ組み合わせに対応する必要があるため `GET /items` への追加を採用した
