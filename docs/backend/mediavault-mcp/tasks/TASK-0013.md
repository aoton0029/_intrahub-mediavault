## タスク概要

MediaVault 内の所蔵確認を行う中核ツールを実装する。US-01（所蔵確認）と US-09（候補相談）の入口であり、書き込み系ツールが対象 `item_id` を得るための前段でもある。

**MVP で最も使用頻度が高いツール**。ローカル検索と外部検索の区別（REQ-032）を利用者・AI の両方に伝える役割も担う。

- **後続タスク**: [TASK-0014](TASK-0014.md), Phase 3 の全書き込みツール（実運用上の前段として）

## 実装詳細

### 1. ツール定義 🔵

**信頼性**: 🔵 *[mcp-tools.md](../design/mcp-tools.md) 1. search_library のパラメータ表より*

**実装ファイル**: `backend/mediavault-mcp/src/tools/search_library.rs`

- annotation: `readOnlyHint: true` 🔵
- 説明文（AI向け）:
  > MediaVault に**既に登録済み**の作品を検索する。所蔵確認に使う。未登録の作品を外部から探す場合は `search_external_catalog` を使うこと。

パラメータは `SearchLibraryParams`（[interfaces.rs](../design/interfaces.rs)）。`year` と `sort` を含む（設計決定 D-06）🔵

### 2. 引数バリデーション 🔵

**信頼性**: 🔵 *REQ-143・EDGE-101 / EDGE-102・[design-interview.md](../design/design-interview.md) の決定より*

| 検証 | 不正時 |
|---|---|
| `limit` が 1..=50 | `MCP_INVALID_ARGUMENT`。**丸めない** 🔵 |
| `title` が空白のみでない | `MCP_INVALID_ARGUMENT`（EDGE-102）🟡 |
| 全条件が未指定 | 許可する（全件の先頭20件を返す）🟡 |

`limit` を丸めない理由 🔵: [design-interview.md](../design/design-interview.md) の決定。丸めると AI に上限が伝わらず同じ誤りを繰り返す。エラーメッセージに上限値を含めること。

### 3. 名前解決 🔵

**信頼性**: 🔵 *REQ-010・[dataflow.md](../design/dataflow.md) 機能1 ステップ2-3 より*

`tag` / `category` が指定された場合、`MasterResolver`（TASK-0012）で ID へ解決してから検索する。

**解決できない場合は検索を実行しない** 🟡

**信頼性**: 🟡 *[dataflow.md](../design/dataflow.md) 機能1「空振り検索よりAIが次の手を打ちやすい」より*

`outcome: not_found`、`code: MCP_NAME_NOT_RESOLVED`、`available_names` 付きで返す。存在しないタグIDで検索して0件を返すより、原因が明確になる。

### 4. api 呼び出し 🔵

**信頼性**: 🔵 *[items.md](../../mediavault-api/items.md) の `ListItemsQuery`・TASK-0002 / TASK-0003 の成果より*

```
GET /api/v1/items
  ?title=&media_type=&status=&tag_id=&category_id=&is_favorite=&year=&sort=
  &limit=&after_created_at=&after_id=
  &include_total=true
```

`include_total=true` を常に付ける（REQ-013 で件数が必須のため）🟡

### 5. カーソルの不透明化 🟡

**信頼性**: 🟡 *[dataflow.md](../design/dataflow.md) 機能1 ステップ6「keyset の内部構造を隠蔽する」より*

api の `next_after_created_at` / `next_after_id` を1つの文字列へエンコードして `next_cursor` として返す。受け取ったカーソルはデコードして api のクエリへ戻す。

- エンコード方式: JSON → Base64 など。AI が中身を解釈して改変しないよう不透明にする
- 不正なカーソルは `MCP_INVALID_ARGUMENT` にする 🟡（api 側は不正カーソルを無視して先頭ページを返す仕様だが、MCP では明示的にエラーにするほうが AI の混乱が少ない）

### 6. source フィールド 🔵

**信頼性**: 🔵 *REQ-014 / REQ-032 / NFR-202・[mcp-tools.md](../design/mcp-tools.md) より*

固定値 `"mediavault_library"` を必ず含める。`search_external_catalog` の `"external_catalog"` と対になり、0件時でも取り違えを防ぐ。

### 7. applied_filters 🔵

**信頼性**: 🔵 *REQ-013（US-09「選定条件と該当件数が分かる」）より*

実際に適用された条件を返す。名前で指定されたタグがどの ID に解決されたかも含める 🟡。AI が「何で絞ったか」を利用者へ説明できるようにする。

## 注意事項

- **TASK-0002 / TASK-0003 が未完了だと要件を満たせない**。別名検索と `total_count` は api 側の対応が前提。api が未対応の状態で実装する場合、該当テストは ignore にせず「api 側の対応待ち」として明示的に失敗させ、取りこぼしを防ぐ 🟡
- `limit` を丸めない決定は [prep.md](../spec/prep.md) PREP-09 で「要ユーザー確認」としている。実装前に確認が取れていれば従い、変更があれば本タスクと EDGE-101 を更新する
- このツールは書き込み系の前段として使われる（REQ-142 により、書き込みは UUID のみ受け付ける）。候補が複数返ったとき AI が「どれですか」と聞けるだけの情報が揃っていることが、NFR-301（誤書き込み0件）の実効性を支える 🔵
