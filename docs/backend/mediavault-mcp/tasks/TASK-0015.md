## タスク概要

外部の作品データベース（Annict / TMDb / 楽天ブックス / Steam / NDL）を検索するツールを実装する。

**設計上の中核は「所蔵確認との明確な分離」**（REQ-032 / PRD §6 原則2）。未登録作品を所蔵品と誤認させないため、ツール名・説明・レスポンス型のすべてで区別する。

## 実装詳細

### 1. ツール定義 🔵

**信頼性**: 🔵 *[mcp-tools.md](../design/mcp-tools.md) 3. のパラメータ表より*

**実装ファイル**: `backend/mediavault-mcp/src/tools/search_external_catalog.rs`

- 引数: `media_type`（必須）、`q`（必須）🔵 *`GET /items/search` の `ItemSearchQuery` より*
- annotation: `readOnlyHint: true` 🔵
- 説明文（AI向け）:
  > **外部の作品データベース**（Annict / TMDb / 楽天ブックス / Steam / NDL）を検索する。所蔵確認ではない。ここで見つかった作品は MediaVault に**まだ登録されていない**。登録するには `import_external_item` を呼ぶこと。

### 2. api 呼び出し 🔵

**信頼性**: 🔵 *[items.md](../../mediavault-api/items.md) `GET /items/search` より*

```
GET /api/v1/items/search?media_type={}&q={}
```

プロバイダは api 側が `media_type` に応じて自動選択する。MCP はプロバイダを指定しない 🔵

**タイムアウト** 🟡

**信頼性**: 🟡 *[architecture.md](../design/architecture.md)「外部カタログ検索のみ 30秒」より*

外部プロバイダを経由するため、通常の15秒ではなく30秒のタイムアウトを使う（TASK-0008 で用意した専用メソッド）。

### 3. ExternalCandidate への変換 🔵

**信頼性**: 🔵 *REQ-031・[interfaces.rs](../design/interfaces.rs) `ExternalCandidate`・[items.md](../../mediavault-api/items.md) の `SearchResultItem` より*

| フィールド | 由来 | 用途 |
|---|---|---|
| `external_id` | `SearchResultItem.id` | `import_external_item` へ渡す 🔵 |
| `provider` | `SearchResultItem.provider` | 同上 🔵 |
| `title` | `SearchResultItem.title` | 🔵 |
| `release_year` | 公開日から年を抽出 | 候補の区別 🔵 REQ-031 |
| `media_type` | リクエストの値 | 🔵 |
| `cover_image_url` | — | 🟡 |
| `summary` | あらすじ冒頭 | 候補の区別 🟡 |

**`item_id` を持たない** 🔵

**信頼性**: 🔵 *REQ-032・[dataflow.md](../design/dataflow.md) 機能3「所蔵品との取り違えを型レベルで防ぐ」より*

`ExternalCandidate` に MediaVault の UUID フィールドを**定義しない**。型レベルで所蔵品と混同できないようにする。

**`summary` の長さ制限** 🟡

**信頼性**: 🟡 *PRD §11 のレスポンスサイズ方針から導かれる判断*

あらすじ全文を返すと候補20件でトークンを大量消費する。冒頭100〜200文字程度に切り詰める。

### 4. エラーの扱い 🔵

**信頼性**: 🔵 *REQ-117・EDGE-006・[items.md](../../mediavault-api/items.md) のエラー一覧より*

| api の応答 | `outcome` | `code` | `retriable` |
|---|---|---|---|
| 422 `API_KEY_NOT_CONFIGURED` | `error` | 透過 | false 🔵 |
| 502 `EXTERNAL_API_TIMEOUT` | `error` | 透過 | true 🔵 |
| 502 `EXTERNAL_API_ERROR` | `error` | 透過 | true 🔵 |
| 400 `VALIDATION_ERROR` | `error` | 透過 | false 🔵 |

APIキー未設定は「設定すれば直る」ため、AI が利用者へ設定を促せるようメッセージを保持する（REQ-146）。

### 5. 0件時の扱い 🟡

**信頼性**: 🟡 *REQ-014 の対称として妥当な推測。外部検索の0件は要件に明記がない*

`outcome: success`、`candidates: []`、`source: "external_catalog"`。エラーにしない。「外部にも見つからなかった」ことが AI に伝わればよい。

## AIエージェント向け要件

### 所蔵確認との使い分け 🔵

**信頼性**: 🔵 *REQ-032 / NFR-202・受け入れ基準 TC-NFR-202-01「説明文が互いを参照して区別を明示している」より*

- `search_library` の説明文が「外部を探すなら `search_external_catalog`」と案内すること
- `search_external_catalog` の説明文が「これは所蔵確認ではない」「まだ登録されていない」と明示すること
- レスポンスの `source` により、結果だけを見ても区別できること

**この3重の区別が PRD §6 原則2 の実装**。1つでも欠けると、AI が外部候補を「持っている作品」として利用者へ提示する事故が起きうる。

### 候補選択の材料 🔵

**信頼性**: 🔵 *REQ-031（US-03「公開年、種別、プロバイダーなどを提示して選択を求める」）より*

同名・同シリーズの候補が並んだとき、AI が利用者へ違いを説明できる情報（公開年、あらすじ冒頭、プロバイダ）が揃っていること。

### 登録前の確認 🔵

**信頼性**: 🔵 *PRD §6 原則3・§10 より*

このツールは**登録しない**。説明文で「登録するには `import_external_item` を呼ぶ」と明示し、AI が検索と登録を混同しないようにする。利用者への確認は MCP クライアントの責務（PRD §15.1）。

## 注意事項

- **`ExternalCandidate` に `item_id` を追加しないこと**。「登録済みかどうかを一緒に返すと便利」という発想は REQ-032 に反する。所蔵確認は `search_library` の責務
- 実運用では api 側にプロバイダAPIキーの設定が必要（[prep.md](../spec/prep.md) PREP-06）。wiremock テストでは不要だが、手動確認時に必要になる
- `SearchResultItem` の `id` は media_type により意味が異なる（`mal_id` / `annict work id` / `tmdb id` / `steam appid` / `isbn`）。MCP 側で解釈せず、そのまま `import_external_item` へ渡す 🔵 *[items.md](../../mediavault-api/items.md) より*
- api が `provider` を `null` で返す場合がある。`import_external_item` の `provider` は optional のため問題ないが、AI への提示時に「不明」となる 🟡
