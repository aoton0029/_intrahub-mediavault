## 実装詳細

### 1. エンドポイントとルーティング 🔵

**信頼性**: 🔵 *[prep.md](../spec/prep.md) PREP-04・[mcp-tools.md](../design/mcp-tools.md) の `collection_overview` レスポンス例より*

**実装ファイル**: `backend/mediavault-api/src/handlers/collection.rs`（新規）、`src/routes/mod.rs`

```
GET /api/v1/collection/overview?recent_limit=10
```

- 認証: 不要（既存の公開API と同じ扱い）🔵 *[items.md](../../mediavault-api/items.md) の「認証: 不要」パターンより*

### 2. 集計クエリ 🟡

**信頼性**: 🟡 *返す内容は REQ-090 で確定しているが、クエリの分割方針は実装上の判断*

件数系は1本の集計クエリにまとめる。

```sql
SELECT
    COUNT(*)                                             AS total_items,
    COUNT(*) FILTER (WHERE is_favorite)                  AS favorite_count,
    COUNT(*) FILTER (WHERE status = 'not_started')       AS status_not_started,
    COUNT(*) FILTER (WHERE status = 'in_progress')       AS status_in_progress,
    COUNT(*) FILTER (WHERE status = 'completed')         AS status_completed
FROM items;
```

media_type 別は `GROUP BY media_type` の別クエリ、最近追加・更新は `ORDER BY created_at DESC` / `ORDER BY updated_at DESC` の別クエリとする。計4クエリ。

**既存 `counts-by-media-type` との関係** 🟡

**信頼性**: 🟡 *[prep.md](../spec/prep.md)「包含または併存させるか設計時に決める」より*

既存エンドポイントはフロントエンドのサイドバーが使用している。**併存させる**（削除・変更しない）。集計ロジックは共通のサービス関数へ切り出して重複を避ける。

### 3. レスポンス型 🔵

**信頼性**: 🔵 *[interfaces.rs](../design/interfaces.rs) の `CollectionOverviewResult` / `CountEntry` より*

```json
{
  "success": true,
  "data": {
    "total_items": 181,
    "favorite_count": 34,
    "by_media_type": [{ "key": "manga", "count": 87 }],
    "by_status": [{ "key": "not_started", "count": 90 }],
    "recently_added": [ /* ItemWithRefs[] */ ],
    "recently_updated": [ /* ItemWithRefs[] */ ]
  }
}
```

`recently_added` / `recently_updated` は既存の `ItemWithRefs`（Item + tags + categories）を流用する。MCP 側で `ItemSummary` へ縮約する（TASK-0012）ため、api 側で専用型を作らない 🟡

### 4. `recent_limit` のバリデーション 🔵

**信頼性**: 🔵 *完了条件・[mcp-tools.md](../design/mcp-tools.md)「1..=50、既定 10」より*

範囲外は 400 `VALIDATION_ERROR`。既存の `limit` バリデーション（`GET /items` の max 100）と同じパターンに揃える。

**信頼性**: 🔵 *完了条件より*

**実装ファイル**: `docs/backend/mediavault-api/collection.md`（新規）、`docs/backend/mediavault-api/index.md`（リンク追加）

## 単体テスト要件

### テストケース1: 全項目が返る 🔵

**信頼性**: 🔵 *完了条件より*

**Given**: media_type が3種、status が3種にまたがる Item 群
**When**: `GET /api/v1/collection/overview`
**Then**: `total_items` / `favorite_count` / `by_media_type` / `by_status` / `recently_added` / `recently_updated` がすべて返る

### テストケース2: 件数の正確性 🔵

**信頼性**: 🔵 *完了条件より*

**Given**: anime 5件（うち favorite 2件、completed 3件）、manga 3件
**When**: 同上
**Then**: `total_items=8`、`by_media_type` に anime=5 / manga=3、`favorite_count=2`、`by_status` の completed=3

### テストケース3: recently_added の順序 🔵

**信頼性**: 🔵 *完了条件「最近追加された Item」より*

**Given**: created_at が異なる Item 15件
**When**: `recent_limit=5`
**Then**: created_at 降順の上位5件が返る

### テストケース4: recently_updated の順序 🔵

**信頼性**: 🔵 *完了条件より*

**When**: 同上
**Then**: updated_at 降順の上位5件が返る（recently_added とは異なる並びになりうる）

### テストケース5: 既定値 🔵

**信頼性**: 🔵 *完了条件「既定10」より*

**Given**: Item 20件
**When**: `recent_limit` 未指定
**Then**: `recently_added` が10件

### テストケース6: 範囲外の recent_limit 🔵

**信頼性**: 🔵 *完了条件「最大50」より*

**When**: `recent_limit=51` / `recent_limit=0`
**Then**: 400 `VALIDATION_ERROR`

### テストケース7: 空コレクション 🟡

**信頼性**: 🟡 *境界ケースとして妥当な推測*

**Given**: Item が0件
**When**: 同上
**Then**: すべて0・空配列で 200（エラーにしない）
