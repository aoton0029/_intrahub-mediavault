## タスク概要

作品に URL を追加する。用途（通常リンク / 配信リンク / トレーラー）に応じて3つの api を振り分ける。

**要点はフォールバック**（REQ-081）。api の配信プラットフォームは5種固定であり、Jellyfin・Calibre-Web・U-NEXT などは表現できない。非対応の場合は通常リンクへ登録し、そのことを結果で通知する。

## 実装詳細

### 1. ツール定義 🔵

**信頼性**: 🔵 *[mcp-tools.md](../design/mcp-tools.md) 9.・[interfaces.rs](../design/interfaces.rs) `AddAccessLinkParams` より*

**実装ファイル**: `backend/mediavault-mcp/src/tools/add_access_link.rs`

| 引数 | 型 | 説明 |
|---|---|---|
| `item_id` | `Uuid`（必須）| 🔵 REQ-142 |
| `url` | `String`（必須）| http / https のみ 🔵 REQ-116 |
| `kind` | `LinkKind`（必須）| `link` / `streaming` / `trailer` 🔵 |
| `platform` | `Option<String>` | `kind=streaming` 時 🔵 |
| `label` | `Option<String>` | 通常リンクのラベル 🔵 |

- annotation: `readOnlyHint: false`、`destructiveHint: false` 🔵
- 説明文（AI向け）:
  > 作品に URL を追加する。配信サービスは `kind: "streaming"`、予告編は `kind: "trailer"`、公式サイト・Jellyfin・Calibre-Web などは `kind: "link"` を使う。

### 2. URL のバリデーション 🔵

**信頼性**: 🔵 *REQ-116・[dataflow.md](../design/dataflow.md) 機能6 ステップ1 より*

`url` クレートでパースし、スキームが `http` / `https` であることを確認する。

不正な場合は api を呼ばず `MCP_INVALID_ARGUMENT` を返す 🟡。`ftp://` や `javascript:` を通さない。

### 3. 振り分けロジック 🔵

**信頼性**: 🔵 *REQ-080 / REQ-081・[dataflow.md](../design/dataflow.md) 機能6 のフローチャートより*

| `kind` | `platform` | 登録先 | `registered_as` |
|---|---|---|---|
| `trailer` | — | `POST /items/{id}/trailers` | `trailer` 🔵 |
| `link` | — | `POST /items/{id}/links` | `link` 🔵 |
| `streaming` | 対応5種 | `POST /items/{id}/streaming-links` | `streaming_link` 🔵 |
| `streaming` | それ以外・未指定 | `POST /items/{id}/links` | `link` + `fallback_from: "streaming"` 🔵 REQ-081 |

**対応プラットフォーム** 🔵 *[item-streaming-links.md](../../mediavault-api/item-streaming-links.md) より*: `netflix` / `amazon_prime` / `disney_plus` / `dmm_tv` / `apple_tv`

### 4. フォールバック時のラベル 🟡

**信頼性**: 🟡 *[dataflow.md](../design/dataflow.md) 機能6 ステップ2「label = platform名」より*

`POST /items/{id}/links` は `label` が**必須**（[item-links.md](../../mediavault-api/item-links.md)）。フォールバック時は以下の優先順でラベルを決める。

1. 明示された `label`
2. `platform` 名（例: `"u-next"`）
3. URL のホスト名（例: `"jellyfin.local"`）🟡

ラベルが決められない場合はバリデーションエラーとする 🟡。api の必須項目を空文字で埋めない。

### 5. プラットフォーム名の正規化 🟡

**信頼性**: 🟡 *AI が渡す値の揺れを吸収するための実装上の判断。要件に明記なし*

`"Netflix"` / `"netflix"` / `"NETFLIX"` を同一とみなす。小文字化 + 空白をアンダースコアへ変換してから対応表と照合する。

過度な正規化（`"アマゾンプライム"` → `amazon_prime` など）は行わない。対応表にない値はフォールバックすればよく、誤変換のリスクを冒す必要がない。

### 6. 409 の冪等化 🟡

**信頼性**: 🟡 *[dataflow.md](../design/dataflow.md)「冪等化する409の一覧」より*

配信リンクは `(item_id, platform)` の一意制約があり、重複時 409 `DUPLICATE_STREAMING_LINK` が返る（[item-streaming-links.md](../../mediavault-api/item-streaming-links.md)）。

`outcome: success` + `already_registered: true` として扱う。

**通常リンク・トレーラーには一意制約がない可能性がある** 🟡: 同じURLを2回登録すると2件できるかもしれない。api 仕様を確認し、冪等化できない場合はその旨を注意事項に残す。

### 7. トレーラーの label 🔵

**信頼性**: 🔵 *[item-trailers.md](../../mediavault-api/item-trailers.md)「`label` (optional)」より*

トレーラーの `label` は任意。通常リンクと異なり必須ではない。

## AIエージェント向け要件

### フォールバックの通知 🔵

**信頼性**: 🔵 *REQ-081「フォールバックが起きたことを結果に含める」より*

AI が利用者へ以下のように伝えられること:

> 「U-NEXT は配信リンクとして登録できないため、通常リンクとして追加しました。」

黙ってフォールバックすると、利用者は配信リンクとして登録されたと誤解し、UI で見つからず混乱する。

### 用途の選び方 🔵

**信頼性**: 🔵 *[mcp-tools.md](../design/mcp-tools.md) のツール説明文より*

説明文で3つの `kind` の使い分けを具体例つきで示す。特に Jellyfin・Calibre-Web が `link` であることを明示する（「視聴できるサービス」なので `streaming` と誤解しやすい）🟡

### 対応プラットフォームの提示 🟡

**信頼性**: 🟡 *NFR-201 の趣旨をこのツールへ適用した推測*

フォールバックが起きたとき、対応している5種を結果に含めると AI が利用者へ説明しやすい。ただしレスポンスが冗長になるため、パラメータ説明に列挙するだけで足りるか実装時に判断する。

## 注意事項

- **フォールバックを黙って行わないこと**。`fallback_from` は REQ-081 の明示要件
- **api 側の `platform` ENUM を拡張しない**。ヒアリング（requirements Q4）でフォールバック方式が選ばれており、ENUM 拡張は不採用。「Jellyfin を追加すれば綺麗」と考えても、api のマイグレーションを増やさない判断
- 通常リンク・トレーラーの重複可否を api 仕様で確認する。冪等化できない場合、同じURLが複数登録されうる 🟡
- `POST /items/{id}/links` の `label` は必須。空文字で埋めないこと 🔵
- プラットフォーム名の正規化を過度に賢くしないこと。誤変換で意図しないプラットフォームへ登録されるほうが害が大きい 🟡
