## タスク概要

`GET /api/v1/items` の `title` クエリの検索対象を、現行の `items.title`（本題）のみから、`items.original_title`（原題）と `items.details->'alternative_titles'`（別名）へ拡張する。

MCP の `search_library`（TASK-0013）で「別名でも所蔵を確認できる」体験を実現するための前提。

## 実装詳細

### 1. 検索クエリの拡張 🔵

**信頼性**: 🔵 *[items.md](../../mediavault-api/items.md)「`title` (string, optional) — 部分一致検索」・REQ-011 より*

**実装ファイル**: `backend/mediavault-api/src/repositories/`（items のクエリ構築箇所）

3つの対象を OR で結合する。

```sql
WHERE (
    items.title ILIKE '%' || $1 || '%'
    OR items.original_title ILIKE '%' || $1 || '%'
    OR EXISTS (
        SELECT 1
        FROM jsonb_array_elements_text(
            COALESCE(items.details -> 'alternative_titles', '[]'::jsonb)
        ) AS alt(value)
        WHERE alt.value ILIKE '%' || $1 || '%'
    )
)
```

**`details` の形状に関する注意** 🟡

**信頼性**: 🟡 *[items.md](../../mediavault-api/items.md)「`details` はスキーマが強制されない自由形式の JSON」より*

`alternative_titles` は anime（Jikan/Annict 経由）で配列として入るが、他の media_type では存在しない、あるいは配列でない可能性がある。`jsonb_array_elements_text` は非配列に対してエラーになるため、`jsonb_typeof(...) = 'array'` のガードを入れる。

```sql
AND jsonb_typeof(items.details -> 'alternative_titles') = 'array'
```

### 2. インデックス方針の決定 🟡

**信頼性**: 🟡 *完了条件「検索性能が実用範囲に収まる」から導かれる実装上の判断*

`ILIKE '%...%'` は前方一致ではないため B-tree インデックスが効かない。以下から選択する。

| 案 | 内容 | 判断材料 |
|---|---|---|
| A. インデックスなし | 単一ユーザー・数百件規模なら全走査でも十分速い | 現在の総件数は181件（`counts-by-media-type` のサンプル値） |
| B. `pg_trgm` + GIN | `CREATE EXTENSION pg_trgm` の上で `gin (title gin_trgm_ops)` | 数千件を超える場合に有効 |

**推奨**: まず A で実装し、`EXPLAIN ANALYZE` で実測してから B を検討する。件数規模に対して過剰な最適化を避ける。

### 3. 重複排除 🔵

**信頼性**: 🔵 *完了条件「同一 Item が複数条件でヒットしても重複して返らない」より*

OR 条件は `EXISTS` サブクエリを使うため行の増殖は起きないが、既存のタグ・カテゴリ JOIN と組み合わせた場合に重複が出ないことをテストで確認する。

### 4. API仕様書の更新 🔵

**信頼性**: 🔵 *完了条件より*

**実装ファイル**: `docs/backend/mediavault-api/items.md`

`title` パラメータの説明を「本題・原題・別名を横断した部分一致検索」に更新する。

**あわせて既存の記載漏れも補う** 🟡

**信頼性**: 🟡 *[design-interview.md](../design/design-interview.md) 事前調査で判明した文書と実装の乖離より*
