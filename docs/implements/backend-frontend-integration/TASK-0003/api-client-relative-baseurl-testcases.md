# TASK-0003 テストケース: apiClient のデフォルトBASE_URL相対パス化

## 1. 正常系テストケース

- **テスト名**: デフォルトで相対パス `/api/v1` をベースにリクエストする
  - **何をテストするか**: `VITE_API_BASE_URL` 未設定時に `apiClient` が相対パスでfetchを呼び出すこと
  - **期待される動作**: `fetch` が `/api/v1/items` を引数に呼ばれる
- **入力値**: `apiClient('/items')`、環境変数未設定
  - **入力データの意味**: 最も一般的な呼び出しパターン
- **期待される結果**: `fetch` が `'/api/v1/items'` で呼び出される
  - **期待結果の理由**: REQ-009によりデフォルトBASE_URLは `/api/v1` である
- **テストの目的**: BASE_URLの相対パス化を確認
  - **確認ポイント**: 絶対URL（`http://localhost:8080/...`）でないこと
- 🔵 信頼性レベル: タスク定義のテストケース1をそのまま採用

## 2. 正常系テストケース（環境変数優先）

- **テスト名**: `VITE_API_BASE_URL` 設定時はその値が優先される
  - **何をテストするか**: 環境変数が設定されている場合のフォールバック挙動
  - **期待される動作**: 環境変数の値をBASE_URLとして使用する
- **入力値**: `VITE_API_BASE_URL='https://example.com/api/v1'` を `vi.stubEnv` で設定
  - **入力データの意味**: 開発者が独自のAPIエンドポイントを指定するケース
- **期待される結果**: `fetch` が `'https://example.com/api/v1/items'` で呼び出される
  - **期待結果の理由**: `??` 演算子によるフォールバックは既存挙動のまま維持する必要がある
- **テストの目的**: 環境変数優先ロジックの回帰確認
  - **確認ポイント**: デフォルト値変更が環境変数優先ロジックを壊していないこと
- 🟡 信頼性レベル: 既存実装のフォールバック挙動からの妥当な推測

## 3. 異常系テストケース

- 🔵 本タスクはBASE_URLの静的な値変更のみであり、新たな異常系は発生しない。既存の異常系テスト（NETWORK_ERROR, PARSE_ERROR, VALIDATION_ERROR）は `client.test.ts` に既存実装済みであり、回帰確認として引き続きパスすることを確認する。

## 4. 境界値テストケース
