# TASK-0006 テストケース: 統合環境の起動・疎通・分離結合テスト

受け入れ基準（`docs/spec/backend-frontend-integration/acceptance-criteria.md`）の12件をそのまま採用する。

## 1. 正常系テストケース

- **TC-001-01**: `docker compose up -d` 実行後、全コンテナが起動状態になる 🔵
- **TC-001-02**: `db` のヘルスチェック成功後に `backend` が起動する 🔵
- **TC-002-01**: 統合用docker-compose定義に `backend`・`db` の `ports:` が存在しない 🔵
- **TC-002-02**: 既存の `backend/docker-compose.yml` が変更されていない（`git diff` 差分なし） 🔵
- **TC-003-01**: フロントエンドのAPIリクエストが相対パスで発行される 🔵
- **TC-003-02**: nginxが `/api/` リクエストをbackendへ正しく転送する 🔵
- **TC-003-03**: SPAの直接URLアクセスで `index.html` が返る 🟡
- **TC-NFR-101-01**: ホストからbackend/dbへの直接接続テスト（両方失敗すること） 🔵
- **TC-NFR-102-01**: `.env` がgit管理対象外であることの確認 🔵

## 2. 異常系テストケース

- **TC-001-E01**: ポート80使用中の場合、`docker compose up` が失敗する 🟡
- **TC-001-E02**: dbヘルスチェック失敗継続時、backendが待機し続ける 🟡
- **TC-002-E01**: ホストから `localhost:8080` への接続が失敗する 🔵
- **TC-003-E01**: backend未起動時に `/api/` アクセスで502等が返る 🟡

## 3. 境界値テストケース

- 🔵 本タスクに数値的な境界値は存在しない。ネットワーク到達性の有無（到達可/不可）が実質的な境界条件であり、上記の正常系・異常系テストケースでカバーされる。

## 4. Edgeケーステスト（Should Have）

- **TC-EDGE-001-01**: dbが起動しない状態でのbackend挙動確認（起動を試みず待機し続ける） 🟡
- **TC-EDGE-002-01**: backend停止中の `/api/` アクセスエラー確認（502等） 🟡

## 5. 開発言語・フレームワーク

- **実施方法**: シェルコマンド（`docker compose`, `curl`, `git diff` 等）による手動/スクリプト実施 🔵
- **テストフレームワーク**: 本タスクは結合テストであり、Vitest等の自動テストフレームワークは使用しない（TASK-0001〜0003の単体テストで担保済み） 🔵
