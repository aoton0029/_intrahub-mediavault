## 1. 正常系テストケース（基本的な動作）

### TC-01: 全ナビゲーションリンクがレンダリングされる
- **テスト名**: 全8項目のナビゲーションリンクが表示されること
  - **何をテストするか**: `Sidebar`コンポーネントを`MemoryRouter`内でレンダリングしたとき、全体一覧・3メディアグループ・マイリスト・タグ/カテゴリ・スタッフ・設定の各リンクが存在すること
  - **期待される動作**: `<nav>`内に8つの`<a>`（`NavLink`）要素がレンダリングされる
- **入力値**: `<MemoryRouter><Sidebar /></MemoryRouter>`
  - **入力データの意味**: 初期ルート`/`での標準的なレンダリングケース
- **期待される結果**: `screen.getByRole('link', { name: '全体一覧' })`等、8つのリンクがすべて`getByRole`で取得できる
  - **期待結果の理由**: TASK-0007.md完了条件「全体一覧・3メディアグループ・マイリスト・タグ/カテゴリ・スタッフ・設定へのリンクがある」を直接検証するため
- **テストの目的**: ナビゲーション項目の網羅性確認
  - **確認ポイント**: ラベル文言の一致、リンク数が過不足ないこと
- 🔵 信頼性レベル: TASK-0007.md「完了条件」「ナビゲーション構成」より確定

### TC-02: 各リンクのhref(to)が正しいパスを指す
- **テスト名**: 各ナビゲーションリンクの`href`属性が仕様通りのパスであること
  - **何をテストするか**: 8項目それぞれの`to`値が要件定義の対応表と一致するか
  - **期待される動作**: `screen.getByRole('link', { name: 'マイリスト' })`の`href`が`/mylists`等
- **入力値**: 各label文言（"全体一覧","一般メディア","学術書・専門書","論文・文献","マイリスト","タグ/カテゴリ","スタッフ","設定"）
  - **入力データの意味**: TASK-0007.md記載のnavItems全件を網羅
- **期待される結果**:
  | label | href |
  |---|---|
  | 全体一覧 | `/` |
  | 一般メディア | `/collections/general` |
  | 学術書・専門書 | `/collections/academic` |
  | 論文・文献 | `/collections/paper` |
  | マイリスト | `/mylists` |
  | タグ/カテゴリ | `/tags-categories` |
  | スタッフ | `/staff` |
  | 設定 | `/settings` |
  - **期待結果の理由**: global-navigation-requirements.md「入力・出力の仕様」の対応表に基づく
- **テストの目的**: 遷移先パスの正確性確認
  - **確認ポイント**: タイポや末尾スラッシュ等の差異がないこと
- 🔵 信頼性レベル: requirements.md「ナビゲーション項目とパスの対応」より確定

### TC-03: ナビリンクをクリックすると対応するルートへ遷移する
- **テスト名**: 「マイリスト」リンクをクリックすると`/mylists`へ遷移すること
  - **何をテストするか**: `userEvent.click`でリンクをクリックした際のルート変化
  - **期待される動作**: クリック後、`window.location`相当（テストでは`MemoryRouter`の`initialEntries`/`useLocation`を表示する補助コンポーネント）が`/mylists`を示す
- **入力値**: `MemoryRouter`でラップし、ルート遷移を確認するための簡易`Routes`定義（例: `<Route path="*" element={<LocationDisplay />} />`を併設）を用意してクリックをシミュレート
  - **入力データの意味**: 実際のクリック操作によるSPA内遷移を再現
- **期待される結果**: クリック後に表示される現在パスが`/mylists`になる
  - **期待結果の理由**: TASK-0007.mdテストケース2「クリック時の遷移」を検証するため
- **テストの目的**: React Router統合の動作確認
  - **確認ポイント**: `NavLink`のデフォルト遷移挙動が阻害されていないこと
- 🔵 信頼性レベル: TASK-0007.md「単体テスト要件 テストケース2」より確定

### TC-04: 現在ルートに対応するリンクにアクティブクラスが付与される
- **テスト名**: 現在ルートが`/staff`のとき「スタッフ」リンクに`active`クラスが付与されること
  - **何をテストするか**: `NavLink`の`isActive`に基づくクラス切り替え
  - **期待される動作**: `initialEntries={['/staff']}`でレンダリングした際、「スタッフ」リンクの`className`に`active`が含まれ、他のリンクには含まれない
- **入力値**: `<MemoryRouter initialEntries={['/staff']}><Sidebar /></MemoryRouter>`
  - **入力データの意味**: 「設定」「マイリスト」等の他ルートとは異なる単一ルートを明示的に指定し区別を確認
- **期待される結果**: 「スタッフ」リンクの`class`属性に`active`を含み、他7つのリンクには含まない
  - **期待結果の理由**: TASK-0007.md完了条件「現在のアクティブルートが視覚的に識別できる」を検証
- **テストの目的**: アクティブ状態表示の正確性確認
  - **確認ポイント**: アクティブなのは常に1つのみであること（誤って複数や0個にならないこと）
- 🔵 信頼性レベル: TASK-0007.md「単体テスト要件 テストケース3」より（クラス名の具体仕様は🟡推測）

### TC-05: ルートパス("/")がアクティブのとき「全体一覧」のみがアクティブになる（end指定の確認）
- **テスト名**: ルート`/`表示時に「全体一覧」のみアクティブになり、他の`/collections/...`等が誤ってアクティブにならないこと
  - **何をテストするか**: `NavLink`の`to="/"`は前方一致だと全パスにマッチしてしまうため、`end`propの付与有無を検証
  - **期待される動作**: `initialEntries={['/']}`時、「全体一覧」のみ`active`、他は非アクティブ
- **入力値**: `<MemoryRouter initialEntries={['/']}><Sidebar /></MemoryRouter>`
  - **入力データの意味**: ルートパスの前方一致バグを検出する代表的な境界ケース
- **期待される結果**: 「全体一覧」リンクのみ`active`クラスを持つ
  - **期待結果の理由**: React Router v7の`NavLink`は`to="/"`に`end`を付けないと常にアクティブと誤判定されるため、実装の正確性を担保する必要がある
- **テストの目的**: ルートパスのアクティブ判定バグ防止
  - **確認ポイント**: `end`propの付与または同等の判定ロジック
- 🟡 信頼性レベル: React Router v7の一般的な`NavLink`仕様からの妥当な推測（設計文書に明記なし）

## 2. 異常系テストケース（エラーハンドリング）

### TC-06: 未知のルート表示時にどのリンクもアクティブにならない
- **エラーケースの概要**: ナビゲーション項目に存在しないパス（例: `/items/123`のような詳細ページ）を表示しているとき
  - **エラー処理の重要性**: 該当しないリンクが誤ってアクティブ表示されると、ユーザーが現在位置を誤認する
- **入力値**: `<MemoryRouter initialEntries={['/items/123']}><Sidebar /></MemoryRouter>`
  - **不正な理由**: navItemsの8パスいずれにも該当しない動的パラメータ付きルート
  - **実際の発生シナリオ**: アイテム詳細画面（TASK-0017以降で実装）をサイドバーと共に表示する場合
- **期待される結果**: 8つのリンクすべてに`active`クラスが付与されない
  - **エラーメッセージの内容**: 該当なし（UIの状態検証のため例外は発生しない）
  - **システムの安全性**: アクティブ状態が「不明」として扱われても画面遷移自体は問題なく機能する
- **テストの目的**: 未対応ルートでの誤表示防止確認
  - **品質保証の観点**: ナビゲーション対象外ページでもUIが破綻しないことを保証
- 🟡 信頼性レベル: TASK-0007.md「想定される使用例」エッジケース記載（🟡）から導出

### TC-07: Sidebarがpropsなしでもレンダリングエラーを起こさない
- **エラーケースの概要**: `Sidebar`は外部からpropsを受け取らない静的コンポーネントであるため、props未指定時に例外が発生しないことを確認
  - **エラー処理の重要性**: 将来的な呼び出しミス（不要なprops渡し含む）に対する堅牢性を最低限担保する
- **入力値**: `<Sidebar />`（propsなし）
  - **不正な理由**: 該当なし（正常な使用方法だが、念のため例外非発生を明示的にテストする）
  - **実際の発生シナリオ**: `RootLayout`からの通常呼び出し
- **期待される結果**: レンダリング時に例外がスローされない（`render()`がエラーなく完了する）
  - **エラーメッセージの内容**: 該当なし
  - **システムの安全性**: クラッシュしないことを保証
- **テストの目的**: コンポーネントの基本的な堅牢性確認
  - **品質保証の観点**: 最低限のレンダリング安定性を担保
- 🔵 信頼性レベル: requirements.md「入力・出力の仕様」（propsを受け取らない静的なナビゲーション構成）より確定

## 3. 境界値テストケース

### TC-08: 同名に見える別パス間でアクティブ判定が混同しない（`/collections/general` 表示時）
- **テスト名**: `/collections/general`表示時に「一般メディア」のみアクティブになり、「学術書・専門書」「論文・文献」が誤って一致しないこと
  - **境界値の意味**: `/collections/`配下の3パスは接頭辞が共通するため、`NavLink`のマッチングロジックが完全一致でない場合に誤判定が起きやすい境界
  - **境界値での動作保証**: 接頭辞が共通する隣接パス間でも正確に区別できることを保証
- **入力値**: `<MemoryRouter initialEntries={['/collections/general']}><Sidebar /></MemoryRouter>`
  - **境界値選択の根拠**: 3つの`/collections/*`パスのうち最初の項目を選び、残り2項目との混同有無を確認する代表ケース
  - **実際の使用場面**: ユーザーが一般メディア一覧画面を閲覧中の状態
- **期待される結果**: 「一般メディア」リンクのみ`active`、「学術書・専門書」「論文・文献」は非アクティブ
  - **境界での正確性**: パス文字列の前方一致による誤マッチがないこと
  - **一貫した動作**: TC-04（`/staff`）と同様のロジックで動作すること
- **テストの目的**: 類似パス間でのアクティブ判定境界の確認
  - **堅牢性の確認**: パス構造が似た項目が増えても誤動作しない設計であることの確認
- 🟡 信頼性レベル: React Routerの`NavLink`一般仕様＋requirements.mdのパス一覧からの妥当な推測

## 4. 開発言語・フレームワーク

- **プログラミング言語**: TypeScript（React 19.2.6 / .tsx）
  - **言語選択の理由**: プロジェクト全体がTypeScript + Reactで統一されているため（frontend/package.json, frontend/CLAUDE.md）
  - **テストに適した機能**: 型安全なpropsとコンポーネント定義により、テストコードでも誤った呼び出しをコンパイル時に検出できる
- **テストフレームワーク**: Vitest + @testing-library/react（+ `react-router-dom`の`MemoryRouter`）
  - **フレームワーク選択の理由**: frontend/vitest.config.ts, frontend/src/test/setup.tsで既に構成済みであり、既存コンポーネント（EmptyState等）も同様の構成でテストされているため一貫性を保つ
  - **テスト実行環境**: jsdom環境、`yarn test`で実行
- 🔵 信頼性レベル: frontend/vitest.config.ts, frontend/CLAUDE.mdより確定
