## 実装内容

### 1. AcademicBookDetailsフォーム部品 🔵

**信頼性**: 🔵 *interfaces.ts AcademicBookDetails（104-110行目）・REQ-019より*

`src/features/item-form/components/AcademicBookDetailsFields.tsx` を実装する。`AcademicBookDetails`型に対応するzodスキーマ（TASK-0022の`details`部分を`.extend()`して構成）に基づき、以下の項目の入力UIを提供する。

- 著者（`author`、任意、文字列入力）
- 出版社（`publisher`、任意、文字列入力）
- ISBN（`isbn`、任意、ISBN-10/ISBN-13形式の入力検証 🟡 桁数・チェックディジットの厳密検証は要件に明記なし、文字列長・数字+ハイフンのパターンチェック程度の妥当な推測）
- NDL ID（`ndlId`、`source==='api'`時のみ表示専用 🟡 ItemBase.externalIdと同様の推測）
- Google Books ID（`googleBooksId`、`source==='api'`時のみ表示専用 🟡 同上）

REQ-104（学術書/専門書グループはISBN等専用フォーム項目を表示しなければならない）に対応し、本フォーム部品はTASK-0026にて`media_type==='academic_book'`の場合にのみ表示切り替えされることを前提とする。

## 単体テスト要件 🔵

**信頼性**: 🔵 *REQ-019・REQ-104・NFR-201より*

- 著者・出版社・ISBNの各フィールドが表示されること
- ISBNに桁数や形式が不正な値（例: 英字混在、極端に短い文字列）を入力した場合にバリデーションエラーとなること
- ISBNを空のまま送信してもバリデーションエラーにならないこと（任意項目）
- `ndlId`/`googleBooksId`について、`source==='api'`の場合は編集不可（表示専用）として描画されること
- 正しい形式のISBN（ISBN-10/ISBN-13）を入力した場合にバリデーションが成功すること
