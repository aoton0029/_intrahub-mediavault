## 背景・目的

詳細画面（`/items/:id`）はアイテムの全項目表示・編集削除導線・status/consumed_date更新の起点となる画面であり、Phase3で実装するGroupSection（TASK-0018）・関連付けUI（TASK-0019）・リンク/ファイル/トレーラーUI（TASK-0020）はすべて本ページに組み込まれる。`Item`判別共用体（`mediaType`によるdiscriminated union）に基づき、メディア種別ごとの詳細表示（`details`フィールド）を切り替える基盤を構築する。

## 実装詳細

### 対象ファイル

- `src/pages/ItemDetailPage.tsx`（新規）
- `src/features/items/ItemDetailHeader.tsx`（新規、任意分割）
- `src/features/status/StatusUpdateControl.tsx`（新規、status・consumed_date更新UI）

### 機能要件対応

- 🔵 **REQ-007**: 詳細画面で既存アイテムの編集（`PATCH /items/:id`への遷移導線。実際の編集フォームはItemFormPage(mode=edit)が担当）・削除（`DELETE /items/:id`）導線を提供する。削除時は`ConfirmDialog`（共通コンポーネント、TASK-0006）で確認後に実行し、成功後は一覧へ遷移する。
  *出典: requirements.md REQ-007*
- 🔵 **REQ-013**: status（`not_started`/`in_progress`/`completed`）とconsumed_dateの更新UIを提供し、`PATCH /items/:id/status`（`UpdateItemStatusRequest`）を呼び出す。
  *出典: requirements.md REQ-013, interfaces.ts UpdateItemStatusRequest*
- 🔵 **判別共用体に基づく表示分岐**: `interfaces.ts`の`Item`型（`mediaType`で判別される8種のUnion: anime/movie/drama/manga/novel/game/academic_book/paper）に応じ、`item.details`の各フィールド（例: anime→`episodeCount`/`studio`、movie→`runtimeMinutes`/`director`、game→`platformList`/`developer`等）を出し分ける表示コンポーネントを実装する。`isItemOfType`型ガードまたは`switch(item.mediaType)`で分岐する。
  *出典: interfaces.ts Item型定義, ヒアリングQ3*

### API呼び出し

- `useItemQuery(id)`（TASK-0009で実装済みの`GET /items/:id`フック）🔵 *architecture.md API層設計より*
- `useUpdateItemStatusMutation()`（`PATCH /items/:id/status`）🔵 *interfaces.ts UpdateItemStatusRequestより*
- `useDeleteItemMutation()`（`DELETE /items/:id`）🔵 *requirements.md REQ-007より*

未実装の場合は`src/api/items.ts`に追加実装する（TASK-0009のスコープ外であった場合の補完）。

### コンポーネント構成

```
pages/ItemDetailPage.tsx
├── ItemDetailHeader（タイトル・カバー画像・編集/削除ボタン）
├── StatusUpdateControl（status select + consumed_date picker）
├── 詳細情報セクション（mediaType別details表示）
├── <Outlet for Phase3 subsections>
│   ├── GroupSection（TASK-0018で追加）
│   ├── RelationsSection（TASK-0019で追加）
│   └── LinksFilesSection（TASK-0020で追加）
```

本タスクでは上記サブセクションのプレースホルダ（空のセクション枠）までを実装範囲とし、実体はTASK-0018〜0020で追加する。

## UI/UX要件

- 🔵 **ローディング状態**: `useItemQuery`の`isPending`時にスケルトンまたはローディングスピナーを表示する。
- 🔵 **エラー表示**: `ITEM_NOT_FOUND`（404）受信時はエラートーストを表示し、一覧画面（履歴があれば直前の一覧、なければ`/`）へリダイレクトする。
  *出典: dataflow.md エラーハンドリングフロー「*_NOT_FOUND 404 → 一覧へリダイレクト+エラートースト」*
- 🟡 **モバイル対応**: Tailwind CSSのレスポンシブユーティリティで、画面幅に応じてヘッダー・詳細情報セクションを縦積みレイアウトに切り替える。
  *出典: architecture.md Tailwind CSS 4 + shadcn/ui方針から妥当な推測*
