## タスク概要

`src/api/client.ts`に、素の`fetch`をラップした`apiClient`を実装する。`ApiOkResponse`/`ApiErrorResponse`を判定し、エラー時は`ApiClientError`として例外化する。`VITE_API_BASE_URL`環境変数（`.env`）でベースURL（デフォルト`http://localhost:8080/api/v1`）を上書き可能にする。本クライアントは全featureのAPIフック（TASK-0005後続のapi/*実装）から利用される基盤コンポーネントである。

## 実装詳細

### apiClient基本設計 🔵
**信頼性**: 🔵 *architecture.md「バックエンド連携（API層）」より：「素の`fetch`をラップした`apiClient`（`src/api/client.ts`）。axios等の追加依存は導入しない」*

```ts
// src/api/client.ts
import { ApiClientError } from '@/types';
import type { ApiResponse } from '@/types';

const BASE_URL = import.meta.env.VITE_API_BASE_URL ?? 'http://localhost:8080/api/v1';

interface RequestOptions {
  method?: 'GET' | 'POST' | 'PATCH' | 'DELETE' | 'PUT';
  body?: unknown;
  signal?: AbortSignal;
  headers?: Record<string, string>;
}

export async function apiClient<T>(path: string, options: RequestOptions = {}): Promise<{ data: T; pagination?: Pagination }> {
  const { method = 'GET', body, signal, headers } = options;

  let res: Response;
  try {
    res = await fetch(`${BASE_URL}${path}`, {
      method,
      headers: {
        ...(body !== undefined && !(body instanceof FormData) ? { 'Content-Type': 'application/json' } : {}),
        ...headers,
      },
      body: body instanceof FormData ? body : body !== undefined ? JSON.stringify(body) : undefined,
      signal,
    });
  } catch (err) {
    throw new ApiClientError('NETWORK_ERROR', err instanceof Error ? err.message : 'ネットワークエラーが発生しました');
  }

  let json: ApiResponse<T>;
  try {
    json = await res.json();
  } catch {
    throw new ApiClientError('PARSE_ERROR', 'レスポンスの解析に失敗しました');
  }

  if (!json.success) {
    throw new ApiClientError(json.error.code, json.error.message);
  }

  return { data: json.data, pagination: json.pagination };
}
```

🟡 上記の関数シグネチャ（`RequestOptions`の形・FormData分岐等）は設計文書に直接の実装例がないため、architecture.md記載の方針（fetchラップ・ApiOkResponse/ApiErrorResponse判定・ApiClientError例外化）から妥当な推測で構成した。`FormData`対応は後続のファイルアップロード（REQ-012, TASK後続）を見据えた設計判断（🟡）。

### 環境変数対応 🔵
**信頼性**: 🔵 *architecture.md「APIベースURL」: 「`http://localhost:8080/api/v1`（🟡推測値を継承、`.env`の`VITE_API_BASE_URL`で上書き可能とする）」*

`frontend/.env`（または`.env.local`、gitignore対象）に以下を定義する。

```
VITE_API_BASE_URL=http://localhost:8080/api/v1
```

`frontend/.env.example`にも同内容を記載し、リポジトリにコミットする（🟡 一般的なVite運用パターンからの推測）。

### `/internal/*`呼び出し禁止の設計上の保証 🔵
**信頼性**: 🔵 *REQ-402: 「システムはバックエンドの内部REST API（`/internal/*`）を呼び出してはならない」*

apiClient自体はパス文字列を受け取る汎用実装のため、呼び出し側（各api/*.tsファイル）で`/internal/*`を使用しないことが運用上の前提となる。本タスクでは関数のJSDocコメントに「`/internal/*`は対象外」である旨を明記し、レビュー時に検出しやすくする（🟡 静的な型レベルでの強制は本設計では行わない）。

## 単体テスト要件

### テストケース1: 成功レスポンス解析 🔵
**信頼性**: 🔵 *interfaces.ts `ApiOkResponse<T>`構造・完了条件より*
- `fetch`をモックし`{success: true, data: {...}}`を返すとき、`apiClient`が`data`を正しく返すこと
- `pagination`を含むレスポンスの場合、`pagination`も正しく返されること

### テストケース2: エラーレスポンスで`ApiClientError`をthrow 🔵
**信頼性**: 🔵 *interfaces.ts `ApiErrorResponse`構造・architecture.md「エラーハンドリング」より*
- `fetch`をモックし`{success: false, error: {code: 'VALIDATION_ERROR', message: '...'}}`を返すとき、`apiClient`が`ApiClientError`をthrowし、`error.code`/`error.message`が一致すること

### テストケース3: ネットワークエラー処理 🔵
**信頼性**: 🔵 *完了条件「ネットワークエラー時も適切にエラーハンドリングされる」より*
- `fetch`がreject（ネットワーク切断等）した場合、`ApiClientError`（コード`NETWORK_ERROR`等）がthrowされること
- レスポンスのJSON parseに失敗した場合も同様にエラー化されること

### テストケース4: VITE_API_BASE_URL上書き 🟡
**信頼性**: 🟡 *完了条件・architecture.md記載のオプション挙動から妥当な推測*
- 環境変数未設定時にデフォルトURL（`http://localhost:8080/api/v1`）がベースとして使われること（vitestの`vi.stubEnv`等でテスト）
