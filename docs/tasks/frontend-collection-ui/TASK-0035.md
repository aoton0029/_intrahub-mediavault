## タスク概要

Playwrightで以下4つの主要フローのE2Eテストを実装する: ①全体一覧の閲覧・絞り込み（dataflow.md機能1）②外部API検索からの追加（機能2）③手動追加・編集（機能3）④インポート（機能5）。本プロジェクトはコンポーネント/コンテキストテスト中心の方針であるため、E2Eテストは上記4主要フローに限定し、網羅的な画面・操作パターンのE2E化は行わない。各フローについてバックエンドAPIをモック（Playwrightの`page.route()`またはMSW）し、正常系に加えて主要なエラーケース（`API_KEY_NOT_CONFIGURED`, `EXTERNAL_API_TIMEOUT`）の一部を含める。

## 実装詳細

### 1. フロー①: 全体一覧の閲覧・絞り込み E2E 🔵
**信頼性**: 🔵 *dataflow.md機能1シーケンス図・REQ-001/002/003より*

`/`にアクセスしカード一覧が表示されることを確認後、`FilterBar`で`media_type`を変更し、URLクエリパラメータ（`?media_type=...`）が更新され、絞り込まれたカード一覧が表示されることを確認する。ブラウザの戻る操作で絞り込み前の状態に戻ることも確認する（REQ-003 URL同期）。

**実装ファイル**: `frontend/tests/e2e/list-filter.spec.ts`

### 2. フロー②: 外部API検索からの追加 E2E 🔵
**信頼性**: 🔵 *dataflow.md機能2シーケンス図・REQ-005・EDGE-001/REQ-203より*

`/search/general`にアクセスし検索語を入力して検索実行、モックした`GET /items/search`の成功レスポンスから1件選択して「追加」、モックした`POST /items/import`の201レスポンスを受けてtoast表示+詳細画面（`/items/:id`）へ遷移することを確認する。エラーケースとして、`GET /items/search`が422（`API_KEY_NOT_CONFIGURED`）を返す場合に「APIキー未設定」表示+手動追加画面への導線が表示されること、502（`EXTERNAL_API_TIMEOUT`）を返す場合にエラーメッセージ+再試行ボタンが表示されることをそれぞれ確認する。

**実装ファイル**: `frontend/tests/e2e/search-add.spec.ts`

### 3. フロー③: 手動追加・編集 E2E 🔵
**信頼性**: 🔵 *dataflow.md機能3シーケンス図・REQ-006/007より*

`/items/new/general`にアクセスし必須項目を入力して保存、モックした`POST /items`の201レスポンスを受けて詳細画面へ遷移+toast表示を確認する。続けて詳細画面から編集（`/items/:id/edit`）に遷移し、項目を変更して保存、モックした`PATCH /items/:id`の200レスポンスを受けて詳細画面へ遷移することを確認する。バリデーションNGケース（必須項目未入力での保存試行）でフィールド近傍にエラーが表示されることも1ケース含める。

**実装ファイル**: `frontend/tests/e2e/manual-add-edit.spec.ts`

### 4. フロー④: インポート E2E 🔵
**信頼性**: 🔵 *dataflow.md機能5シーケンス図・REQ-022・EDGE-002より*

`/settings`のインポートタブにアクセスし、CSVファイル（テスト用固定ファイル、`tests/e2e/fixtures/booklog-sample.csv`）を選択して実行、モックした`POST /import/booklog`の`ImportSummary{successCount, failureCount, failures[]}`レスポンスを受けて成功件数・失敗件数・失敗理由一覧が画面に表示されることを確認する。

**実装ファイル**: `frontend/tests/e2e/import.spec.ts`, `frontend/tests/e2e/fixtures/booklog-sample.csv`

### 5. APIモック共通基盤 🟡
**信頼性**: 🟡 *Playwrightでの一般的なAPIモック実装パターンから推測（設計文書にE2Eモック方式の個別記載なし）*

## 単体テスト要件

本タスクはE2Eテスト整備が主目的のため、単体テストは対象外。代わりに統合テスト要件（E2Eシナリオ）を以下に定義する。

---

## 統合テスト要件

### 統合テストケース1: 全体一覧の絞り込みとURL同期 🔵
**Given** 全体一覧画面（`/`）を開いている
**When** `media_type`フィルタを「anime」に変更する
**Then** URLが`?media_type=anime`に更新され、表示されるカードがアニメのみにフィルタされる。さらにブラウザの「戻る」操作で絞り込み前の状態に戻る

### 統合テストケース2: 外部API検索→選択→追加→詳細遷移（正常系） 🔵
**Given** `/search/general`で検索語を入力する
**When** 検索実行後、結果から1件選択し「追加」を押す
**Then** `POST /items/import`が呼ばれ、成功後に詳細画面へ遷移しtoastが表示される

### 統合テストケース3: 外部API検索でAPI_KEY_NOT_CONFIGURED（422）発生時の表示 🔵
**Given** `GET /items/search`が422 `API_KEY_NOT_CONFIGURED`を返すようモックする
**When** `/search/general`で検索を実行する
**Then** 「APIキー未設定」相当のエラー表示と手動追加画面への遷移導線が表示される（REQ-203）

### 統合テストケース4: 外部API検索でEXTERNAL_API_TIMEOUT（502）発生時の表示 🔵
**Given** `GET /items/search`が502 `EXTERNAL_API_TIMEOUT`を返すようモックする
**When** `/search/general`で検索を実行する
**Then** エラーメッセージと再試行ボタンが表示される（EDGE-001）

### 統合テストケース5: 手動追加→保存→詳細遷移（正常系） 🔵
**Given** `/items/new/general`で必須項目を入力する
**When** 保存ボタンを押す
**Then** `POST /items`が呼ばれ、成功後に詳細画面へ遷移する

### 統合テストケース6: 編集→保存→詳細遷移（正常系） 🔵
**Given** 既存アイテムの編集画面（`/items/:id/edit`）で項目を変更する
**When** 保存ボタンを押す
**Then** `PATCH /items/:id`が呼ばれ、成功後に詳細画面へ遷移する

### 統合テストケース7: インポート実行→結果表示（成功・失敗混在） 🔵
**Given** `/settings`インポートタブでCSVファイルを選択する
**When** 実行ボタンを押し、`ImportSummary{successCount:8, failureCount:2, failures:[...]}`がモックレスポンスとして返る
**Then** 画面に成功件数・失敗件数・各失敗行の`rowNumber`/`reason`一覧が表示される（EDGE-002）

## 注意事項

- 本タスクのE2Eテストは「主要フローのみ」に限定する方針のため、フロー④（シーズン/巻管理）やマイリスト・タグ管理・スタッフ管理等の画面はE2E対象外とし、それらはコンポーネント/コンテキストテスト（Phase2〜5の各タスクで実装済み）でカバーする。
- E2Eテストは実バックエンドに依存せず、`page.route()`等によるAPIモックで完結させること。CI環境でバックエンドサーバーを起動せずに実行できることを前提とする。
- TASK-0033で確定したルーティング構成（パス・メディアグループ分岐）を前提にテストを実装するため、TASK-0033完了後に着手すること。
- TASK-0034のアクセシビリティ修正（特に`div`+`onClick`からネイティブ要素への変更）によりE2Eテストのセレクタ（`getByRole`等）が影響を受ける可能性があるため、TASK-0034完了後に実装することが望ましい。
