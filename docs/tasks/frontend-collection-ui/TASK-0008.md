## 実装詳細

### useSearchParamsFilter 🔵
**信頼性**: 🔵 *requirements.md REQ-003「システムは一覧画面の絞り込み状態をURLクエリパラメータに反映し、ブラウザの戻る/進む・URL共有で同一の絞り込み結果を再現できなければならない」、architecture.md「ルーティング: React Router v7。`useSearchParams`で一覧フィルタ状態をURLに同期（REQ-003）」、dataflow.md「機能1」シーケンス図より*

`interfaces.ts`の`ItemListFilters`型（`mediaType`/`tagId`/`categoryId`/`isFavorite`/`status`/`page`/`limit`）をURLクエリパラメータ（`media_type`/`tag_id`/`category_id`/`favorite`/`status`/`page`/`limit`、🟡 クエリパラメータ名はバックエンドAPI仕様のスネークケース命名から妥当な推測）と相互変換する。

```ts
// src/hooks/useSearchParamsFilter.ts
import { useSearchParams } from 'react-router-dom';
import type { ItemListFilters } from '@/types';

export function useSearchParamsFilter() {
  const [searchParams, setSearchParams] = useSearchParams();

  const filters: ItemListFilters = {
    mediaType: searchParams.get('media_type') as ItemListFilters['mediaType'] ?? undefined,
    tagId: searchParams.get('tag_id') ?? undefined,
    categoryId: searchParams.get('category_id') ?? undefined,
    isFavorite: searchParams.get('favorite') === 'true' ? true : undefined,
    status: searchParams.get('status') as ItemListFilters['status'] ?? undefined,
    page: searchParams.get('page') ? Number(searchParams.get('page')) : undefined,
    limit: searchParams.get('limit') ? Number(searchParams.get('limit')) : undefined,
  };

  const setFilters = (next: Partial<ItemListFilters>) => {
    setSearchParams(prev => {
      const updated = new URLSearchParams(prev);
      Object.entries(next).forEach(([key, value]) => {
        const paramKey = toQueryKey(key as keyof ItemListFilters);
        if (value === undefined || value === null || value === '') {
          updated.delete(paramKey);
        } else {
          updated.set(paramKey, String(value));
        }
      });
      return updated;
    });
  };

  return { filters, setFilters };
}
```

`dataflow.md`「機能1: 全体一覧の閲覧・絞り込み」シーケンス図の「U->>F: フィルタ条件を変更」→「F->>R: setSearchParams(新条件)」→「R->>P: 再レンダリング（queryKey変化）」というフローに対応する実装とする（🔵）。クエリパラメータの具体的なキー名マッピング（`toQueryKey`関数の内部対応）はバックエンドAPI仕様のクエリパラメータ命名（architecture.md「対象API」記載の`media_type`等のスネークケース）からの妥当な推測（🟡）。

### useConfirmDialog 🟡
**信頼性**: 🟡 *architecture.mdに直接の関数名明記はないが、タスク指示・ConfirmDialog（TASK-0006）コンポーネントとの組み合わせ用フックとして妥当に必要とされる。REQ-007（アイテム削除）等の確認UIパターンから推測*

```ts
// src/hooks/useConfirmDialog.ts
import { useState, useCallback } from 'react';

export function useConfirmDialog() {
  const [open, setOpen] = useState(false);
  const [pendingAction, setPendingAction] = useState<(() => void) | null>(null);

  const confirm = useCallback((action: () => void) => {
    setPendingAction(() => action);
    setOpen(true);
  }, []);

  const handleConfirm = useCallback(() => {
    pendingAction?.();
    setOpen(false);
    setPendingAction(null);
  }, [pendingAction]);

  const handleCancel = useCallback(() => {
    setOpen(false);
    setPendingAction(null);
  }, []);

  return { open, confirm, handleConfirm, handleCancel };
}
```

`ConfirmDialog`コンポーネント（TASK-0006）の`open`/`onConfirm`/`onCancel`propsとそのまま接続できるインターフェースとした（🟡 設計上の整合を意図した推測）。

## 単体テスト要件

### useSearchParamsFilter: URL読み書き 🔵
**信頼性**: 🔵 *REQ-003・dataflow.md「機能1」より*
- 初期URL（例: `?media_type=anime&page=2`）から`filters.mediaType==='anime'`, `filters.page===2`が読み取れること
- `setFilters({ mediaType: 'movie' })`呼び出し後、URLクエリパラメータが`media_type=movie`に更新されること
- 値を`undefined`にした場合、対応するクエリパラメータがURLから削除されること
- （`MemoryRouter`の`initialEntries`を変更して）ブラウザの戻る/進む相当の操作で異なるURLをレンダリングした際、`filters`が正しく再計算されること

### useConfirmDialog: 状態遷移 🔵
**信頼性**: 🔵 *完了条件・一般的な確認ダイアログパターンより*
- 初期状態で`open===false`であること
- `confirm(action)`呼び出し後、`open===true`になること
- `handleConfirm()`呼び出し後、渡した`action`が実行され、`open===false`に戻ること
- `handleCancel()`呼び出し後、`action`は実行されず`open===false`になること
