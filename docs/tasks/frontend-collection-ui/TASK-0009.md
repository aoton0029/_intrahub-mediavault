## タスク概要
`src/api/items.ts`に、アイテム一覧・詳細取得・削除・status更新を行うTanStack Queryフック（`useItemsQuery`, `useItemQuery`, `useDeleteItemMutation`, `useUpdateItemStatusMutation`）を実装する。一覧取得はフィルタ・ページングをクエリパラメータとして送信し（REQ-002）、`queryKey`に`['items', filters]`形式を採用してキャッシュ管理を行う。削除・status更新成功時は関連する一覧クエリを`invalidateQueries`で無効化する。

## 依存タスク
- **前提タスク**: TASK-0005（apiClient実装）
- **後続タスク**: TASK-0011（HomePage）, TASK-0012（GeneralListPage）, TASK-0013（AcademicListPage）, TASK-0014（PaperListPage）

## 完了条件
- [ ] `useItemsQuery(filters: ItemListFilters)`が`GET /items`を`media_type`/`tag_id`/`category_id`/`is_favorite`/`status`/`page`/`limit`クエリパラメータ付きで呼び出し、`queryKey=['items', filters]`でキャッシュされる
- [ ] `useItemQuery(id: string)`が`GET /items/:id`を呼び出し、`queryKey=['items', 'detail', id]`でキャッシュされる
- [ ] `useDeleteItemMutation()`が`DELETE /items/:id`を呼び出し、成功時に`['items']`配下の一覧クエリを`invalidateQueries`で無効化する
- [ ] `useUpdateItemStatusMutation()`が`PATCH /items/:id/status`に`UpdateItemStatusRequest`を送信し、成功時に対象アイテムの詳細クエリと一覧クエリを無効化する
- [ ] APIエラー時、各フックの`error`に`ApiClientError`がそのまま伝播する

## 実装詳細

### 1. fetch関数の実装 🔵
**信頼性**: 🔵 *architecture.md「リソース別フック」・interfaces.ts ItemListFilters/UpdateItemStatusRequestより*

`fetchItems(filters: ItemListFilters): Promise<ApiOkResponse<Item[]>>`, `fetchItem(id: string): Promise<Item>`, `deleteItem(id: string): Promise<void>`, `updateItemStatus(id: string, body: UpdateItemStatusRequest): Promise<Item>`をTASK-0005の`apiClient`（`src/api/client.ts`）を用いて実装する。フィルタオブジェクトはURLSearchParamsに変換し未定義フィールドは送信しない。

**実装ファイル**: `frontend/src/api/items.ts`

### 2. useItemsQuery / useItemQuery 実装 🔵
**信頼性**: 🔵 *dataflow.md 機能1（全体一覧の閲覧・絞り込み）より*

`useQuery({ queryKey: ['items', filters], queryFn: () => fetchItems(filters) })`の形式で実装する。`useItemQuery`は`queryKey: ['items', 'detail', id]`、`enabled: !!id`とする。

**実装ファイル**: `frontend/src/api/items.ts`

### 3. useDeleteItemMutation / useUpdateItemStatusMutation 実装 🔵
**信頼性**: 🔵 *dataflow.md「データ整合性の保証」キャッシュ無効化方針より*

`useMutation`の`onSuccess`で`queryClient.invalidateQueries({ queryKey: ['items'] })`を呼び出す。`useUpdateItemStatusMutation`は加えて`queryKey: ['items', 'detail', id]`も無効化する。

**実装ファイル**: `frontend/src/api/items.ts`

## 単体テスト要件

### テストケース1: useItemsQueryがフィルタ条件付きでGET /itemsを呼び出す 🔵
**Given** `filters={mediaType:'anime', page:1, limit:20}`
**When** `useItemsQuery(filters)`を実行する
**Then** `GET /items?media_type=anime&page=1&limit=20`相当のリクエストが発行され、`queryKey`が`['items', filters]`である

### テストケース2: フィルタ変更でqueryKeyが変化し再取得される 🔵
**Given** 初回`filters={}`でクエリ実行済み
**When** `filters={isFavorite:true}`に変更して再実行する
**Then** 新しい`queryKey`でクエリが再実行される（キャッシュとは別エントリになる）

### テストケース3: useItemQueryが正常系でアイテム詳細を返す 🔵
**Given** 存在する`id`
**When** `useItemQuery(id)`を実行する
**Then** `GET /items/:id`が呼び出され`data`にItemが返る

### テストケース4: useDeleteItemMutation成功時にinvalidateQueriesが呼ばれる 🔵
**Given** 削除対象の`id`
**When** `mutate(id)`を実行し成功する
**Then** `queryClient.invalidateQueries`が`queryKey:['items']`で呼ばれる

### テストケース5: useUpdateItemStatusMutationがエラー時にApiClientErrorを伝播する 🟡
**Given** 不正な`status`値を送信
**When** `mutate({id, status})`を実行する
**Then** `VALIDATION_ERROR`を持つ`ApiClientError`が`error`に設定される 🟡 *バックエンドエラーコード一覧から妥当な推測*
