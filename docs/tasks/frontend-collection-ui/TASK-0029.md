## タスク概要

`src/api/staff.ts`にスタッフのCRUD用TanStack Queryフック（`useStaffListQuery`, `useCreateStaffMutation`, `useAttachStaffMutation`, `useDetachStaffMutation`等）を実装し、`pages/StaffPage.tsx`でスタッフ（監督・声優・著者など）の追加・役割付与・作品への紐付け・解除を行うUIを実装する（REQ-014）。

## 依存タスク

- **前提タスク**: TASK-0005（apiClient実装）
- **後続タスク**: なし

## 完了条件

- [ ] `useStaffListQuery()`が`GET /staff`相当を呼び出しスタッフ一覧を取得する
- [ ] `useCreateStaffMutation()`が`POST /staff`を呼び出し、成功時にスタッフ一覧クエリを無効化する
- [ ] `useAttachStaffMutation()`が`POST /items/:id/staff`を`role`（`characterName`任意）付きで呼び出し、成功時に対象アイテムの詳細クエリを無効化する
- [ ] `useDetachStaffMutation()`が`DELETE /items/:id/staff/:item_staff_id`を呼び出し、成功時に対象アイテムの詳細クエリを無効化する
- [ ] `StaffPage`でスタッフを新規追加できる
- [ ] `StaffPage`でスタッフに役割（role）を指定してアイテムへ紐付けできる
- [ ] `StaffPage`でアイテムとスタッフの紐付け（ItemStaff）を解除できる

## 実装詳細

### 1. fetch関数・Queryフックの実装 🔵
**信頼性**: 🔵 *architecture.md「リソース別フック」・interfaces.ts Staff/ItemStaffより*

`fetchStaffList(): Promise<Staff[]>`, `createStaff(name: string): Promise<Staff>`, `attachStaff(itemId: string, body: {staffId: string; role: string; characterName?: string}): Promise<ItemStaff>`, `detachStaff(itemId: string, itemStaffId: string): Promise<void>`をTASK-0005の`apiClient`を用いて実装する。`queryKey`は`['staff']`とする。

**実装ファイル**: `frontend/src/api/staff.ts`

### 2. ミューテーション実装とキャッシュ無効化 🔵
**信頼性**: 🔵 *dataflow.md「データ整合性の保証」キャッシュ無効化方針より*

`useCreateStaffMutation`の`onSuccess`で`['staff']`を無効化する。`useAttachStaffMutation`/`useDetachStaffMutation`の`onSuccess`で対象アイテムの詳細クエリ（`['items', 'detail', itemId]`）を無効化する。

**実装ファイル**: `frontend/src/api/staff.ts`

### 3. StaffPageの実装 🔵
**信頼性**: 🔵 *REQ-014・architecture.md 画面構成「/staff」より*

react-hook-form + zodでスタッフ名入力フォームを構築する。スタッフ一覧をリスト表示し、各スタッフから「作品に紐付け」操作で対象アイテム検索・選択UIと役割（role）・キャラクター名（任意）入力フォームを開く。紐付け済み一覧（ItemStaff）には解除ボタンを設置する。

**実装ファイル**: `frontend/src/pages/StaffPage.tsx`

## 単体テスト要件

### テストケース1: useCreateStaffMutationが成功時にスタッフ一覧を無効化する 🔵
**Given** 有効な`name`
**When** `mutate({name})`を実行し成功する
**Then** `queryClient.invalidateQueries`が`queryKey:['staff']`で呼ばれる

### テストケース2: useAttachStaffMutationがroleを含むリクエストを送信する 🔵
**Given** `itemId`・`staffId`・`role='director'`
**When** `mutate({itemId, staffId, role})`を実行する
**Then** `POST /items/:id/staff`に`{staffId, role}`相当のボディが送信される

### テストケース3: useAttachStaffMutation成功時に対象アイテム詳細クエリが無効化される 🔵
**Given** 紐付け対象`itemId`
**When** ミューテーションが成功する
**Then** `queryClient.invalidateQueries`が`queryKey:['items', 'detail', itemId]`で呼ばれる

### テストケース4: useDetachStaffMutationが紐付け解除を実行する 🔵
**Given** 紐付け済みの`itemStaffId`
**When** `mutate({itemId, itemStaffId})`を実行する
**Then** `DELETE /items/:id/staff/:item_staff_id`相当のリクエストが発行される

### テストケース5: StaffPageでスタッフ追加フォーム送信時に名前未入力だと送信できない 🟡
**Given** スタッフ名入力欄が空
**When** 追加ボタンを押そうとする
**Then** 送信ボタンが無効化されている、またはバリデーションエラーが表示される 🟡 *タグ/カテゴリのEDGE-102パターンを類推適用*
