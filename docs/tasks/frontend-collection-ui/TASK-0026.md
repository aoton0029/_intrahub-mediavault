## 実装内容

### 1. ItemFormPage（mode=create/edit） 🔵

**信頼性**: 🔵 *architecture.md 画面構成（`/items/new/:group`, `/items/:id/edit`）・REQ-006/007より*

`src/pages/ItemFormPage.tsx` を実装する。

- propsまたはルートパラメータで`mode: 'create' | 'edit'`を判定（`/items/new/:group`はcreate、`/items/:id/edit`はedit、architecture.md画面構成表より）
- `mode==='edit'`の場合、`useItemQuery(id)`相当の既存取得フックでアイテムを取得し、react-hook-formの`defaultValues`に反映
- `media_type`の選択（create時のみ選択可能、edit時は変更不可 🟡 media_type変更時の整合性問題を避けるための妥当な推測、要件に明記なし）に応じて、TASK-0023（一般メディア6種）/TASK-0024（学術書・専門書）/TASK-0025（論文・文献）のフォーム部品を動的に切り替え表示する
  - `anime`/`movie`/`drama`/`manga`/`novel`/`game` → TASK-0023の対応フォーム部品
  - `academic_book` → TASK-0024の`AcademicBookDetailsFields`
  - `paper` → TASK-0025の`PaperDetailsFields`
- `source`に応じたexternal_id表示制御
  - `source==='api'`の場合、`external_id`を表示専用（編集不可、読み取り専用inputまたはテキスト表示）とする（REQ-201）
  - `source==='manual'`の場合、`external_id`関連の表示を一切行わない（REQ-202）

### 2. ミューテーションフック実装 🔵

**信頼性**: 🔵 *dataflow.md機能3「手動追加・編集」・architecture.md API層設計より*

`src/api/items.ts` を拡張し、以下のTanStack Queryミューテーションフックを実装する。

- `useCreateItemMutation()`: `POST /items`を呼び出す。成功時は`['items', ...]`クエリを`invalidateQueries`で無効化し、作成済みアイテムの詳細画面へ遷移（dataflow.md機能3より）
- `useUpdateItemMutation(id)`: `PATCH /items/:id`を呼び出す。成功時は同様にキャッシュ無効化の上、詳細画面へ遷移

### 3. エラーハンドリング 🟡

**信頼性**: 🟡 *dataflow.md「エラーハンドリングフロー」・REQ-007・NFR-201より*

- `VALIDATION_ERROR`（400）受信時: レスポンスのフィールド単位エラー情報を`setError`（react-hook-form）でフィールド近傍に反映し、加えてsonner toastで全体エラーを通知（dataflow.md機能3・エラーハンドリングフロー図より）
- `ITEM_NOT_FOUND`（404、edit時のみ想定）受信時: 一覧画面へリダイレクトし、エラートーストを表示（dataflow.mdエラーハンドリングフローより）

## UI/UX要件 🟡

**信頼性**: 🟡 *NFR-201/202・dataflow.md状態管理フローより*

- ローディング状態: ミューテーション実行中（`isPending`）は保存ボタンを無効化し、ローディングインジケータ（スピナー等）を表示する
- フィールド近傍エラー表示: react-hook-formの`formState.errors`をshadcn/uiの`FormMessage`で各フィールド直下に表示する（NFR-201）
- モバイル対応: フォームレイアウトはモバイル幅では縦1カラム、デスクトップ幅では2カラム等のレスポンシブ対応とする（🟡 一般的なレスポンシブパターンから推測、要件に具体的ブレークポイント記載なし）
- アクセシビリティ: 全入力項目に`<label>`（shadcn/ui `FormLabel`の`htmlFor`紐付け）を付与し、キーボード操作（Tab順序）・コントラスト比をWCAG 2.1 AA相当で確保する（NFR-202）

## 単体テスト要件 🔵

**信頼性**: 🔵 *REQ-006/007・REQ-201/202・NFR-201より*

- `mode==='create'`時にフォームが空の初期値で表示されること
- `mode==='edit'`時に既存アイテムのデータがフォームに反映されること
- `media_type`に応じて正しいフォーム部品（TASK-0023/0024/0025のいずれか）が表示切り替えされること
- `source==='api'`の場合、`external_id`が表示専用（編集不可）として描画されること（REQ-201）
- `source==='manual'`の場合、`external_id`関連のUI要素が一切表示されないこと（REQ-202）
- バリデーションエラー時にフィールド近傍にエラーメッセージが表示されること
- `VALIDATION_ERROR`（400）受信時にフィールドエラーが反映されること
- `ITEM_NOT_FOUND`（404）受信時に一覧画面へのリダイレクトが行われること

## 統合テスト要件 🔵

**信頼性**: 🔵 *dataflow.md機能3シーケンス図より*

- フォーム入力（必須項目入力）→保存ボタン押下→`useCreateItemMutation`実行→成功時に詳細画面へ遷移するフロー全体が正しく動作すること
