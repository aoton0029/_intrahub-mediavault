## 実装内容

### 1. PaperDetailsフォーム部品 🔵

**信頼性**: 🔵 *interfaces.ts PaperDetails（112-119行目）・REQ-020より*

`src/features/item-form/components/PaperDetailsFields.tsx` を実装する。`PaperDetails`型に対応するzodスキーマ（TASK-0022の`details`部分を`.extend()`して構成）に基づき、以下の項目の入力UIを提供する。

- DOI（`doi`、任意、`10.xxxx/...`形式の入力検証 🟡 厳密なDOI構文検証は要件に明記なし、`10.`始まりのパターンチェック程度の妥当な推測）
- 掲載誌（`journalName`、任意、文字列入力）
- 巻号（`volumeIssue`、任意、文字列入力）
- ページ範囲（`pageRange`、任意、文字列入力、例: `123-145`形式 🟡 形式の厳密検証は要件に明記なし）
- 著者リスト（`authorList`、文字列配列、タグ追加形式のUIコンポーネント 🟡 TASK-0023のgenreList入力UIと同様のパターンを再利用する想定）
- NDL ID（`ndlId`、`source==='api'`時のみ表示専用 🟡 ItemBase.externalIdと同様の推測）

REQ-104（論文/文献グループはDOI等専用フォーム項目を表示しなければならない）に対応し、本フォーム部品はTASK-0026にて`media_type==='paper'`の場合にのみ表示切り替えされることを前提とする。

## 単体テスト要件 🔵

**信頼性**: 🔵 *REQ-020・REQ-104・NFR-201より*

- DOI・掲載誌・巻号・ページ範囲・著者リストの各フィールドが表示されること
- DOIに`10.`で始まらない不正な形式を入力した場合にバリデーションエラーとなること
- DOIを空のまま送信してもバリデーションエラーにならないこと（任意項目）
- 著者リスト（`authorList`）の追加・削除が正しく動作すること
- `ndlId`について、`source==='api'`の場合は編集不可（表示専用）として描画されること
- 正しい形式のDOI（例: `10.1234/example.doi`）を入力した場合にバリデーションが成功すること
