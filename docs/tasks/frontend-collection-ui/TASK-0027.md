## タスク概要

`src/api/tags.ts`にタグ・カテゴリのCRUD用TanStack Queryフック（`useTagsQuery`, `useCategoriesQuery`, `useCreateTagMutation`, `useCreateCategoryMutation`, `useAttachTagMutation`, `useDetachTagMutation`等）を実装し、`pages/TagsCategoriesPage.tsx`でタグ・カテゴリの作成・一覧・アイテムへの付与・削除を行うUIを実装する（REQ-008）。名称未入力時は作成ボタンを無効化、またはAPIからの`VALIDATION_ERROR`をフィールド近傍にエラー表示する（EDGE-102）。

## 依存タスク

- **前提タスク**: TASK-0005（apiClient実装）
- **後続タスク**: なし

## 完了条件

- [ ] `useTagsQuery()`が`GET /tags`相当を呼び出しタグ一覧を取得する
- [ ] `useCategoriesQuery()`が`GET /categories`相当を呼び出しカテゴリ一覧を取得する
- [ ] `useCreateTagMutation()`が`POST /tags`を呼び出し、成功時にタグ一覧クエリを`invalidateQueries`で無効化する
- [ ] `useCreateCategoryMutation()`が`POST /categories`を呼び出し、成功時にカテゴリ一覧クエリを無効化する
- [ ] `useAttachTagMutation()`が`POST /items/:id/tags/:tag_id`を呼び出す
- [ ] `useDetachTagMutation()`が`DELETE /items/:id/tags/:tag_id`を呼び出す
- [ ] `TagsCategoriesPage`で名称未入力の状態では作成ボタンが無効化される、またはAPIの`VALIDATION_ERROR`がフィールド近傍に表示される（EDGE-102）
- [ ] タグ・カテゴリの作成・削除がUI操作で完結する

## 実装詳細

### 1. fetch関数・Queryフックの実装 🔵
**信頼性**: 🔵 *architecture.md「リソース別フック」・interfaces.ts Tag/Categoryより*

`fetchTags(): Promise<Tag[]>`, `fetchCategories(): Promise<Category[]>`, `createTag(name: string): Promise<Tag>`, `createCategory(name: string): Promise<Category>`, `attachTag(itemId: string, tagId: string): Promise<void>`, `detachTag(itemId: string, tagId: string): Promise<void>`をTASK-0005の`apiClient`を用いて実装する。`queryKey`は`['tags']`/`['categories']`とする。

**実装ファイル**: `frontend/src/api/tags.ts`

### 2. ミューテーション実装とキャッシュ無効化 🔵
**信頼性**: 🔵 *dataflow.md「データ整合性の保証」キャッシュ無効化方針より*

各作成ミューテーションの`onSuccess`で対応する一覧クエリを`invalidateQueries`する。タグ付与・解除ミューテーションは成功時に対象アイテムの詳細クエリ（`['items', 'detail', itemId]`）も無効化する。

**実装ファイル**: `frontend/src/api/tags.ts`

### 3. TagsCategoriesPageの実装 🔵
**信頼性**: 🔵 *REQ-008・architecture.md 画面構成「/tags-categories」より*

react-hook-form + zodで名称入力フォームを構築し、`name`が空文字の場合はzodスキーマでエラーとし送信ボタンを無効化する（EDGE-102）。タグ・カテゴリの一覧をリスト表示し、各項目に削除ボタンを設置する。サーバー側`VALIDATION_ERROR`応答時はtoast表示と共にフィールド近傍にもエラーメッセージを表示する。

**実装ファイル**: `frontend/src/pages/TagsCategoriesPage.tsx`

## 単体テスト要件

### テストケース1: useCreateTagMutationが成功時にタグ一覧を無効化する 🔵
**Given** 有効な`name`
**When** `mutate({name})`を実行し成功する
**Then** `queryClient.invalidateQueries`が`queryKey:['tags']`で呼ばれる

### テストケース2: useCreateCategoryMutationが成功時にカテゴリ一覧を無効化する 🔵
**Given** 有効な`name`
**When** `mutate({name})`を実行し成功する
**Then** `queryClient.invalidateQueries`が`queryKey:['categories']`で呼ばれる

### テストケース3: 名称未入力時に作成ボタンが無効化される 🟡
**Given** `TagsCategoriesPage`のタグ作成フォームで`name`が空
**When** フォームの状態を確認する
**Then** 作成ボタンが`disabled`になっている 🟡 *EDGE-102のUI実現方式は複数案あるうちの一案のため推測*

### テストケース4: サーバー側VALIDATION_ERROR時にフィールド近傍にエラー表示される 🔵
**Given** クライアント側検証を回避した不正な`name`でサブミット
**When** APIが`VALIDATION_ERROR`を返す
**Then** 入力欄近傍にエラーメッセージが表示される（EDGE-102）

### テストケース5: タグ削除（解除）操作でuseDetachTagMutationが呼ばれる 🔵
**Given** アイテムに付与済みのタグ
**When** 削除ボタンを押す
**Then** `DELETE /items/:id/tags/:tag_id`相当のミューテーションが実行される
