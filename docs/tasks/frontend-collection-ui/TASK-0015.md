## タスク概要
`src/api/search.ts`に、外部API検索（`useExternalSearchQuery`, `GET /items/search`, REQ-005）とインポート（`useImportItemMutation`, `POST /items/import`）を行うTanStack Queryフックを実装する。`ApiClientError`の`code`プロパティから`API_KEY_NOT_CONFIGURED`（422）・`EXTERNAL_API_TIMEOUT`（502）のエラーコードを判定できるようにし、呼び出し元（SearchAddPage, TASK-0016）がエラー種別ごとに異なるUI分岐を行えるようにする。

## 依存タスク
- **前提タスク**: TASK-0005（apiClient実装）
- **後続タスク**: TASK-0016（SearchAddPage）

## 完了条件
- [ ] `useExternalSearchQuery(query: ExternalSearchQuery)`が`GET /items/search?media_type=...&q=...`を呼び出し、`ExternalSearchResultItem[]`を返す
- [ ] 検索クエリの`q`が空文字の場合はクエリを実行しない（`enabled: !!query.q`）
- [ ] `useImportItemMutation()`が`POST /items/import`に`ImportItemRequest`を送信し、成功時に作成済み`Item`を返す
- [ ] インポート成功時、`['items']`配下の一覧クエリを`invalidateQueries`で無効化する
- [ ] `API_KEY_NOT_CONFIGURED`（422）エラー時、`error.code === 'API_KEY_NOT_CONFIGURED'`で判定可能である
- [ ] `EXTERNAL_API_TIMEOUT`（502）エラー時、`error.code === 'EXTERNAL_API_TIMEOUT'`で判定可能である

## 実装詳細

### 1. fetch関数の実装 🔵
**信頼性**: 🔵 *interfaces.ts ExternalSearchQuery/ExternalSearchResultItem/ImportItemRequestより*

`searchExternalItems(query: ExternalSearchQuery): Promise<ExternalSearchResultItem[]>`, `importItem(body: ImportItemRequest): Promise<Item>`をTASK-0005の`apiClient`を用いて実装する。`apiClient`がHTTPエラー応答を検知した場合は`ApiClientError(code, message)`をthrowする前提（architecture.md API層設計）に依拠する。

**実装ファイル**: `frontend/src/api/search.ts`

### 2. useExternalSearchQuery実装 🔵
**信頼性**: 🔵 *dataflow.md 機能2（外部API検索からの追加）シーケンス図より*

`useQuery({ queryKey: ['search', query], queryFn: () => searchExternalItems(query), enabled: !!query.q })`の形式で実装する。`q`未入力時は不要なリクエストを発生させない。

**実装ファイル**: `frontend/src/api/search.ts`

### 3. useImportItemMutation実装とエラーコード判定 🔵
**信頼性**: 🔵 *dataflow.md 機能2「alt API_KEY_NOT_CONFIGURED / EXTERNAL_API_TIMEOUT / 成功」分岐より*

`useMutation`で`importItem`を呼び出し、`onSuccess`で`queryClient.invalidateQueries({queryKey:['items']})`を実行する。エラー判定自体はミューテーション内部では行わず、呼び出し元（SearchAddPage）が`mutation.error instanceof ApiClientError`かつ`mutation.error.code`を見て分岐できるよう、`error`オブジェクトをそのまま返却する。検索側`useExternalSearchQuery`も同様に`error.code`を呼び出し元へ透過する。

**実装ファイル**: `frontend/src/api/search.ts`

## 単体テスト要件

### テストケース1: 検索成功で結果一覧が返る 🔵
**Given** `query={mediaType:'anime', q:'進撃'}`
**When** `useExternalSearchQuery(query)`を実行する
**Then** `GET /items/search?media_type=anime&q=進撃`が呼び出され`ExternalSearchResultItem[]`が返る

### テストケース2: qが空文字の場合クエリが実行されない 🔵
**Given** `query={mediaType:'anime', q:''}`
**When** `useExternalSearchQuery(query)`をマウントする
**Then** `GET /items/search`が呼び出されない（`enabled:false`）

### テストケース3: API_KEY_NOT_CONFIGUREDエラーが判定可能 🔵
**Given** バックエンドが422 `API_KEY_NOT_CONFIGURED`を返す
**When** `useExternalSearchQuery`を実行する
**Then** `error`が`ApiClientError`であり`error.code === 'API_KEY_NOT_CONFIGURED'`である

### テストケース4: EXTERNAL_API_TIMEOUTエラーが判定可能 🔵
**Given** バックエンドが502 `EXTERNAL_API_TIMEOUT`を返す
**When** `useExternalSearchQuery`を実行する
**Then** `error.code === 'EXTERNAL_API_TIMEOUT'`である

### テストケース5: インポート成功時に一覧キャッシュが無効化される 🔵
**Given** `ImportItemRequest`が有効
**When** `useImportItemMutation().mutate(request)`が成功する
**Then** `queryClient.invalidateQueries`が`queryKey:['items']`で呼ばれ、作成済み`Item`が返る
