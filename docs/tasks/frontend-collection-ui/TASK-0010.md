## 実装詳細

### 1. FilterBarコンポーネント構造 🔵
**信頼性**: 🔵 *architecture.md コンポーネント粒度（common/FilterBar）より*

`media_type`（Select）、タグ（複数選択 or Select、設計はシンプルな単一タグ選択から開始）、カテゴリ（Select）、お気に入り（Switch/Checkbox）、status（Select: not_started/in_progress/completed）の5つのフィルタUIをshadcn/uiコンポーネントで構成する。props経由で`filters: ItemListFilters`, `onChange`相当のハンドラ, `tagOptions`, `categoryOptions`, `mediaTypeOptions?`を受け取る。

**実装ファイル**: `frontend/src/components/common/FilterBar.tsx`

### 2. useSearchParamsFilterとの連携 🔵
**信頼性**: 🔵 *dataflow.md 機能1「フィルタUI変更時はsetSearchParamsでURLを更新」より*

FilterBar内部で`useSearchParamsFilter`を直接呼ぶか、呼び出し元（HomePage等）が`useSearchParamsFilter`を保持しFilterBarへ`filters`と`setFilters`をpropsで渡す設計のいずれかを取る。本設計では再利用性を優先し、**呼び出し元がフックを保持しFilterBarはcontrolledコンポーネントとする**方式を採用する。

**実装ファイル**: `frontend/src/components/common/FilterBar.tsx`

### 3. クリアボタンの実装 🟡
**信頼性**: 🟡 *要件に明記なし、一般的な一覧フィルタUIパターンから妥当な推測*

「フィルタをクリア」ボタンをFilterBar内に設置し、押下時は`onChange`に空の`ItemListFilters`相当（`page`は維持）を渡す。

**実装ファイル**: `frontend/src/components/common/FilterBar.tsx`

## 単体テスト要件

### テストケース1: media_type変更でonChangeが正しい値で呼ばれる 🔵
**Given** FilterBarが`filters={}`でレンダリングされている
**When** media_typeセレクトで`anime`を選択する
**Then** `onChange`が`{...filters, mediaType:'anime'}`相当の値で呼ばれる

### テストケース2: お気に入りトグル操作でonChangeが呼ばれる 🔵
**Given** お気に入りスイッチが未選択状態
**When** スイッチをONにする
**Then** `onChange`が`{...filters, isFavorite:true}`で呼ばれる

### テストケース3: statusセレクト操作でonChangeが呼ばれる 🔵
**Given** statusセレクトが未選択
**When** `in_progress`を選択する
**Then** `onChange`が`{...filters, status:'in_progress'}`で呼ばれる

### テストケース4: クリアボタンで全フィルタがリセットされる 🟡
**Given** 複数フィルタが設定された状態
**When** 「クリア」ボタンを押下する
**Then** `onChange`が空フィルタ相当の値で呼ばれる 🟡 *クリアボタンの仕様自体が推測のため*

### テストケース5: mediaTypeOptionsで選択肢が制限される 🔵
**Given** `mediaTypeOptions=['academic_book']`が渡されている
**When** FilterBarをレンダリングする
**Then** media_typeセレクトの選択肢が`academic_book`のみになる

## UI/UX要件
- **ローディング状態**: タグ・カテゴリ選択肢は呼び出し元から渡されるため、取得中は呼び出し元が`disabled`状態のセレクトを表示するようpropsで制御可能にする
- **エラー表示**: 該当なし（FilterBar自体はAPI呼び出しを行わないため）
- **モバイル対応**: フィルタ項目を横並び（デスクトップ）から縦積み・折りたたみ（モバイル）に切り替えるレスポンシブレイアウトをTailwindのブレークポイントで実装する 🟡 *NFR-202 WCAG準拠から一般的なレスポンシブ対応を推測*
- **アクセシビリティ**: 各フィルタ項目に`label`を関連付け、キーボード操作（Tab/Enter/矢印キー）でセレクト・スイッチを操作可能にする（NFR-202）
