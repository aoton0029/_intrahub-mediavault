## タスク概要

`src/api/settings.ts`に外部APIキー登録・更新用TanStack Queryフック（`useApiCredentialsQuery`, `useUpsertApiCredentialMutation`）を実装し、`pages/SettingsPage.tsx`にタブ構成（APIキー/インポート/エクスポート）の枠組みとAPIキータブを実装する（REQ-021）。対象プロバイダはtmdb/igdb/ndl/steam/openlibrary/anilistの6種。登録後の一覧表示では`ApiCredential.apiKeyMasked`を用いて末尾数文字以外をマスク表示する（NFR-101）。

## 依存タスク

- **前提タスク**: TASK-0005（apiClient実装）
- **後続タスク**: TASK-0031（インポート機能）, TASK-0032（エクスポート未実装ボタン）

## 完了条件

- [ ] `useApiCredentialsQuery()`が登録済みAPIキー一覧（プロバイダ別マスク済み）を取得する
- [ ] `useUpsertApiCredentialMutation()`が`PUT /settings/api-keys/:provider`に`UpsertApiCredentialRequest`（平文`apiKey`）を送信し、成功時にAPIキー一覧クエリを無効化する
- [ ] `SettingsPage`にAPIキー/インポート/エクスポートのタブ構成（shadcn/ui Tabs）が実装されている
- [ ] APIキータブでtmdb/igdb/ndl/steam/openlibrary/anilistそれぞれのキー入力・保存ができる
- [ ] 入力中は平文表示、保存後の一覧表示では`apiKeyMasked`によりマスク表示される（NFR-101）
- [ ] APIキーがソースコードに直接記述されず、すべて`PUT /settings/api-keys/:provider`経由で送信される（REQ-403）

## 実装詳細

### 1. fetch関数・Queryフックの実装 🔵
**信頼性**: 🔵 *architecture.md「リソース別フック」・interfaces.ts ApiCredential/UpsertApiCredentialRequestより*

`fetchApiCredentials(): Promise<ApiCredential[]>`, `upsertApiCredential(provider: ApiProvider, body: UpsertApiCredentialRequest): Promise<ApiCredential>`をTASK-0005の`apiClient`を用いて実装する。`queryKey`は`['settings', 'api-credentials']`とする。

**実装ファイル**: `frontend/src/api/settings.ts`

### 2. useUpsertApiCredentialMutation実装とキャッシュ無効化 🔵
**信頼性**: 🔵 *dataflow.md「データ整合性の保証」キャッシュ無効化方針より*

`onSuccess`で`queryClient.invalidateQueries({queryKey: ['settings', 'api-credentials']})`を呼び出し、保存直後に最新のマスク済み値で一覧を再取得する。

**実装ファイル**: `frontend/src/api/settings.ts`

### 3. SettingsPageのタブ構成実装 🔵
**信頼性**: 🔵 *REQ-021/022/023・architecture.md 画面構成「/settings」より*

shadcn/uiの`Tabs`コンポーネントでAPIキー/インポート/エクスポートの3タブを構成する。本タスクではタブの枠組みとAPIキータブの内容を実装し、インポート・エクスポートタブはTASK-0031/0032で実装するプレースホルダとする。

**実装ファイル**: `frontend/src/pages/SettingsPage.tsx`

### 4. APIキー入力フォームとマスク表示の実装 🔵
**信頼性**: 🔵 *NFR-101・REQ-403・interfaces.ts ApiCredential.apiKeyMaskedより*

各プロバイダごとにreact-hook-form + zodの入力フィールドを用意する。未保存・入力中は平文の`<input type="text">`相当で表示し、保存済みキーは`apiKeyMasked`の値（末尾数文字以外マスク）で表示する。保存ボタン押下時のみ`useUpsertApiCredentialMutation`を呼び出し、平文値をリクエストボディとして送信後はフォーム内の平文値をクリアし一覧の`apiKeyMasked`表示に切り替える。

**実装ファイル**: `frontend/src/pages/SettingsPage.tsx`（または`features/settings/ApiKeysTab.tsx`）

## 単体テスト要件

### テストケース1: useUpsertApiCredentialMutationがPUT /settings/api-keys/:providerを呼び出す 🔵
**Given** `provider='tmdb'`、有効な`apiKey`
**When** `mutate({provider, apiKey})`を実行する
**Then** `PUT /settings/api-keys/tmdb`相当のリクエストが`{apiKey}`ボディで発行される

### テストケース2: 保存成功時にAPIキー一覧クエリが無効化される 🔵
**Given** 任意のプロバイダのキー保存
**When** ミューテーションが成功する
**Then** `queryClient.invalidateQueries`が`queryKey:['settings', 'api-credentials']`で呼ばれる

### テストケース3: 保存後の一覧表示でマスク済み文字列が表示される 🔵
**Given** `useApiCredentialsQuery`が`apiKeyMasked='****abcd'`を含むデータを返す
**When** APIキータブを表示する
**Then** 画面上に平文キーではなく`apiKeyMasked`の値が表示される（NFR-101）

### テストケース4: 入力中は平文表示される 🔵
**Given** APIキー入力欄にユーザーが文字を入力している状態
**When** 入力欄を確認する
**Then** マスクされず入力した文字列がそのまま表示される

### テストケース5: 6プロバイダ全てに対し個別の保存操作ができる 🔵
**Given** tmdb/igdb/ndl/steam/openlibrary/anilistそれぞれの入力欄
**When** 各プロバイダで個別に保存操作を行う
**Then** 各プロバイダごとに独立した`PUT /settings/api-keys/:provider`が発行される

### テストケース6: VALIDATION_ERROR時にフィールド近傍にエラー表示される 🟡
**Given** 空文字のAPIキーで保存を試みる
**When** APIが`VALIDATION_ERROR`を返す
**Then** 当該プロバイダの入力欄近傍にエラーメッセージが表示される 🟡 *NFR-201から類推*
