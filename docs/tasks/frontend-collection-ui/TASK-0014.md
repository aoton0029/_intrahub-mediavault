## タスク概要
`pages/PaperListPage.tsx`を実装する。論文/文献（`media_type=paper`）専用の一覧画面を提供し（REQ-004）、ルート`/collections/paper`に対応する。TASK-0011のHomePageで構築した共有一覧ロジックを再利用し、`media_type`を`paper`に固定したFilterBarを表示する。

## 依存タスク
- **前提タスク**: TASK-0011（HomePage、共有ロジックの抽出元）
- **後続タスク**: なし

## 完了条件
- [ ] `/collections/paper`ルートでアクセス可能
- [ ] 一覧取得は`media_type=paper`が常に固定で適用される（ユーザーがmedia_typeを変更できない、もしくは変更不可なUIとする）
- [ ] FilterBar・カードグリッド・EmptyState・ページングはHomePageと同等の挙動を持つ（共有ロジック経由）
- [ ] タグ・カテゴリ・お気に入り・statusの絞り込みは通常通り操作可能（media_typeのみ固定）

## 実装詳細

### 1. media_type固定フィルタの適用 🔵
**信頼性**: 🔵 *REQ-004「論文/文献...専用に一覧画面を提供」より*

共有一覧ロジック（`ItemListView`/`useItemListPage`）に対し、初期フィルタとして`mediaType: 'paper'`を固定で渡す。FilterBarには`media_type`セレクト自体を非表示にするか、選択不可（`paper`のみ表示しdisabled）にする設計とする。

**実装ファイル**: `frontend/src/pages/PaperListPage.tsx`

### 2. ルーティング設定 🔵
**信頼性**: 🔵 *architecture.md 画面構成とルーティング表より*

`src/routes.tsx`に`/collections/paper` → `PaperListPage`のルートを追加する。

**実装ファイル**: `frontend/src/routes.tsx`, `frontend/src/pages/PaperListPage.tsx`

## 単体テスト要件

### テストケース1: media_type=paperが固定で適用される 🔵
**Given** PaperListPageをレンダリングする
**When** `useItemsQuery`の呼び出し引数を確認する
**Then** `filters.mediaType === 'paper'`である

### テストケース2: media_typeセレクトが表示されないか変更不可である 🟡
**Given** PaperListPageが表示されている
**When** FilterBarを確認する
**Then** media_typeセレクトが非表示またはdisabledになっている 🟡 *UI表現方法は要件に明記なく妥当な推測*

### テストケース3: status絞り込みは通常通り操作可能 🔵
**Given** PaperListPageが表示されている
**When** statusフィルタで`completed`を選択する
**Then** `filters`が`{mediaType:'paper', status:'completed'}`相当になり一覧が再取得される
