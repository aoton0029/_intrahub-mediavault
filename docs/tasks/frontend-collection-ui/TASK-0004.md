## タスク概要

`docs/design/frontend-collection-ui/interfaces.ts`の内容を`frontend/src/types/`に配置し、TypeScriptビルドが通ることを確認する。型定義は`MediaType`, `Item`（判別共用体）, 各メディア別Details型, `ItemGroup`/`ItemEpisode`, `ItemRelation`/`ItemLink`/`ItemFile`/`ItemTrailer`, `Staff`/`ItemStaff`, `Tag`/`Category`/`MyList`, `ApiCredential`, `ItemListFilters`, 各種Request/Response DTO, `ApiOkResponse`/`ApiErrorResponse`/`ApiResponse`/`ApiClientError`を含む。

- **前提タスク**: [TASK-0001](TASK-0001.md)
- **後続タスク**: api/フック実装タスク全般（TASK-0005含む、Phase 2以降の全機能実装タスク）

## 完了条件

- [ ] `frontend/src/types/`に`interfaces.ts`相当の型定義ファイルが配置されている（単一ファイルまたはドメイン別に分割）
- [ ] `MediaType`, `Item`, `ItemBase`派生の判別共用体, 各`*Details`型がエクスポートされている

## 実装詳細

### 型定義ファイルの配置方針 🟡
**信頼性**: 🟡 *architecture.md「ディレクトリ構造」で`types/`配下に`interfaces.ts`（本設計のentity/DTO型）を配置する方針は🔵明記されているが、単一ファイルかドメイン別分割かは設計文書に明記がないため推測*

architecture.mdは「`types/` # interfaces.ts（本設計のentity/DTO型）」と明記しているため、まずは`frontend/src/types/index.ts`（または`interfaces.ts`のファイル名をそのまま維持）として単一ファイル配置を基本方針とする。ファイル量が増えた場合のドメイン別分割（`item.ts`, `api.ts`等）はPhase 2以降の必要に応じた判断とする（🟡）。

### 配置内容 🔵
**信頼性**: 🔵 *interfaces.tsの内容そのまま転記*

- 列挙型: `MediaType`, `GeneralMediaType`, `ItemStatus`, `ItemSource`, `GroupType`, `RelationType`, `FileType`, `ApiProvider`
- メディア別詳細: `AnimeDetails`, `MovieDetails`, `DramaDetails`, `MangaDetails`, `NovelDetails`, `GameDetails`, `AcademicBookDetails`, `PaperDetails`
- `Item`判別共用体, `isItemOfType`型ガード
- `ItemGroup`, `ItemEpisode`, `ItemRelation`, `ItemLink`, `ItemFile`, `ItemTrailer`
- `Staff`, `ItemStaff`, `Tag`, `Category`, `MyList`, `ApiCredential`
- `ItemListFilters`
- DTO: `CreateItemRequest`, `UpdateItemRequest`, `UpdateItemStatusRequest`, `ExternalSearchQuery`, `ExternalSearchResultItem`, `ImportItemRequest`, `CreateGroupRequest`, `CreateEpisodeRequest`, `UploadItemFileRequest`, `ImportSummary`, `ImportFailure`, `UpsertApiCredentialRequest`
- 統一APIレスポンス: `ApiOkResponse<T>`, `ApiErrorResponse`, `ApiResponse<T>`, `Pagination`, `ApiClientError`

### tsconfig.jsonパスエイリアス確認 🟡
**信頼性**: 🟡 *設計文書に明記なし、一般的なVite+TSプロジェクト構成から妥当な推測*

`@/types`のようなパスエイリアスを使う場合は`tsconfig.json`の`compilerOptions.paths`とVite側の`resolve.alias`を整合させる（shadcn/ui初期化時に`@/*`エイリアスが既に設定される場合が多いため、TASK-0001のshadcn/ui初期化結果を確認する）。
