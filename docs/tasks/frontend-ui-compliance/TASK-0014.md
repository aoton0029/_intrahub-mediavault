`frontend/src/pages/SettingsPage.tsx`を左タブ＋右パネルのレイアウト（`.settings-shell`/`.settings-tabs`/`.settings-tab`/`.settings-panel`）に更新し、APIキー管理／インポート／エクスポートの各パネルに対応させる。APIキー管理は`.kv-card`表示（provider名＋キー表示）に対応させる（REQ-010）。既存`SettingsPage.test.tsx`が壊れないことを確認する。

## 実装詳細

### タブ+パネルレイアウト 🔵
**信頼性**: 🔵 *requirements.md REQ-010「設定画面を左タブ+右パネルのレイアウトに更新する」・05_settings.htmlの`.settings-shell`/`.settings-tabs`/`.settings-panel`構造より*

```tsx
<div className="settings-shell">
  <nav className="settings-tabs">
    {tabs.map((tab) => (
      <button
        key={tab.id}
        className={`settings-tab${activeTab === tab.id ? ' active' : ''}`}
        onClick={() => setActiveTab(tab.id)}
      >
        {tab.label}
      </button>
    ))}
  </nav>
  <section className="settings-panel">
    {activeTab === 'api-keys' && <ApiKeysPanel />}
    {activeTab === 'import' && <ImportPanel />}
    {activeTab === 'export' && <ExportPanel />}
  </section>
</div>
```

既存`SettingsPage.tsx`のタブ構成（APIキー管理／インポート／エクスポート以外に既存タブがある場合はそれも含む）は変更せず、視覚のみ`.settings-tabs`/`.settings-tab`/`.settings-panel`構造に置き換える 🟡（既存タブの正確な項目数・名称は既存実装に依存するため、既存コードのタブ一覧をそのまま踏襲する前提の推測）。

### APIキー管理パネルの`.kv-card`表示 🔵
**信頼性**: 🔵 *requirements.md REQ-010「APIキー管理は`.kv-card`表示に対応させる」・_shared.cssの`.kv-card`定義より*

既存のAPIキー一覧（プロバイダ名＋キー値の保存・表示ロジック）を`.kv-card`要素で1件ずつ表示する。

```tsx
<div className="kv-card">
  <span className="key">{apiKey.provider}</span>
  <span className="value">{maskedKey(apiKey.value)}</span>
</div>
```

キーのマスキング表示（例: `sk-****abcd`）は既存実装のセキュリティ方針を踏襲する 🟡（マスキングの具体的な仕様は背景資料に明記がないため、既存のAPIキー表示ロジックをそのまま利用する前提の推測）。

### インポート・エクスポートパネル 🟡
**信頼性**: 🟡 *requirements.md REQ-010でパネルの存在は🔵明記されるが、既存実装のUI詳細（ファイル選択・ボタン配置等）までは資料に明記がないための推測*

既存のインポート・エクスポート機能（ファイル選択・実行ボタン等）を`.settings-panel`内にそのまま配置し、視覚スタイルのみ更新する。機能ロジック自体は変更しない。
