## 実装詳細

### 更新対象と方針（新規ではなく既存更新）🔵
**信頼性**: 🔵 *タスク指示「FilterBarについては『新規』ではなく『既存コンポーネントの更新』であることを明記」・実際のファイル`frontend/src/components/common/FilterBar.tsx`が既存実装として存在することより*

architecture.md「共通コンポーネント層」には`FilterBar` / `Chip`が「`.filter-bar`, `.chip`, `.search-box`相当」の新規コンポーネントと記載されているが、実装時点では既存の`FilterBar.tsx`（`select`要素ベースのメディアタイプ/タグ/カテゴリ/お気に入り/ステータス絞り込み、`FilterBar.test.tsx`・`FilterBar.test.a11y.tsx`のテスト資産あり）が存在する。本タスクは既存コンポーネントの視覚表現をモックアップ準拠に更新するものであり、機能（controlledコンポーネントとしての`filters`/`onChange`契約）は変更しない（REQ-401）。

### 現状実装の要点 🔵
**信頼性**: 🔵 *既存ファイル`frontend/src/components/common/FilterBar.tsx`の内容より*

- `FilterSelectField`ヘルパーによる`label + select`繰り返しパターン（メディアタイプ・タグ・カテゴリ・ステータス）
- お気に入りは`checkbox`
- クリアボタンは素の`<button>`

### スタイル更新方針 🟡
**信頼性**: 🟡 *_shared.css `.filter-bar`/`.chip`/`.search-box`定義とREQ-005「`.chip`によるステータス/タグ絞り込み + 検索ボックス」から妥当な推測。既存の`select`ベースUIを`chip`トグルに変更する具体的なマイグレーション方法は資料に明記がないため推測*

`_shared.css`定義:

```css
.filter-bar { display: flex; align-items: center; gap: 8px; flex-wrap: wrap; margin-bottom: 20px; }
.chip {
  display: inline-flex; align-items: center; gap: 6px;
  padding: 5px 10px; border-radius: 999px;
  border: 1px solid var(--border); background: var(--bg-surface);
  color: var(--text-muted); font-size: 12px; cursor: pointer;
}
.chip:hover { border-color: var(--accent); color: var(--text-primary); }
.chip.active { background: var(--accent-soft); border-color: var(--accent); color: var(--accent-strong); }
.search-box {
  margin-left: auto; display: flex; align-items: center; gap: 6px;
  background: var(--bg-input); border: 1px solid var(--border);
  border-radius: var(--radius); padding: 6px 10px; min-width: 220px;
  color: var(--text-faint); font-size: 13px;
}
```

REQ-005は「`.chip`によるステータス/タグ絞り込み + 検索ボックス」と明記しているため（🔵）、ステータス絞り込み（`select`→`chip`ボタン群へのUI変更）とタグ絞り込みの`chip`化を優先実装する。メディアタイプ・カテゴリの絞り込みUIをどこまで`chip`化するかは資料に明記がないため（🟡）、既存の`select`のまま視覚スタイルのみ更新するか、全て`chip`化するかは実装時に判断する。既存のcontrolled props（`filters: ItemListFilters`, `onChange`）契約は変更しない。

### 検索ボックスの追加 🟡
**信頼性**: 🟡 *REQ-005「検索ボックス」・既存propsに`keyword`相当のフィールドがあるかは未確認のため、`ItemListFilters`型定義を実装時に確認の上追加要否を判断する必要がある推測*

現状の`FilterBarProps`にキーワード検索用のprops（例: `filters.keyword`, `onChange`経由）が存在するか、`src/types`の`ItemListFilters`定義を確認し、必要であれば追加する。既存になければ後方互換を保つ形でoptionalフィールドとして追加する。

### アクセシビリティ 🔵
**信頼性**: 🔵 *タスク指示「chipのactive状態の色分け、検索ボックスのフォーカス状態」・既存の`FilterBar.test.a11y.tsx`資産より*

既存の`FilterBar.test.a11y.tsx`が検証しているラベル紐付け（`htmlFor`/`id`）・キーボード操作性を、`chip`ボタン化後も維持する（`<button role="button">`+`aria-pressed`によるactive状態通知等）。
