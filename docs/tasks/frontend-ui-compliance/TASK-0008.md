## 実装詳細

### 現状実装の要点 🔵
**信頼性**: 🔵 *既存ファイル`frontend/src/components/common/MediaCard.tsx`の内容より*

現状は`<img src={item.coverImageUrl ?? ''}>`によるカバー表示、`MediaTypeBadge`コンポーネントの通常配置（オーバーレイではない）、お気に入り・ステータスは`data-testid`+`data-favorite`/`data-status`属性のみで視覚表現がない。

### 拡張要素1: カバー画像プレースホルダ 🔵
**信頼性**: 🔵 *requirements.md REQ-004・dataflow.md「.cover グラデーション プレースホルダ表示」、_shared.css `.media-card .cover`定義より*

```css
.media-card .cover {
  aspect-ratio: 2/3;
  background: linear-gradient(160deg, #33304a, #232323);
  display: flex; align-items: flex-end; justify-content: flex-end;
  padding: 6px; position: relative;
}
```

`coverImageUrl`が存在する場合は`<img>`を`.cover`コンテナ内に配置し、未設定時はグラデーションのみのプレースホルダとする想定（🟡 モックアップは画像なしの前提で作られているため、実画像がある場合の重ね方は資料に明記がなく妥当な推測）。バッジ・お気に入りアイコンは`.cover`コンテナ内に絶対配置する。

### 拡張要素2: media-typeバッジのオーバーレイ 🟡
**信頼性**: 🟡 *requirements.md REQ-004・_shared.css `.media-card .badge`定義より。既存`MediaTypeBadge.tsx`との統合方法（新規スタイル追加 vs `MediaTypeBadge`側にvariant追加）はタスク指示に「既存`MediaTypeBadge.tsx`との統合検討」とあるのみで具体的な方針は資料に明記がないため推測*

```css
.media-card .badge {
  font-family: var(--font-mono); font-size: 10px; letter-spacing: 0.04em;
  background: rgba(0,0,0,0.55); color: var(--text-muted);
  padding: 2px 6px; border-radius: 4px;
  position: absolute; top: 6px; left: 6px;
}
```

既存の`MediaTypeBadge`コンポーネントに`variant="overlay"`のようなpropsを追加し、MediaCard内でオーバーレイ用クラスを付与する方針、または`MediaCard`側でラッパー`<div className="badge">`に既存`MediaTypeBadge`を内包する方針のいずれかを実装時に選択する。既存の`MediaTypeBadge`のREQ-002（media_type別アクセントカラー8色）との共存を壊さないよう注意する。

### 拡張要素3: ★お気に入りアイコン 🔵
**信頼性**: 🔵 *requirements.md REQ-004受け入れ基準「お気に入り=true のアイテムで★アイコンが表示される」、_shared.css `.media-card .fav`定義より*

```tsx
{item.isFavorite && <span className="fav" data-testid="media-card-favorite">★</span>}
```

`.fav { color: var(--favorite); font-size: 14px; }`。既存の`data-testid="media-card-favorite"`は維持しつつ、`data-favorite`属性ではなく実際の★表示有無で判定できるようにする（既存テストとの互換性は実装時に確認）。

### 拡張要素4: ステータスドット 🔵
**信頼性**: 🔵 *requirements.md REQ-004受け入れ基準「ステータス未設定（none）の場合グレーのステータスドットが表示される」、_shared.css `.status-dot`定義より*

```tsx
<span className={cn('status-dot', statusToClass(item.status))} data-testid="media-card-status" />
```

```css
.status-dot { width: 6px; height: 6px; border-radius: 50%; display: inline-block; }
.status-dot.done { background: var(--status-done); }
.status-dot.progress { background: var(--status-progress); }
.status-dot.none { background: var(--status-none); }
```

`item.status`（`not_started` / `in_progress` / `completed`、既存`ItemStatus`型より）を`none` / `progress` / `done`にマッピングする関数を実装する。`not_started`→`none`、`in_progress`→`progress`、`completed`→`done`という対応は資料に直接の記載はないが、既存`ItemStatus`型定義とモックアップの3値（`none`/`progress`/`done`）から妥当な推測（🟡）。

### hoverアニメーション 🔵
**信頼性**: 🔵 *_shared.css `.media-card:hover { border-color: var(--accent); transform: translateY(-2px); }`、タスク指示より*
