## タスク概要

既存の`frontend/src/pages/RootLayout.tsx`を、現状の`flex`ベース2カラム構成（Sidebar + main）から`_shared.css`の`.app-shell`グリッド構造（`grid-template-columns: var(--sidebar-w) 1fr`）に変更する（REQ-006）。アイテム詳細画面のみ`.app-shell.has-properties`相当（3カラム、`grid-template-columns: var(--sidebar-w) 1fr var(--properties-w)`）を適用し、properties列は空間確保のみ（中身は実装しない、スコープ外）とする。

- **前提タスク**: [TASK-0002](TASK-0002.md)（Tailwind CSS 4連携で`--sidebar-w`, `--properties-w`等のトークンが利用可能であること）
- **後続タスク**: Phase3の全タスク（RootLayout配下でレンダリングされる全画面）、特に[TASK-0011](TASK-0011.md)相当のアイテム詳細画面タスク

## 実装詳細

### 現状実装 🔵
**信頼性**: 🔵 *既存ファイル`frontend/src/pages/RootLayout.tsx`の内容より*

```tsx
export default function RootLayout() {
  return (
    <div className="flex min-h-screen">
      <Sidebar />
      <main className="flex-1">
        <Outlet />
      </main>
    </div>
  );
}
```

現状は`flex`ベースの2カラム構成で、properties列の概念がない。

### app-shellグリッド化 🔵
**信頼性**: 🔵 *requirements.md REQ-006・_shared.css `.app-shell`/`.app-shell.has-properties`定義より*

```css
.app-shell {
  display: grid;
  grid-template-columns: var(--sidebar-w) 1fr;
  height: 100vh;
}
.app-shell.has-properties {
  grid-template-columns: var(--sidebar-w) 1fr var(--properties-w);
}
```

```tsx
export default function RootLayout() {
  const isItemDetail = useIsItemDetailRoute() // ルート判定フック
  return (
    <div className={cn('app-shell', isItemDetail && 'has-properties')}>
      <Sidebar />
      <main className="main">
        <Outlet />
      </main>
      {isItemDetail && <aside className="properties" />}
    </div>
  );
}
```

### ルート判定ロジック 🟡
**信頼性**: 🟡 *dataflow.md「RootLayout / app-shell グリッド化（REQ-006）」フロー図「画面種別を判定」より方針は確実だが、具体的な判定実装（React Routerの`useMatch`/`useLocation`か、ルート設定側でレイアウトを分岐するか）は資料に明記がないため推測*

現在のルートパスがアイテム詳細画面かどうかを`react-router-dom`の`useLocation`または`useMatch`で判定する。アイテム詳細画面のパスパターン（例: `/items/:id`相当、architecture.md「画面別スタイル適用」表の`ItemDetailPage.tsx`に対応するパス）は`frontend-collection-ui`の既存ルーティング設計を参照して確定する必要がある（本要件定義には具体パス文字列の記載がないため実装時に既存`App.tsx`/ルーター設定を確認する）。

```tsx
function useIsItemDetailRoute(): boolean {
  const location = useLocation()
  return /^\/items\/[^/]+/.test(location.pathname) // 実際のルートパスは既存ルーター設定に合わせて確認・調整する
}
```

### properties列は中身を実装しない 🔵
**信頼性**: 🔵 *requirements.md REQ-006受け入れ基準「Propertiesパネルの中身の実装は次回以降」・dataflow.md備考「properties列は`--properties-w: 300px`分のグリッド列を確保するのみ」より*

`<aside className="properties" />`は空のプレースホルダとし、key-value行・タグ一覧等のコンテンツは一切実装しない（スコープ外）。

### 既存Sidebarクラスとの整合 🟡
**信頼性**: 🟡 *_shared.css `.sidebar`, `.main`クラスとの対応関係。TASK-0007（Sidebar拡張）との整合が必要だが、両タスクの実装順序（並行/直列）は資料に明記がないため実装時に調整が必要*

TASK-0007でSidebarに`.sidebar`相当のクラスを付与する前提のため、本タスクの`.app-shell`グリッドとSidebarの`.sidebar`スタイル（`display: flex; flex-direction: column;`）が競合しないことを確認する。
