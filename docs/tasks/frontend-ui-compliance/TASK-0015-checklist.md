### 基準未達の既知課題

- **`--text-faint` (#5c5c5f) を `--bg-app` (#1e1e1e) 上で使用した場合、2.50:1 でWCAG AA基準（4.5:1、大きいテキストでも3:1）を満たさない。**
  - REQ-401（機能不変・視覚表現限定）の方針に従い、本タスクでは色トークン自体の変更は行わない。
  - 実使用箇所を確認したところ、`--text-faint` は主に補助的なプレースホルダ・タイムスタンプ等の非本質的情報に限定使用されている。ただし本文情報として使われる箇所があれば個別に `--text-muted` への置き換えを検討する必要があり、既知の課題として残す（フォローアップはTASK-0016またはIssue化）。
- **`--status-none` (#6b6b6e) は3.14:1とAA非テキストUI基準(3:1)をわずかに上回るのみ。** 将来的な微調整の余地ありとして記録。

## 2. 色以外の識別手段（WCAG 1.4.1 色のみに依存しない）の確認

- ステータスドット（`--status-progress` / `--status-done` / `--status-none`）は、色だけでなく `title`属性・隣接するステータスラベル文字列（例:「進行中」「完了」「未着手」）によっても状態を識別できることをコードベース上で確認した（`MediaCard` 等のステータス表示箇所）。
- お気に入り★アイコンも塗り潰しの有無（形状変化）で状態を示しており、色のみに依存していない。
- → **色以外の識別手段あり。WCAG 1.4.1準拠。**

## 4. 既存a11yテストの回帰確認

- `yarn test`（`vitest run`、デフォルト設定）を実行し、既存239テスト・26ファイルすべてがパスすることを確認した。
- **⚠️ 既知の課題（テスト構成上の問題）**: `Sidebar.test.a11y.tsx` / `FilterBar.test.a11y.tsx` は、ファイル名が `*.test.a11y.tsx` であるためvitestのデフォルトinclude glob（`**/*.{test,spec}.?(c|m)[jt]s?(x)`、`.test.a11y.tsx` は末尾が `.test.tsx` ではないため対象外）にマッチせず、**`yarn test` では一度も実行されていない**ことが判明した。
  - vitest.config.tsのincludeパターンを一時的に拡張して両ファイルを個別実行したところ、`FilterBar.test.a11y.tsx`（13テスト中含む）は全パス、`Sidebar.test.a11y.tsx` は13テスト中2件失敗（`TC-05-1`, `TC-05-2`: モバイル用ハンバーガーメニューの `aria-label="メニューを開く"` ボタンが見つからない）。
  - この2件の失敗はデザイントークン（色）の変更とは無関係で、モバイル用ハンバーガーメニュー機能（TASK-0034で言及）が現在の`Sidebar`実装に存在しない、または未実装であることに起因すると考えられる。TASK-0001〜0014のトークン置換による回帰ではない。
  - **本タスクのスコープ（トークン置換に伴うa11y回帰確認）に対する結論**: トークン変更が原因の回帰は無い。ただし「テストがそもそも実行されていない」「実行時に無関係の理由で2件失敗する」という2つの問題はプロジェクトの既知の課題として記録し、TASK-0016またはIssueで対応を検討する。
  - vitest.config.tsは検証後、変更を加えずに元の状態に復元済み（本タスクはプロダクションコード変更を行わない方針のため）。
