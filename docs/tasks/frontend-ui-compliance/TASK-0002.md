## 実装詳細

### @theme inlineブロックの参照整合 🔵
**信頼性**: 🔵 *architecture.md「デザイントークン層」（Tailwind CSS 4の`@theme`ディレクティブ経由で置換後のCSS変数をユーティリティクラスにマッピングする）より*

現状の`@theme inline`は以下のように旧トークン名を参照している（実測値）。

```css
@theme inline {
  --color-bg-base: var(--bg-base);
  --color-bg-surface: var(--bg-surface);
  --color-bg-elevated: var(--bg-elevated);
  --color-text-primary: var(--text-primary);
  --color-text-secondary: var(--text-secondary);
  --color-border-default: var(--border-default);
  ...
}
```

TASK-0001で`:root`側の変数名自体を`_shared.css`準拠（`--bg-app`, `--bg-sidebar`, `--bg-surface`, `--text-primary`, `--text-muted`等）に変更した場合、`@theme inline`側の参照先(`var(--bg-base)`等)も追随して修正する必要がある。本タスクでは以下のいずれかの方針で整合させる。

1. `--color-bg-base: var(--bg-app);` のように、Tailwindユーティリティ名は既存のまま維持しつつ参照先変数のみ新トークンに差し替える（既存クラス名`bg-bg-base`等を使用しているコンポーネントへの影響を最小化）
2. 新トークン名に合わせて`--color-bg-app`等の新規ユーティリティ変数を追加する

既存コンポーネントが参照しているクラス名（`bg-bg-base`等）を壊さないため、方針1（参照先のみ差し替え）を優先する 🟡 *資料に既存クラス名の互換性維持方針の明記はないが、REQ-401「機能要件は変更しない」の趣旨、および既存コンポーネントの回帰を避ける観点からの妥当な推測*。

### shadcn oklchトークンの上書き 🔵
**信頼性**: 🔵 *requirements.md REQ-402（shadcn由来のoklch系トークンは`_shared.css`の対応する色に上書きする）より*

`:root`内の以下oklchトークンを、`_shared.css`の16進値・rgba値で上書きする。

```css
:root {
  /* shadcn oklchトークンの上書き（REQ-402） */
  --background: var(--bg-app);          /* #1e1e1e */
  --foreground: var(--text-primary);    /* #dcddde */
  --card: var(--bg-surface);            /* #262626 */
  --card-foreground: var(--text-primary);
  --popover: var(--bg-surface);
  --popover-foreground: var(--text-primary);
  --primary: var(--accent);             /* #8b6cf6 */
  --primary-foreground: var(--text-primary);
  --secondary: var(--bg-surface-hover); /* #2c2c2c */
  --secondary-foreground: var(--text-primary);
  --muted: var(--bg-surface-hover);
  --muted-foreground: var(--text-muted); /* #8a8a8d */
  --accent: var(--accent-soft);          /* Tailwind慣習のaccent(hover背景)用途、要ヒアリング */
  --accent-foreground: var(--text-primary);
  --destructive: var(--danger);          /* #e0615a */
  --border: var(--border);               /* #383838 */
  --input: var(--bg-input);              /* #1c1c1c */
  --ring: var(--accent-strong);          /* #a48bf8 */
}
```

shadcnの`--accent`（hover背景用途のニュートラルトークン）と`_shared.css`の`--accent`（単一アクセント色トークン）が同名で意味が異なるため、変数名の衝突を避ける調整が必要になる。本タスクでは`_shared.css`側のアクセント色トークンを`--brand-accent`のような別名にリネームして`:root`に保持し、shadcnの`--primary`にはそのエイリアスを充てる方針とする 🟡 *資料に同名変数の衝突回避方針の明記はないため、REQ-402の意図（見た目をモックアップ準拠にする）を損なわない範囲での妥当な設計判断*。

### .darkクラスブロックの整合 🟡
**信頼性**: 🟡 *architecture.md・requirements.mdに`.dark`ブロックの扱いに関する明記はなく、REQ「ライトモード等のテーマ切替はスコープ外」から妥当な推測*

本プロジェクトはダークUI単一構成であり、ライトモード切替は今回のスコープ外（requirements.mdスコープ外セクション）である。既存の`.dark`クラスブロックは`:root`と別の値を保持しているため、以下いずれかの方針を採用しコメントで明記する。

- 方針A: `.dark`ブロックの値を`:root`と同一値に揃え、`.dark`クラスが付与されるか否かに関わらず同一の見た目になるようにする
- 方針B: `:root`自体をダークテーマとして扱い、`.dark`クラス自体を将来のライトモード対応まで使用しない（コメントで明記）

本タスクでは方針B（`:root`をダークテーマの正とし、`.dark`ブロックは将来のテーマ切替実装まで凍結する）を採用し、`index.css`内にその方針をコメントとして残す 🟡。

### media_type別アクセントカラーへの影響回避 🔵
**信頼性**: 🔵 *requirements.md REQ-002・受け入れ基準（media_type別アクセントカラーが引き続き正しく表示される）より*

`@theme inline`内の`--color-accent-anime`等8色のマッピングは本タスクで変更しない。shadcnの`--accent`系トークンとの名前空間分離（`--accent-anime`等はmedia_type専用プレフィックス、shadcnの単一`--accent`とは別トークン）を維持していることを確認する。
