## 実装詳細

### 2カラムグリッドレイアウト 🔵
**信頼性**: 🔵 *requirements.md REQ-009「手動追加・編集フォームを2カラムグリッド（`.form-grid`）…に対応させる」・04_item_form.htmlの`.form-grid`/`.form-field`構造より*

既存フォームの各入力フィールドを`.form-field`単位でラップし、`.form-grid`（2カラムCSS Grid）内に配置する。既存のフィールド一覧（タイトル・原題・概要・タグ等、`ItemFormPage.tsx`の既存フォーム項目）はそのまま維持し、配置のみ変更する。

```tsx
<form className="form-grid">
  <div className="form-field">
    <label>タイトル<span className="required">*</span></label>
    <input ... />
    {errors.title && <p className="field-error">{errors.title}</p>}
    <p className="field-hint">作品の正式名称を入力してください</p>
  </div>
  {/* 他フィールドも同様 */}
  <div className="form-actions">
    <Button variant="ghost" onClick={handleCancel}>キャンセル</Button>
    <Button variant="accent" type="submit">保存</Button>
  </div>
</form>
```

各フィールドのヒント文言は既存実装に明記がある場合はそれを踏襲し、ない場合は簡潔な説明文を補う 🟡（フィールドヒントの具体的な文言は背景資料に明記がないため妥当な推測）。

### 必須マークとエラー表示 🔵
**信頼性**: 🔵 *requirements.md REQ-009「必須マーク、エラー表示…に対応させる」・_shared.cssの`.required`/`.field-error`定義より*

既存のバリデーションロジック（必須チェック等）が返すエラー情報をそのまま`.field-error`要素にマッピングする。バリデーションルール自体（どのフィールドが必須か等）は既存実装を変更しない。

### タグ入力（TagPill利用） 🔵
**信頼性**: 🔵 *タスク指示「タグ入力部分はTASK-0004のTagPillを利用する」より*

既存のタグ入力UI（追加済みタグの表示部分）をTagPillコンポーネント（`.tag-pill`、`#`プレフィックス付き）に置き換える。タグの追加・削除ロジック自体は既存実装のものを流用する。

### フォーム下部操作ボタン群 🔵
**信頼性**: 🔵 *requirements.md REQ-009「下部操作ボタン群」・04_item_form.htmlの`.form-actions`構造より*

`.form-actions`内に「キャンセル」（`.btn`/`.btn-ghost`）と「保存」（`.btn-accent`）ボタンを配置する。既存の送信・キャンセル処理はそのまま呼び出す。

## 単体テスト要件

### バリデーションエラー表示 🔵
**信頼性**: 🔵 *タスク概要「バリデーションエラー時の`.field-error`表示」より*
- 必須フィールド未入力で送信した場合、対応するフィールドに`.field-error`が表示されること
- エラーメッセージの内容が既存のバリデーションロジックが返す文言と一致すること

### 必須マーク表示 🔵
**信頼性**: 🔵 *タスク概要「必須フィールドの`.required`マーク表示」より*
- 必須フィールドのラベル横に`.required`マークが表示されること
- 任意フィールドには`.required`マークが表示されないこと

### 2カラムレイアウト・フォームアクション 🟡
**信頼性**: 🟡 *レイアウト構造テストとして妥当な推測*
- フォームコンテナに`.form-grid`クラスが付与されていること
- `.form-actions`内に保存・キャンセルボタンが表示されること
