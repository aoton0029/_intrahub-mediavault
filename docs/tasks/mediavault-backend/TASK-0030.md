## タスク概要
`POST /import/booklog`（multipart/form-data、CSVファイル）を実装する。ブクログのエクスポートCSVを行単位で解析し、正常行は`items`テーブルへ登録、形式不正な行はスキップして`ImportFailure(row_number, reason)`に記録する。レスポンスは`ImportSummary{success_count, failure_count, failures}`を返す。なお、prep.mdにて「ブクログCSVの実カラム形式は実装着手前に実物サンプルの確認が必要」と明記されているため、本タスクでは下記の仮カラムフォーマットを定義して実装し、実サンプル入手後にパーサ部分のみを調整できる構成（カラムマッピングの分離）とする。

## 依存タスク

- **後続タスク**: なし（Phase5最終タスク群の一つ）

## 完了条件
- [ ] `POST /import/booklog`がmultipart/form-dataでCSVファイルを受け取れる
- [ ] CSVを1行ずつ解析し、仮定義したカラムマッピングに従って`CreateItemRequest`相当のデータへ変換する
- [ ] 正常に変換できた行はTASK-0009の登録ロジックを通じて`items`テーブルへ登録される（`source`は`manual`相当の値とする）
- [ ] カラム数不足・必須項目欠落・型変換失敗などの形式不正行はスキップされ、処理が継続する（EDGE-002）
- [ ] スキップされた行について`row_number`（1始まり、ヘッダー行を除く）と`reason`（不正理由の文字列）が`ImportFailure`として記録される
- [ ] レスポンスとして`ImportSummary{success_count, failure_count, failures: ImportFailure[]}`が返る（TC-016-01）
- [ ] 全行が不正な場合でも`200`で`ImportSummary`が返り、例外で落ちない（TC-016-E01）
- [ ] カラムマッピング定義が実装の他部分から分離されており、実サンプル確認後の調整が容易な構造になっている

## 実装詳細
### 1. multipartアップロードハンドラ 🔵
**信頼性**: 🔵 *api-endpoints.md「POST /import/booklog」（multipart）より*

Axumの`Multipart`エクストラクタを用いてCSVファイルのバイト列を受け取る。ファイルが存在しない・空の場合は`400 Bad Request`（`VALIDATION_ERROR`相当）を返す。文字コードはUTF-8を前提とするが、ブクログCSVがShift_JIS等の可能性もあるため、デコード失敗時は`encoding_rs`等によるフォールバック変換を検討する余地を残す。

**実装ファイル**: `mediavault-api/src/handlers/import_booklog.rs`

### 2. 仮カラムフォーマット定義 🟡
**信頼性**: 🟡 *prep.md「ブクログCSVのサンプルファイル準備」より実物未確認のため仮定義、一般的なブクログエクスポート仕様から妥当な推測*

実物サンプル未確認のため、以下を仮の列定義として実装する（実装後にprep.mdのサンプル入手結果に応じて`BooklogCsvRow`構造体のフィールドマッピングのみ調整する）。

仮定義カラム: `作品名`(title, 必須), `感想/レビュー`(description, optional), `読了日`(consumed_date, optional, `YYYY-MM-DD`形式), `評価`(rating, optional, 数値), `ISBN`(external_idの参考情報、optional)。

**実装ファイル**: `mediavault-api/src/import/booklog_csv.rs`（カラムマッピングを独立モジュールとして分離）

### 3. 行単位パース・スキップロジック 🔵
**信頼性**: 🔵 *EDGE-002「ブクログCSV・Steamライブラリインポートで一部行が形式不正の場合、不正行のみスキップし正常行の取込を継続」より*

`csv`クレート等でレコードを1行ずつ読み込み、各行を`BooklogCsvRow`へデシリアライズする。必須列（作品名）が空・カラム数不足・日付/数値のパース失敗の場合はその行をスキップし、`ImportFailure { row_number, reason }`へ理由文字列（例: `"title is empty"`, `"invalid date format"`）を記録する。正常行はTASK-0009の`CreateItemRequest`に変換し登録処理を呼び出す。

**実装ファイル**: `mediavault-api/src/import/booklog_csv.rs`, `mediavault-api/src/handlers/import_booklog.rs`

### 4. ImportSummary/ImportFailureレスポンス型 🔵
**信頼性**: 🔵 *api-endpoints.md「レスポンス（成功, 200）: ImportSummary（success_count, failure_count, failures）」より*

```json
{
  "success_count": 10,
  "failure_count": 2,
  "failures": [
    { "row_number": 3, "reason": "title is empty" }
  ]
}
```

**実装ファイル**: `mediavault-api/src/models/import.rs`

## 単体テスト要件
### テストケース1: 正常CSVの全行登録（TC-016-01） 🔵
**Given** 仮カラムフォーマットに準拠した正常行のみのCSV
**When** `POST /import/booklog`を呼び出す
**Then** `success_count`がCSV行数と一致し、`failure_count`は0、対応する`items`レコードが登録される

### テストケース2: 形式不正行のスキップ（EDGE-002） 🔵
**Given** 作品名が空の行を1行含むCSV
**When** インポート処理を実行する
**Then** その行はスキップされ、`failures`に`row_number`と理由が記録され、他の正常行は登録される

### テストケース3: 全行不正でも例外にならない（TC-016-E01） 🔵
**Given** 全行が形式不正なCSV
**When** `POST /import/booklog`を呼び出す
**Then** `200`が返り、`success_count=0`、`failure_count`がCSV行数と一致する

### テストケース4: 空ファイルアップロード時の400 🟡
**Given** 0バイトのファイルまたはファイル未添付のmultipartリクエスト
**When** `POST /import/booklog`を呼び出す
**Then** `400 Bad Request`（`VALIDATION_ERROR`相当）が返る

## 注意事項
- カラムフォーマットは仮定義であり、prep.mdに記載の「ブクログCSVのサンプルファイル準備」が完了した時点で`booklog_csv.rs`のマッピング定義（カラム名・型変換ロジック）のみを差分修正する想定。ハンドラ・レスポンス型・スキップロジックの構造自体は変更不要な設計とすること。
- 文字コード（UTF-8 / Shift_JIS）の実際の仕様もサンプル確認後に確定するため、デコード処理は差し替え可能な形にしておく。
- `source`フィールドの具体的な値（`manual`または専用の`booklog`値を設けるか）は設計文書未確定のため、実装時に既存`item_source` enumの値を確認し決定する。
