## タスク概要
`item_relations`テーブルに対するCRUD（`POST /item-relations`, `DELETE /item-relations/:id`）を実装する。`relation_type`は`reference`（関連作品）または`dlc`を取り、自己参照（`item_id == related_item_id`）防止チェックを行う。

## 依存タスク
- **前提タスク**: TASK-0004（マイグレーション）, TASK-0007（起動骨格）
- **後続タスク**: なし

## 完了条件
- [x] `POST /item-relations`が`item_id`, `related_item_id`, `relation_type`を受け取り、`item_relations`にINSERTする
- [x] `relation_type`が`reference`/`dlc`以外の場合、`VALIDATION_ERROR`（400）を返す
- [x] `item_id == related_item_id`の場合、アプリケーション層で拒否する（DB制約`chk_item_relations_not_self`と二重チェック）
- [x] 同一の`(item_id, related_item_id, relation_type)`組み合わせが既に存在する場合、一意制約違反に対応したエラーを返す
- [x] `DELETE /item-relations/:id`が指定IDの関連付けを削除する

## 実装詳細

### 1. POST /item-relations ハンドラ実装 🔵
**信頼性**: 🔵 *api-endpoints.md POST /item-relations リクエスト例より*

```json
{ "item_id": "...", "related_item_id": "...", "relation_type": "dlc" }
```
`mediavault-api/src/handlers/item_relations.rs`に`create_item_relation`を実装する。

**実装ファイル**: `mediavault-api/src/handlers/item_relations.rs`, `mediavault-api/src/models/item_relation.rs`

### 2. 自己参照防止チェック（TC-013-02） 🔵
**信頼性**: 🔵 *database-schema.sql chk_item_relations_not_self制約、TC-013-02より*

ハンドラ内で`item_id == related_item_id`の場合、DBへの問い合わせ前に`VALIDATION_ERROR`（400）を返す。DB側の`CHECK`制約は最終防衛線として機能する。

**実装ファイル**: `mediavault-api/src/handlers/item_relations.rs`

### 3. DELETE /item-relations/:id ハンドラ実装 🔵
**信頼性**: 🔵 *api-endpoints.md POST/DELETE /item-relations/:id より*

`item_relations.id`（UUID）を主キーとして削除する。存在しない場合は404を返す。

**実装ファイル**: `mediavault-api/src/handlers/item_relations.rs`
