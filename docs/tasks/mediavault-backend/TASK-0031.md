## タスク概要
`POST /import/steam`（`{ "steam_id": "..." }`）を実装する。Steam Web API（`api-client-lib::clients::steam`）を利用して指定`steam_id`の所持ゲーム一覧（`GetOwnedGames`相当）を取得し、`items`（`media_type=game`, `source=api`）および`game_details`（`steam_appid`等）として一括登録する。Steam APIキーが未設定・無効な場合は`401`相当のエラーを返す。TASK-0023で確立済みの`ExternalSearchService`/`api-client-lib`連携パターンを踏襲する。

## 依存タスク
- **前提タスク**: TASK-0023（ExternalSearchService/api-client-lib連携パターン）, TASK-0009（アイテム作成ロジック）
- **後続タスク**: なし（Phase5最終タスク群の一つ）

## 完了条件
- [ ] `POST /import/steam`が`{ "steam_id": string }`のリクエストボディを受け取る
- [ ] `steam_id`が空・形式不正（数値文字列でない等）の場合に`400`（`VALIDATION_ERROR`相当）を返す
- [ ] `api-client-lib::clients::steam`を通じてSteam Web API（所持ゲーム一覧取得）を呼び出す
- [ ] Steam APIキーが未設定または無効な場合、`401`相当のエラー（`STEAM_API_KEY_INVALID`）を返す（TC-017-E01）
- [ ] 取得した所持ゲーム一覧について、各ゲームを`items`（`media_type=game`, `source=api`）+`game_details`（`steam_appid`を含む）として一括登録する
- [ ] 既に同一`steam_appid`で登録済みのアイテムが存在する場合は重複登録せず、スキップまたは更新する（重複防止）
- [ ] 一部ゲーム情報の取得・変換に失敗した場合でも、他の正常なゲームの登録処理は継続される（EDGE-002）
- [ ] レスポンスとして`ImportSummary{success_count, failure_count, failures}`相当の結果を返す（TC-017-01）

## 実装詳細
### 1. POST /import/steamハンドラ 🔵
**信頼性**: 🔵 *api-endpoints.md「POST /import/steam」リクエスト例・エラーコードより*

```json
{ "steam_id": "76561198000000000" }
```
リクエストボディを`SteamImportRequest { steam_id: String }`としてデシリアライズする。`steam_id`はSteamID64形式（17桁の数値文字列）であることを簡易検証する。

**実装ファイル**: `mediavault-api/src/handlers/import_steam.rs`

### 2. Steam Web API連携（所持ゲーム一覧取得） 🔵
**信頼性**: 🔵 *タスク概要記載の`api-client-lib::clients::steam`、TASK-0023で確立済みの外部APIクライアント呼び出しパターンより*

TASK-0023で実装済みの`ExternalSearchService`と同様のパターンで、`api-client-lib::clients::steam`の所持ゲーム一覧取得関数（`GetOwnedGames`相当のSteam Web API、`appid`/`name`/`playtime_forever`等を含むレスポンス）を呼び出す。Steam APIキーはDBに保存された外部APIキー（`PUT /settings/api-keys/steam`で登録済みのもの、REQ-015関連）を使用する。

**実装ファイル**: `mediavault-api/src/import/steam_import.rs`

### 3. APIキー無効時の401エラーハンドリング 🔵
**信頼性**: 🔵 *api-endpoints.md「エラーコード: STEAM_API_KEY_INVALID（401, TC-017-E01）」より*

Steam APIキーがDBに未登録、または呼び出し結果がSteam側の認証エラー（401/403相当）を示す場合、`STEAM_API_KEY_INVALID`エラーコードとともに`401 Unauthorized`を返す。TASK-0018/TASK-0019で実装済みの外部APIエラーハンドリング共通パターン（`API_KEY_NOT_CONFIGURED`等）を参考に統一感のあるエラー型にマッピングする。

**実装ファイル**: `mediavault-api/src/import/steam_import.rs`, `mediavault-api/src/error.rs`

### 4. items/game_details一括登録ロジック 🔵
**信頼性**: 🔵 *タスク概要「items(media_type=game, source=api)+game_details(steam_appid)として一括登録」より*

取得したゲーム一覧の各要素について、TASK-0009の登録ロジックを再利用しつつ`media_type=game`, `source=api`, `external_id=steam_appid`として`items`を作成し、付随する`game_details`（`steam_appid`, プレイ時間等取得可能な情報）を登録する。既存の`external_id`+`media_type`の組み合わせで重複チェックを行い、既存レコードがあればスキップまたは更新する。1件ごとの登録失敗（DB制約違反等）は`ImportFailure`として記録し、全体処理は継続する。

**実装ファイル**: `mediavault-api/src/import/steam_import.rs`

### 5. ImportSummaryレスポンス 🔵
**信頼性**: 🔵 *api-endpoints.md「POST /import/booklog」と同形式のImportSummaryをSteamインポートにも適用（タスク概要・REQ-017/EDGE-002の対称性より）*

ブクログインポート（TASK-0030）と同様の`ImportSummary{success_count, failure_count, failures}`型を再利用し、レスポンス形式の一貫性を保つ。

**実装ファイル**: `mediavault-api/src/models/import.rs`（TASK-0030と共通）

## 単体テスト要件
### テストケース1: 正常な所持ゲーム一覧の一括登録（TC-017-01） 🔵
**Given** 有効なSteam APIキーが設定済みで、Steam Web APIが複数件の所持ゲームを返すモック
**When** `POST /import/steam { "steam_id": "76561198000000000" }`を呼び出す
**Then** 取得件数分の`items`（`media_type=game`, `source=api`）と`game_details`が登録され、`success_count`が件数と一致する

### テストケース2: Steam APIキー無効時の401（TC-017-E01） 🔵
**Given** Steam APIキーが未設定、またはSteam Web APIが認証エラーを返すモック
**When** `POST /import/steam`を呼び出す
**Then** `401 Unauthorized`が`STEAM_API_KEY_INVALID`エラーコードとともに返る

### テストケース3: 一部ゲームの登録失敗時のスキップ継続（EDGE-002） 🟡
**Given** 取得した複数件のゲームのうち1件がDB制約違反等で登録に失敗するケース
**When** インポート処理を実行する
**Then** 失敗した1件は`failures`に記録され、他の正常なゲームの登録は継続される

### テストケース4: steam_id形式不正時の400 🟡
**Given** `steam_id`が空文字または非数値文字列
**When** `POST /import/steam`を呼び出す
**Then** `400 Bad Request`（`VALIDATION_ERROR`相当）が返る

### テストケース5: 重複steam_appidのスキップ・更新 🟡
**Given** 既に同一`steam_appid`で`items`に登録済みのゲームを含む所持ゲーム一覧
**When** インポート処理を実行する
**Then** 重複分は新規作成されず、スキップまたは既存レコードの更新として処理される

## 注意事項
- Steamプロフィールが非公開設定の場合、所持ゲーム一覧APIが空配列を返す可能性がある（prep.md「Steam Web APIキー・SteamIDの取得」に記載のプロフィール公開設定要件と関連）。この場合は`success_count=0, failure_count=0`として正常終了させ、エラーとはしない設計とする。
- `ImportSummary`/`ImportFailure`型はTASK-0030（ブクログインポート）と共通化し、`mediavault-api/src/models/import.rs`に集約することで実装の重複を避ける。
- Steam Web APIのレート制限・タイムアウトはTASK-0018/0019で確立済みの外部APIタイムアウトハンドリング（`EXTERNAL_API_TIMEOUT`, 502相当）パターンを再利用する。
