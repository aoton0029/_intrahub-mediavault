## タスク概要
`mediavault-api/src/main.rs` に、`.env` ファイルの読込、PostgreSQL接続プール（`PgPool`、最大5〜10接続）の確立、Axum Routerの骨格構築を実装する。モジュール構成（`routes/`, `handlers/`, `services/`, `db/`, `middleware/`, `models/`）の雛形を用意し、ヘルスチェックエンドポイント `GET /health` を実装する。本タスク完了をもってPhase 1「基盤構築」が完了し、Phase 2（各メディア種別のCRUD実装等）の着手が可能になる。

## 実装詳細
### 1. モジュール構成の雛形作成 🔵
**信頼性**: 🔵 *architecture.mdに記載のレイヤー構成（ルーティング/ハンドラ/サービス/DB/ミドルウェア/モデル分離）より*
`src/routes/mod.rs`, `src/handlers/mod.rs`, `src/services/mod.rs`, `src/db/mod.rs`, `src/middleware/mod.rs`, `src/models/mod.rs` を作成する。各モジュールはPhase 1時点では空（最小限のpub関数や型のみ）でよいが、`main.rs` から `mod routes; mod handlers; ...` で参照可能な状態にする。TASK-0005の `models/response.rs`、TASK-0006の `middleware/api_key_auth.rs` をこの構成に組み込む。
**実装ファイル**: `backend/mediavault-api/src/routes/mod.rs`, `backend/mediavault-api/src/handlers/mod.rs`, `backend/mediavault-api/src/services/mod.rs`, `backend/mediavault-api/src/db/mod.rs`, `backend/mediavault-api/src/middleware/mod.rs`, `backend/mediavault-api/src/models/mod.rs`

### 2. 環境変数読込 🔵
**信頼性**: 🔵 *tech-stack.mdの開発環境構成（.env管理）より*
`main()` の先頭で `dotenvy::dotenv().ok()` を呼び出し、`.env` ファイルが存在しない場合（本番コンテナ環境等）でもエラーにならないようにする。
**実装ファイル**: `backend/mediavault-api/src/main.rs`

### 3. DB接続プール設定 🔵
**信頼性**: 🔵 *tech-stack.mdでsqlxによるPostgreSQL接続が明記、最大接続数は一般的な単一ユーザー向けセルフホストアプリの妥当な設定値*
`sqlx::postgres::PgPoolOptions::new().max_connections(10).connect(&database_url).await` でプールを作成する。接続失敗時はパニックせず、エラーログを出力してプロセスを終了する。プールは `AppState` 構造体に保持し、Axumの `State` 抽出子で各ハンドラに共有する。
**実装ファイル**: `backend/mediavault-api/src/db/mod.rs`, `backend/mediavault-api/src/main.rs`

### 4. AppState定義 🟡
**信頼性**: 🟡 *Axumの一般的な状態共有パターンからの妥当な推測（設計文書にAppStateの明示はない）*
`AppState { db: PgPool, internal_api_key: String }` のような構造体を定義し、`Router::new().with_state(app_state)` でDIする。TASK-0006のミドルウェアもこの状態からAPIキーを参照できるようにする。
**実装ファイル**: `backend/mediavault-api/src/main.rs`

### 5. Axum Routerとヘルスチェック実装 🔵
**信頼性**: 🔵 *architecture.mdの基本構成、一般的なヘルスチェックパターンより*
`Router::new().route("/health", get(health_handler))` を実装する。`health_handler` はDB接続確認（`SELECT 1`等の簡易クエリ）を行い、成功時は `ApiOk` 形式で `{"status": "ok"}` を200で返す（🟡 DB接続確認を含めるかは設計文書に明示なし。最小実装としてDB確認なしの単純な200応答でも完了条件を満たすため、確認込みは拡張案として記載）。Phase 2以降のルートはこのRouterに `.merge()` または `.nest()` で追加していく前提の構成にする。
**実装ファイル**: `backend/mediavault-api/src/handlers/health.rs`, `backend/mediavault-api/src/routes/mod.rs`

### 6. サーバー起動 🔵
**信頼性**: 🔵 *tech-stack.mdでAxum+Tokioランタイムの利用が明記*
`tokio::net::TcpListener::bind(addr).await` でリスナーを作成し、`axum::serve(listener, app).await` でサーバーを起動する。ポート番号は環境変数（例: `APP_PORT`、未設定時は既定値8080）から取得する。
**実装ファイル**: `backend/mediavault-api/src/main.rs`

## 注意事項
