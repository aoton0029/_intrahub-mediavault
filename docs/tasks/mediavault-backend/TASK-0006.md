## タスク概要
`mediavault-api/src/middleware/api_key_auth.rs` に、内部REST APIへのアクセスを保護するAPIキー検証ミドルウェアを実装する。リクエストの `Authorization` ヘッダーを検証し、`.env` の `INTERNAL_API_KEY` と一致しない場合、またはヘッダーが欠落している場合は401 Unauthorizedを返す。REQ-403「内部REST APIへのアクセスはAPIキー検証を必須としなければならない」およびNFR-101「APIキー1本によるヘッダー検証ミドルウェアで保護」を実現する。

## 実装詳細
### 1. ミドルウェア関数の実装 🔵
**信頼性**: 🔵 *NFR-101「APIキー1本によるヘッダー検証ミドルウェア」より*
Axumの `axum::middleware::from_fn` を使用し、`Request` から `Authorization` ヘッダーを取得する関数を実装する。ヘッダー値は `Bearer <key>` 形式、または単純な生キー文字列のいずれかを許容する設計とする（🟡 ヘッダー形式の具体的な記法は要件に明示がないため妥当な推測）。環境変数 `INTERNAL_API_KEY` の値と比較し、一致すれば `next.run(req).await` で次のハンドラに処理を渡す。
**実装ファイル**: `backend/mediavault-api/src/middleware/api_key_auth.rs`

### 2. 検証失敗時のレスポンス 🔵
**信頼性**: 🔵 *TC-018-E01/E02「APIキーなし/誤ったキーで401」より*
検証に失敗した場合、TASK-0005で実装した `ApiError`（`ApiErrorCode::Unauthorized`）を用いて401 Unauthorizedを返す。エラーメッセージは「認証に失敗しました」等、内部実装の詳細を含まない一般的な文言とする。
**実装ファイル**: `backend/mediavault-api/src/middleware/api_key_auth.rs`

### 3. APIキーの環境変数読込 🔵
**信頼性**: 🔵 *NFR-101「APIキー1本」・TASK-0002で.envに INTERNAL_API_KEY を定義済みの前提より*
ミドルウェアは起動時または各リクエスト時に `std::env::var("INTERNAL_API_KEY")` で値を取得する。本番運用ではアプリケーション状態（`AppState`）に保持し、リクエストごとに環境変数を読み直さない実装が望ましい（🟡 パフォーマンス上の妥当な推測。状態の持ち方はTASK-0007のAppState設計と整合させる）。
**実装ファイル**: `backend/mediavault-api/src/middleware/api_key_auth.rs`

### 4. ルーターへの適用 🔵
**信頼性**: 🔵 *NFR-101「全内部エンドポイントに適用」、TC-NFR-101-01より*
TASK-0007で構築するAxum Routerに対し、`.layer(middleware::from_fn(api_key_auth))` 形式で内部APIルート全体に適用できるようにする（実際の適用作業はTASK-0007側で行う。本タスクではミドルウェア関数自体の実装とテストに専念する）。
**実装ファイル**: `backend/mediavault-api/src/middleware/api_key_auth.rs`

## 単体テスト要件（該当する場合）
### テストケース1: 正しいAPIキーで通過する（TC-018-01対応） 🔵
**Given** 環境変数 `INTERNAL_API_KEY` に値 `"secret-key"` が設定されている
**When** `Authorization: secret-key`（またはBearer形式）を含むリクエストがミドルウェアを通過する
**Then** リクエストが次のハンドラに到達し、200系のレスポンスが返る

### テストケース2: APIキーなしで401（TC-018-E01対応） 🔵
**Given** 環境変数 `INTERNAL_API_KEY` が設定されている
**When** `Authorization` ヘッダーを含まないリクエストを送信する
**Then** レスポンスステータスが401であり、`ApiErrorBody.code` が `UNAUTHORIZED` である

### テストケース3: 誤ったAPIキーで401（TC-018-E02対応） 🔵
**Given** 環境変数 `INTERNAL_API_KEY` に値 `"secret-key"` が設定されている
**When** `Authorization: wrong-key` を含むリクエストを送信する
**Then** レスポンスステータスが401である
