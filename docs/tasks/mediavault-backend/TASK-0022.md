## タスク概要
外部APIキー（TMDb/IGDB/NDL/Steam/OpenLibrary/AniList）をDBの `api_credentials` テーブルに登録・更新する `PUT /settings/api-keys/:provider` を実装する。`provider` パスパラメータは `ApiProvider` enum（tmdb/igdb/ndl/steam/open_library/ani_list）に対応する値のみを許可し、不正な値が指定された場合は `400 INVALID_PROVIDER` を返す。Jikanはキー不要のため対象外（REQ-015の通り）。本タスクはPhase3の後続タスク（ExternalSearchService）が外部APIキーをDBから取得するための前提となる。

## 実装詳細
### 1. provider パスパラメータのバリデーション 🔵
**信頼性**: 🔵 *types.rs `ApiProvider` enum定義、api-endpoints.md INVALID_PROVIDER(400, TC-015-02)より*
Axumのパスパラメータ（`String`）を `ApiProvider`（`#[sqlx(type_name = "api_provider", rename_all = "snake_case")]`）にデシリアライズ・変換する。`serde_json`経由でのマッチまたは `match` 文による文字列→enum変換を行い、失敗時は `AppError::InvalidProvider`（400）を返す。
**実装ファイル**: `backend/mediavault-api/src/handlers/settings.rs`, `backend/mediavault-api/src/models/api_credential.rs`

### 2. リクエストボディDTO定義 🔵
**信頼性**: 🔵 *api-endpoints.md PUT /settings/api-keys/:provider リクエスト例 `{ "api_key": "xxxxx" }` より*
```rust
#[derive(Debug, Deserialize)]
pub struct UpdateApiKeyRequest {
    pub api_key: String,
}
```
**実装ファイル**: `backend/mediavault-api/src/models/api_credential.rs`

### 3. upsert クエリ実装 🔵
**信頼性**: 🔵 *database-schema.sql `api_credentials`（provider PRIMARY KEY）、architecture.md db層集約方針より*
`sqlx::query!` で `INSERT INTO api_credentials (provider, api_key) VALUES ($1, $2) ON CONFLICT (provider) DO UPDATE SET api_key = $2, updated_at = CURRENT_TIMESTAMP` を実行する repository関数 `upsert_api_credential` を db層に実装する。
**実装ファイル**: `backend/mediavault-api/src/db/api_credentials.rs`

### 4. ハンドラ・ルーティング登録 🔵
**信頼性**: 🔵 *architecture.md レイヤードアーキテクチャ（routes→handlers→services→db）方針より*
`PUT /settings/api-keys/:provider` を `routes/settings.rs` に追加し、`handlers::settings::update_api_key` を呼び出す。
**実装ファイル**: `backend/mediavault-api/src/routes/settings.rs`, `backend/mediavault-api/src/handlers/settings.rs`

### 5. APIキー取得用関数（後続タスク向け） 🔵
**信頼性**: 🔵 *TASK-0023でExternalSearchServiceがDBからAPIキーを取得する前提（dataflow.md 73行目）より*
`db::api_credentials::find_by_provider(provider: ApiProvider) -> Result<Option<ApiCredential>, sqlx::Error>` を実装し、後続タスクから参照可能にする。
**実装ファイル**: `backend/mediavault-api/src/db/api_credentials.rs`

## 単体テスト要件
### テストケース1: TMDbキー登録（TC-015-01） 🔵
**信頼性**: 🔵 *acceptance-criteria.md TC-015-01より*
**Given**: `api_credentials` テーブルに `tmdb` のレコードが存在しない
**When**: `PUT /settings/api-keys/tmdb` に `{ "api_key": "valid-tmdb-key" }` を送信する
**Then**: `200`が返り、`api_credentials` に `provider=tmdb, api_key=valid-tmdb-key` のレコードが作成される

### テストケース2: 不正provider指定（TC-015-02） 🟡
**信頼性**: 🟡 *acceptance-criteria.md TC-015-02（信頼性🟡指定）より*
**Given**: provider enumに存在しない文字列（例: `unknown_provider`）
**When**: `PUT /settings/api-keys/unknown_provider` に `{ "api_key": "x" }` を送信する
**Then**: `400 INVALID_PROVIDER` が返り、DBへの書き込みは発生しない

### テストケース3: キー更新が以後反映される（TC-015-03） 🔵
**信頼性**: 🔵 *acceptance-criteria.md TC-015-03より*
**Given**: `provider=tmdb` のレコードが既存（`api_key=old-key`）
**When**: `PUT /settings/api-keys/tmdb` に `{ "api_key": "new-key" }` を送信する
**Then**: `200`が返り、`find_by_provider(Tmdb)` が `api_key=new-key` を返す（`updated_at`も更新される）
