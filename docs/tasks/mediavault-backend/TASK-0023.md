## タスク概要
`mediavault-api/src/services/external_search.rs` に `ExternalSearchService` を実装する。利用者が指定する `media_type`（anime/movie/drama/manga/novel/game/paper/book等）に応じて、`api-client-lib` が提供する各プロバイダクライアント（jikan/tmdb/ndl/openlibrary/steam/igdb/anilist）の `ApiClient::execute(Request) -> Result<ApiResponse<Model>, ApiError>` を呼び出すディスパッチロジックを実装する。TMDb/IGDB/NDL/Steam/OpenLibrary/AniListはAPIキーが必要なため、呼び出し前にTASK-0022で実装した `db::api_credentials::find_by_provider` でDBからキーを取得し、クライアントを初期化する。キー未設定時は `ExternalSearchError::ApiKeyNotConfigured` を返す（後続TASK-0024で422にマッピング）。

## 実装詳細
### 1. media_type → provider マッピング定義 🔵
**信頼性**: 🔵 *architecture.md「外部APIクライアント」節、acceptance-criteria.md TC-002-01/02（anime→Jikan, movie/drama→TMDb）より*
`MediaType`（anime/manga/novel/movie/drama/game/paper/book等、types.rs定義）から対応する `ApiProvider`/クライアント種別への対応表を定義する。
- anime → Jikan（キー不要）
- movie / drama → TMDb
- game → Steam または IGDB（🟡 PRD上Steam/IGDBどちらを使うかmedia_type単独では一意に決まらない可能性があるため、要パラメータ追加または優先順位の実装判断が必要）
- manga / novel → OpenLibrary（🟡 NDLとの使い分けは要件上明記が薄く妥当な推測）
- paper / book（学術書） → NDL
- anime（関連情報拡張）→ AniList（🟡 Jikanとの併用方針は要件に明記なし、妥当な推測）
**実装ファイル**: `backend/mediavault-api/src/services/external_search.rs`

### 2. ExternalSearchService構造体・初期化 🔵
**信頼性**: 🔵 *architecture.md「`mediavault-api`からは`clients::{provider}`を呼び出すラッパー（`ExternalSearchService`）を新設」より*
```rust
pub struct ExternalSearchService {
    pool: PgPool,
}

impl ExternalSearchService {
    pub fn new(pool: PgPool) -> Self { ... }

    pub async fn search(&self, media_type: MediaType, query: &str)
        -> Result<Vec<ExternalSearchResult>, ExternalSearchError> { ... }
}
```
**実装ファイル**: `backend/mediavault-api/src/services/external_search.rs`

### 3. APIキー取得とクライアント初期化 🔵
**信頼性**: 🔵 *dataflow.md「サービス層がmedia_typeに対応するプロバイダを選択し、必要に応じてDBから外部APIキーを取得」より*
キーが必要なプロバイダ（TMDb/IGDB/NDL/Steam/OpenLibrary/AniList）については、`db::api_credentials::find_by_provider` を呼び、`None`の場合は `ExternalSearchError::ApiKeyNotConfigured(provider)` を返す。Jikanはキー取得をスキップする。
**実装ファイル**: `backend/mediavault-api/src/services/external_search.rs`

### 4. ApiClient::execute呼び出しとエラーハンドリング 🔵
**信頼性**: 🔵 *architecture.md「`ApiClient`トレイト（`execute(Request) -> Result<ApiResponse<Model>, ApiError>`）」より、既存api-client-lib実装に準拠*
各クライアントの `execute` を呼び出し、`ApiError`（タイムアウト・HTTPエラー等）を `ExternalSearchError::ExternalApiError` にマッピングする。`?`演算子でpanicさせず、Result型で呼び出し元（ハンドラ）に伝播させる。
**実装ファイル**: `backend/mediavault-api/src/services/external_search.rs`

### 5. レスポンス共通化（ExternalSearchResult） 🟡
**信頼性**: 🟡 *api-endpoints.md「外部API検索結果一覧（プロバイダ固有の生データをラップ）」より、ラップ形式は実装詳細が未確定のため妥当な推測*
プロバイダ固有のModel型を、`media_type`・`provider`・`external_id`・`title`・`raw_data`(JSON)等を含む共通DTO `ExternalSearchResult` に変換するアダプタ関数を各プロバイダ用に実装する。
**実装ファイル**: `backend/mediavault-api/src/services/external_search.rs`, `backend/mediavault-api/src/models/external_search.rs`

## 単体テスト要件
### テストケース1: media_type=animeでJikanクライアントが呼ばれる 🔵
**信頼性**: 🔵 *acceptance-criteria.md TC-002-01より*
**Given**: `media_type=Anime`、モック化された各プロバイダクライアント
**When**: `ExternalSearchService::search(MediaType::Anime, "鬼滅の刃")` を呼ぶ
**Then**: Jikanクライアントの `execute` のみが呼び出され、他プロバイダのクライアントは呼ばれない

### テストケース2: media_type=movie/dramaでTMDbクライアントが呼ばれる 🔵
**信頼性**: 🔵 *acceptance-criteria.md TC-002-02より*
**Given**: `media_type=Movie` または `Drama`、`api_credentials`にTMDbキーが登録済み
**When**: `search(MediaType::Movie, "タイトル")` を呼ぶ
**Then**: TMDbクライアントの `execute` が、DBから取得したAPIキーで初期化された状態で呼び出される

### テストケース3: APIキー未設定時にApiKeyNotConfiguredを返す 🟡
**信頼性**: 🟡 *EDGE-001・TC-002-E01から本サービス層での妥当な推測（ハンドラでの422変換は別タスク）*
**Given**: `media_type=Movie`、`api_credentials`にTMDbキーが存在しない
**When**: `search(MediaType::Movie, "タイトル")` を呼ぶ
**Then**: `Err(ExternalSearchError::ApiKeyNotConfigured(ApiProvider::Tmdb))` が返り、外部API呼び出しは発生しない

### テストケース4: 外部APIタイムアウト時にExternalApiErrorを返す 🟡
**信頼性**: 🟡 *TC-002-E02から本サービス層での妥当な推測*
**Given**: モックTMDbクライアントが `ApiError::Timeout` を返すよう設定
**When**: `search(MediaType::Movie, "タイトル")` を呼ぶ
**Then**: `Err(ExternalSearchError::ExternalApiError(..))` が返り、panicしない
