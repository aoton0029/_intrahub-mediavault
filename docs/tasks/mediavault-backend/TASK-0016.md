## タスク概要
マイリスト（`mylists`）の作成と、マイリストへのアイテム追加・削除エンドポイントを実装する。`POST /mylists`, `POST /mylists/:id/items`, `DELETE /mylists/:id/items/:item_id`を構築する。

## 依存タスク
- **前提タスク**: TASK-0004（マイグレーション）, TASK-0007（起動骨格）
- **後続タスク**: なし

## 完了条件
- [ ] `POST /mylists`が`name`を受け取り、`mylists`テーブルに作成する
- [ ] `POST /mylists/:id/items`が`item_id`を受け取り、`mylist_items`に複合キーでINSERTする
- [ ] `DELETE /mylists/:id/items/:item_id`が`mylist_items`から該当レコードを削除する
- [ ] 存在しない`mylist_id`または`item_id`を指定した場合、適切な404エラーを返す

---
## 実装詳細

### 1. マイリスト作成ハンドラ実装 🔵
**信頼性**: 🔵 *REQ-005・user-stories 2.2より*

`mediavault-api/src/handlers/mylists.rs`に`create_mylist`を実装する。`mylists`テーブル（`id`, `name`, `created_at`）にINSERTする。

**実装ファイル**: `mediavault-api/src/handlers/mylists.rs`, `mediavault-api/src/models/mylist.rs`

### 2. マイリストへのitem追加・削除 🔵
**信頼性**: 🔵 *REQ-005より*

`POST /mylists/:id/items`は`mylist_items`（`mylist_id`, `item_id`の複合PK）へINSERTする。`mylist_id`または`item_id`が存在しない場合は外部キー制約違反となるため、事前に存在チェックを行い`MYLIST_NOT_FOUND`/`ITEM_NOT_FOUND`を返す。`DELETE /mylists/:id/items/:item_id`は複合キーでDELETEする。

**実装ファイル**: `mediavault-api/src/handlers/mylists.rs`

## 単体テスト要件

### テストケース1: マイリスト作成の正常動作 🔵
**Given** `{ "name": "今期視聴予定" }`
**When** `POST /mylists`を呼び出す
**Then** 201でマイリスト（UUID付き）が返る

### テストケース2: マイリストへのitem追加 🔵
**Given** 既存mylist, 既存item
**When** `POST /mylists/:id/items`を呼び出す
**Then** 201（または200）で`mylist_items`にレコードが作成される

### テストケース3: マイリストからのitem削除 🔵
**Given** マイリストに追加済みのitem
**When** `DELETE /mylists/:id/items/:item_id`を呼び出す
**Then** 204で`mylist_items`からレコードが削除される

### テストケース4: 存在しないmylist_idでのitem追加で404 🟡
**Given** 存在しないmylist UUID
**When** `POST /mylists/:id/items`を呼び出す
**Then** 404 `MYLIST_NOT_FOUND`が返る
