## タスク概要
`backend/docker-compose.yml` を作成し、PostgreSQLコンテナ（データボリューム永続化付き）とアプリケーションコンテナ（Dockerfileベース）を定義する。`.env` ファイルから環境変数（DB接続情報、内部APIキー等）を読み込む構成とし、ローカル開発・自己ホスト運用の両方で利用できるようにする。

## 完了条件
- [ ] `backend/docker-compose.yml` が作成されている
- [ ] `db` サービスがPostgreSQLイメージを使用し、名前付きボリュームでデータを永続化する設定になっている
- [ ] `.env` ファイルから環境変数を読み込む設定（`env_file` または `environment` + `${VAR}`）になっている

## 実装詳細
### 1. Postgresサービス定義 🔵
**信頼性**: 🔵 *tech-stack.md「開発環境」よりPostgreSQL利用が明記*
`postgres:16` 系イメージ（または同等の安定版）を使用し、`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` を `.env` の値で設定する。ポートはホスト側にマッピング（例: `5432:5432`）し、`volumes` に名前付きボリューム（例: `pgdata:/var/lib/postgresql/data`）を指定する。
**実装ファイル**: `backend/docker-compose.yml`

### 2. アプリケーションサービス定義 🟡
**信頼性**: 🟡 *Dockerfile自体は未作成のため、一般的なRustマルチステージビルド構成からの妥当な推測*
`app` サービスは `build: { context: ., dockerfile: Dockerfile }` とし、`depends_on: [db]` で起動順序を制御する。`DATABASE_URL` 等は `.env` から注入する。本タスクではDockerfileの雛形作成も含む（マルチステージビルド: builderステージでcargo build、runtimeステージで実行バイナリのみ配置）。
**実装ファイル**: `backend/docker-compose.yml`, `backend/Dockerfile`

### 3. 環境変数の外部化 🔵
**信頼性**: 🔵 *prep.mdの開発環境前提・12-factor的構成は標準的*
`backend/.env.example` を作成し、`DATABASE_URL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `INTERNAL_API_KEY` 等の必要な環境変数のテンプレートを記載する。実際の `.env` はgit管理対象外とする。
**実装ファイル**: `backend/.env.example`, `backend/.gitignore`
