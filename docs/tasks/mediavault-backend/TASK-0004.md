## タスク概要
TASK-0003で作成した初期マイグレーションに続き、`tags`/`item_tags`, `categories`/`item_categories`, `mylists`/`mylist_items`, `item_relations`, `item_links`, `item_files`, `item_trailers`, `item_groups`, `item_episodes`, `staff`/`item_staff`, `api_credentials` の全関連テーブルを新規マイグレーションとして追加する。さらに `updated_at` 自動更新トリガー（4テーブル分）と、EDGE-101要件に対応する `check_episode_group_type` トリガー（volumeグループへのepisode追加を禁止する）を実装する。

## 実装詳細
### 1. タグ・カテゴリ関連テーブル 🔵
**信頼性**: 🔵 *database-schema.sql 167-191行目をそのまま反映*
`tags`（タグ名のマスタ）、`item_tags`（items と tags の中間テーブル、複合PK）、`categories`（カテゴリマスタ）、`item_categories`（items と categories の中間テーブル）を定義する。中間テーブルは `ON DELETE CASCADE` を設定し、孤立レコードを防止する。
**実装ファイル**: `backend/mediavault-api/migrations/<timestamp>_add_relation_tables.up.sql`

### 2. マイリスト関連テーブル 🔵
**信頼性**: 🔵 *database-schema.sql 193-209行目をそのまま反映*
`mylists`（ユーザー定義リストのマスタ）、`mylist_items`（mylists と items の中間テーブル、表示順を保持）を定義する。
**実装ファイル**: `backend/mediavault-api/migrations/<timestamp>_add_relation_tables.up.sql`

### 3. アイテム関連・リンク・ファイル・予告編テーブル 🔵
**信頼性**: 🔵 *database-schema.sql 211-264行目をそのまま反映*
`item_relations`（reference/dlc関係。`chk_item_relations_not_self` で自己参照を禁止 🟡 自己参照防止の妥当な推測）、`item_links`（外部リンクURL群）、`item_files`（PDF/画像等のアップロードファイル、`updated_at`トリガー対象）、`item_trailers`（予告編動画URL）を定義する。
**実装ファイル**: `backend/mediavault-api/migrations/<timestamp>_add_relation_tables.up.sql`

### 4. グループ・エピソードテーブルとEDGE-101トリガー 🔵
**信頼性**: 🔵 *database-schema.sql 265-318行目をそのまま反映、EDGE-101要件に対応*
`item_groups`（season/volume/chapterの汎用グループ、`updated_at`トリガー対象）、`item_episodes`（season/chapter配下のみ使用、`updated_at`トリガー対象）を定義する。`check_episode_group_type()` 関数を作成し、`item_episodes` への INSERT/UPDATE 時に紐づく `item_groups.group_type` が `'volume'` の場合は `RAISE EXCEPTION` する。トリガー `trg_check_episode_group_type` を `BEFORE INSERT OR UPDATE ON item_episodes` に設定する。
**実装ファイル**: `backend/mediavault-api/migrations/<timestamp>_add_relation_tables.up.sql`

### 5. スタッフ・APIクレデンシャルテーブル 🔵
**信頼性**: 🔵 *database-schema.sql 322-357行目をそのまま反映*
`staff`（人物マスタ）、`item_staff`（items と staff の中間テーブル、役割を保持）、`api_credentials`（外部APIキー保管、`api_provider`単位でユニーク、`updated_at`トリガー対象）を定義する。
**実装ファイル**: `backend/mediavault-api/migrations/<timestamp>_add_relation_tables.up.sql`

### 6. updated_at自動更新トリガー共通関数 🔵
**信頼性**: 🔵 *database-schema.sql 359-376行目をそのまま反映*
`update_updated_at_column()` トリガー関数（`NEW.updated_at = CURRENT_TIMESTAMP; RETURN NEW;`）を定義し、`items`, `item_groups`, `item_episodes`, `item_files`, `api_credentials` の5テーブルに `BEFORE UPDATE` トリガーとして適用する（`items` のトリガーはTASK-0003側で定義済みの場合は重複作成しないよう確認する）。
**実装ファイル**: `backend/mediavault-api/migrations/<timestamp>_add_relation_tables.up.sql`

### 7. downマイグレーション 🟡
**信頼性**: 🟡 *sqlx-cliの標準運用から妥当な推測*
`down.sql` で全トリガー・関数・テーブルを依存関係の逆順でDROPする。
**実装ファイル**: `backend/mediavault-api/migrations/<timestamp>_add_relation_tables.down.sql`

## 統合テスト要件（該当する場合）
### テストケース1: EDGE-101 volumeグループへのepisode追加禁止 🔵
**Given** `group_type='volume'` の `item_groups` レコードが存在する
**When** そのグループIDを参照する `item_episodes` をINSERTする
**Then** トリガーが例外を発生させ、INSERTが失敗する

### テストケース2: updated_at自動更新 🔵
**Given** `items` テーブルに既存レコードがある
**When** 該当レコードの任意カラムをUPDATEする
**Then** `updated_at` がCURRENT_TIMESTAMPに更新される

### テストケース3: item_relations自己参照禁止 🟡
**Given** `items` テーブルにレコードAが存在する
**When** `item_id=A, related_item_id=A` で `item_relations` にINSERTする
**Then** CHECK制約 `chk_item_relations_not_self` 違反でエラーになる

## 注意事項
- トリガー関数はマイグレーション単位で `CREATE OR REPLACE FUNCTION` を使用し、再実行時の冪等性を確保する。
- `item_episodes` のトリガーは `group_id` から `item_groups.group_type` をサブクエリで参照するため、参照整合性（外部キー）が先に確立していることを確認する。
