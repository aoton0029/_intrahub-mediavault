## タスク概要
`GET /items`エンドポイントを実装する。`media_type`, `tag_id`, `category_id`, `is_favorite`, `status`による絞り込みと、`page`/`limit`によるページネーションに対応した一覧取得APIを構築する。

- [ ] 各フィルタ条件はAND結合で適用される
- [ ] `page`デフォルト1, `limit`デフォルト20・最大100で動作する

## 実装詳細

### 1. クエリパラメータDTO定義 🔵
**信頼性**: 🔵 *api-endpoints.md GET /items クエリパラメータより*

`ListItemsQuery`構造体（`media_type: Option<MediaType>`, `tag_id: Option<Uuid>`, `category_id: Option<Uuid>`, `is_favorite: Option<bool>`, `status: Option<ItemStatus>`, `page: Option<u32>`, `limit: Option<u32>`）をAxumの`Query`extractorで受け取る。

**実装ファイル**: `mediavault-api/src/handlers/items.rs`

### 2. 動的WHERE句構築 🔵
**信頼性**: 🔵 *REQ-001「絞り込み」要件より*

`tag_id`指定時は`item_tags`を、`category_id`指定時は`item_categories`を介したJOINまたはサブクエリで絞り込む。`sqlx::QueryBuilder`を用いて動的にWHERE句を構築する。

**実装ファイル**: `mediavault-api/src/repositories/item_repository.rs`

### 3. ページネーション処理 🟡
**信頼性**: 🟡 *api-endpoints.mdページネーション仕様（page/limitデフォルト値）より*

`limit`は1〜100の範囲にクランプし、`OFFSET (page-1)*limit`を適用する。`total`は同条件での`COUNT(*)`クエリで取得する。

**実装ファイル**: `mediavault-api/src/repositories/item_repository.rs`

## 単体テスト要件

### テストケース1: 絞り込みなしの一覧取得 🔵
**Given** クエリパラメータなし
**When** `GET /items`を呼び出す
**Then** デフォルトpage=1, limit=20で全件のうち先頭20件が返る

### テストケース2: media_typeによる絞り込み 🔵
**Given** `media_type=anime`
**When** `GET /items?media_type=anime`を呼び出す
**Then** anime種別のitemのみが返る

### テストケース3: 複数条件のAND絞り込み 🟡
**Given** `media_type=anime&is_favorite=true`
**When** `GET /items`を呼び出す
**Then** 両条件を満たすitemのみが返る

### テストケース4: limitの最大値クランプ 🟡
**Given** `limit=500`
**When** `GET /items`を呼び出す
**Then** 実際に適用されるlimitは100にクランプされる
