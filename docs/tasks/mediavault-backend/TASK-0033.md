## タスク概要
`.github/workflows/backend-ci.yml`を作成し、プッシュ／プルリクエスト時に`cargo test`（TASK-0032の統合テストを含む）、`cargo clippy --all-targets`、`cargo fmt --check`、`sqlx migrate run`を自動実行するCIパイプラインを構築する。統合テストの実行にはPostgreSQLのテスト用DBが必要なため、GitHub Actions上でPostgresサービスコンテナを起動し、マイグレーション適用後にテストを走らせる構成とする。

## 依存タスク

- **後続タスク**: TASK-0034（README・起動手順整備）

## 完了条件
- [ ] `.github/workflows/backend-ci.yml`が作成されている
- [ ] ワークフローがPostgreSQLサービスコンテナ（GitHub Actionsの`services:`）を起動する設定になっている
- [ ] `sqlx migrate run`がCI内でテスト用DBに対して実行され、マイグレーション適用後にテストが実行される

- [ ] `cargo test`（単体テスト・TASK-0032の統合テストを含む）が実行され、失敗時にCIが失敗する
- [ ] `main`ブランチへのpushおよびpull_requestをトリガーとして動作することを確認する
- [ ] Rustツールチェイン・依存クレートのキャッシュ（`actions/cache`またはRust用キャッシュアクション）が設定され、CI実行時間が短縮される

## 実装詳細
### 1. ワークフローのトリガー・基本構成 🔵
**信頼性**: 🔵 *tech-stack.md「CI/CD」、一般的なRustプロジェクトCI構成より*
`on: [push, pull_request]`を`main`ブランチ・PR全般に対して設定する。`runs-on: ubuntu-latest`を使用し、Rust安定版ツールチェインをセットアップする（`dtolnay/rust-toolchain`または`actions-rs`系アクション、もしくは`rustup`コマンド直接実行）。

**実装ファイル**: `.github/workflows/backend-ci.yml`

### 2. PostgreSQLサービスコンテナとマイグレーション 🔵
**信頼性**: 🔵 *architecture.mdのDB構成、TASK-0032のテスト用DB前提より*
`services:`セクションに`postgres:16`（または開発環境と同バージョン）のイメージを定義し、ヘルスチェック（`pg_isready`）を設定する。ジョブ内で`DATABASE_URL`環境変数をサービスコンテナ向けに設定し、`sqlx-cli`をインストールしたうえで`sqlx migrate run`を実行してスキーマを適用する。

**実装ファイル**: `.github/workflows/backend-ci.yml`

### 3. fmt・clippy・test の実行ステップ 🔵
**信頼性**: 🔵 *タスク概要のCI要件より*
- `cargo fmt --all -- --check`
- `cargo clippy --all-targets --all-features -- -D warnings`
- `cargo test --all-targets`（`TEST_DATABASE_URL`等、TASK-0032で定めた環境変数をジョブ環境変数として渡す）
の3ステップを順に実行する。いずれかが失敗した場合はジョブ全体を失敗とする。

**実装ファイル**: `.github/workflows/backend-ci.yml`

### 4. 依存キャッシュの設定 🟡
**信頼性**: 🟡 *CI実行時間短縮の一般的プラクティスから妥当な推測（tech-stack.mdに明記なし）*
`Swatinem/rust-cache`等のアクション、または`actions/cache`を用いて`~/.cargo`・`target/`をキャッシュし、毎回のフルビルドを回避する。

**実装ファイル**: `.github/workflows/backend-ci.yml`

## 注意事項
- CI上のPostgresサービスコンテナのバージョンは、開発環境のdocker-compose.yml（prep.md記載の必須準備タスク）と揃えること。
- 外部APIキーを要する処理（TASK-0032でモック化済み）はCI上で実APIキーを必要としない構成になっていることを再確認する。
- `sqlx`のオフラインモード（`SQLX_OFFLINE=true`、`.sqlx`メタデータ）を利用している場合は、CI上でもメタデータが最新であることを検証するステップを検討する。
