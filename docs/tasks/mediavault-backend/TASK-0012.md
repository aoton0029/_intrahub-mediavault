## タスク概要
`PATCH /items/:id`エンドポイントを実装する。`UpdateItemRequest`（TASK-0008）で定義した部分更新DTOを用いて、指定フィールドのみを更新する。

## 依存タスク
- **前提タスク**: TASK-0008（itemsモデル・DTO）
- **後続タスク**: なし

## 完了条件
- [x] `PATCH /items/:id`が`UpdateItemRequest`の指定フィールドのみを更新する
- [x] `updated_at`がDBトリガー（trg_items_updated_at）により自動更新される
- [x] 更新後のitemを200で返す
- [x] 該当itemが存在しない場合、`ITEM_NOT_FOUND`（404）を返す（TC-001-E02）
- [x] `title`を空文字に更新しようとした場合、`VALIDATION_ERROR`（400）を返す

## 実装詳細

### 1. PATCH /items/:id ハンドラ実装 🔵
**信頼性**: 🔵 *api-endpoints.md PATCH /items/:id より*

`UpdateItemRequest`をTASK-0008のバリデーションにかけ、`Some`が設定されたフィールドのみ動的にUPDATE文に組み込む。

**実装ファイル**: `mediavault-api/src/handlers/items.rs`

### 2. 動的UPDATE文構築 🔵
**信頼性**: 🔵 *REQ-001・TC-001-02（部分更新の動作）より*

`sqlx::QueryBuilder`を用いて、`Option`が`Some`のフィールドのみSET句に追加する。全フィールドが`None`の場合は何も更新せず現在の状態を返す。

**実装ファイル**: `mediavault-api/src/repositories/item_repository.rs`

### 3. ITEM_NOT_FOUND エラー処理 🔵
**信頼性**: 🔵 *TC-001-E02より*

更新対象が0件だった場合、`ITEM_NOT_FOUND`（404）を返す。

**実装ファイル**: `mediavault-api/src/handlers/items.rs`

## 単体テスト要件

### テストケース1: TC-001-02 部分更新の正常動作 🔵
**Given** 既存item, `{ "rating": 4.5, "is_favorite": true }`
**When** `PATCH /items/:id`を呼び出す
**Then** 200で`rating=4.5`, `is_favorite=true`に更新され、他フィールドは変化しない

### テストケース2: TC-001-E02 存在しないitemで404 🔵
**Given** 存在しないUUID
**When** `PATCH /items/:id`を呼び出す
**Then** 404 `ITEM_NOT_FOUND`が返る

### テストケース3: titleを空文字に更新で400 🟡
**Given** `{ "title": "" }`
**When** `PATCH /items/:id`を呼び出す
**Then** 400 `VALIDATION_ERROR`が返る
