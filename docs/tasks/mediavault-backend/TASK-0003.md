## タスク概要
`sqlx-cli` を導入し、`sqlx migrate add init_schema` で初回マイグレーションファイルを作成する。database-schema.sql に定義された7種のENUM型（media_type, item_status, item_source, group_type, relation_type, file_type, api_provider）、共通テーブル `items`、メディア種別ごとの詳細テーブル8種（anime_details〜paper_details）をマイグレーションSQLとして反映する。`items` テーブルのCHECK制約（source/external_id整合性、title非空）も含める。

## 実装詳細
### 1. sqlx-cli導入 🔵
**信頼性**: 🔵 *tech-stack.mdでsqlx利用が明記されており、マイグレーション管理にsqlx-cliは標準的な手段*
`cargo install sqlx-cli --no-default-features --features postgres` でCLIを導入する。`DATABASE_URL` を `.env` に設定し、`sqlx database create` でDB作成を確認する。
**実装ファイル**: なし（グローバルツールのインストール）

### 2. ENUM型定義の反映 🔵
**信頼性**: 🔵 *database-schema.sql 17-38行目のCREATE TYPE文をそのまま反映*
以下7種のENUM型を `up.sql` の先頭に定義する。
- `media_type`: anime, movie, drama, manga, novel, game, academic_book, paper
- `item_status`: not_started, in_progress, completed
- `item_source`: api, manual
- `group_type`: season, volume, chapter
- `relation_type`: reference, dlc
- `file_type`: pdf, image, other
- `api_provider`: tmdb, igdb, ndl, steam, openlibrary, anilist
**実装ファイル**: `backend/mediavault-api/migrations/<timestamp>_init_schema.up.sql`

### 3. itemsテーブル定義 🔵
**信頼性**: 🔵 *database-schema.sql 44-73行目をそのまま反映*
`gen_random_uuid()` を主キー既定値とし、`title`, `media_type`, `status`, `source` をNOT NULLとする。CHECK制約 `chk_items_source_external_id`（source=manualならexternal_id任意、source=apiならexternal_id必須）と `chk_items_title_not_empty`（title<>''）を含める。インデックス `idx_items_media_type`, `idx_items_status`, `idx_items_is_favorite`, `idx_items_external_id` も作成する。
**実装ファイル**: `backend/mediavault-api/migrations/<timestamp>_init_schema.up.sql`

### 4. メディア別詳細テーブル定義（8種） 🔵
**信頼性**: 🔵 *database-schema.sql 79-160行目をそのまま反映*
`anime_details`, `movie_details`, `drama_details`, `manga_details`, `novel_details`, `game_details`, `academic_book_details`, `paper_details` の8テーブルを、`item_id` を主キー兼 `items(id)` への外部キー（`ON DELETE CASCADE`）として定義する。各テーブル固有のメディア属性カラム（episode_count, director, isbn, doi等）と外部API ID（jikan_id, tmdb_id, steam_appid等）を含める。
**実装ファイル**: `backend/mediavault-api/migrations/<timestamp>_init_schema.up.sql`

### 5. downマイグレーション 🟡
**信頼性**: 🟡 *sqlx-cliの標準運用から妥当な推測（設計文書に明示はない）*
`down.sql` では作成した全テーブルをDROP（CASCADE）し、最後にENUM型をDROP TYPEする（依存関係順に注意）。
**実装ファイル**: `backend/mediavault-api/migrations/<timestamp>_init_schema.down.sql`

## 統合テスト要件（該当する場合）
### テストケース1: CHECK制約違反の確認 🔵
**Given** `items` テーブルが作成済みである
**When** `source='api'` かつ `external_id` を指定せずにINSERTを実行する
**Then** PostgreSQLがCHECK制約 `chk_items_source_external_id`違反のエラーを返す

### テストケース2: タイトル空文字の拒否 🟡
**Given** `items` テーブルが作成済みである
**When** `title=''` でINSERTを実行する
**Then** CHECK制約 `chk_items_title_not_empty`違反のエラーを返す
