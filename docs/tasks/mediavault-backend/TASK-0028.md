## タスク概要
`PATCH /items/:id/files/:file_id/calibre-link` エンドポイントを実装し、`file_type=pdf` の `item_files` レコードに対して `calibre_book_id` を更新する。Calibre-Web側でのPDF取込完了後に呼び出される想定（REQ-103）。また、`calibre_book_id` が設定済みのPDFについては、アイテム詳細APIのレスポンスにCalibre-Web遷移用情報（calibre_book_idおよび関連リンク情報）を含めるようレスポンス構築を拡張する（TC-020-02、部分的に🟡）。

## 依存タスク
- **前提タスク**: [TASK-0026](TASK-0026.md)（item_filesモデル/リポジトリ・パス指定方式の基盤）
- **後続タスク**: なし（Phase 4内の独立した拡張機能。Phase 5以降でCalibre-Web連携UIが必要になった場合に参照される可能性あり）

## 完了条件
- [ ] `PATCH /items/:id/files/:file_id/calibre-link` が `calibre_book_id` を受け取り、対象 `item_files` レコードを更新する
- [ ] 対象の `file_type` が `pdf` 以外の場合はエラーを返す（`VALIDATION_ERROR`等）
- [ ] 対象の `item_id`/`file_id` が存在しない、または `item_id` と `file_id` の紐付けが一致しない場合 `FILE_NOT_FOUND`相当（404）を返す
- [ ] 更新成功時、更新後の `item_files` レコードを200で返す
- [ ] `calibre_book_id` が設定済みのPDFについて、アイテム詳細APIのレスポンスにCalibre-Web遷移用情報が含まれる（TC-020-02）
- [ ] TC-020-01・TC-020-02を満たす

## 実装詳細

### 1. UpdateCalibreLinkRequest DTO定義 🔵
**信頼性**: 🔵 *api-endpoints.md PATCH /items/:id/files/:file_id/calibre-link リクエスト例より*

```json
{ "calibre_book_id": "calibre-12345" }
```
`calibre_book_id`（必須, 非空文字列）を持つDTOを定義する。

**実装ファイル**: `mediavault-api/src/models/item_file.rs`

### 2. ハンドラ実装・file_type=pdf検証 🔵
**信頼性**: 🔵 *REQ-020/103・TC-020-01より*

`item_id` と `file_id` の存在・紐付けを確認後、対象レコードの `file_type` が `pdf` であることを検証する。`pdf` 以外の場合は更新を拒否し `VALIDATION_ERROR`（400）を返す。

**実装ファイル**: `mediavault-api/src/handlers/item_files.rs`

### 3. calibre_book_id 更新（リポジトリ層） 🔵
**信頼性**: 🔵 *database-schema.sqlのitem_filesテーブル定義より*

`UPDATE item_files SET calibre_book_id = $1 WHERE id = $2 AND item_id = $3 AND file_type = 'pdf'` 相当のクエリを実装する。

**実装ファイル**: `mediavault-api/src/repositories/item_file_repository.rs`

### 4. アイテム詳細APIレスポンスへのCalibre-Web遷移情報付加 🟡
**信頼性**: 🟡 *TC-020-02・PRDの「Calibre-Web遷移」記述からの妥当な推測（遷移用URL構築方式は未確定）*

アイテム詳細APIのレスポンス構築処理（既存のPhase2実装）を拡張し、関連 `item_files` のうち `file_type=pdf` かつ `calibre_book_id IS NOT NULL` のものについて、`calibre_book_id` をレスポンスに含める。Calibre-Web側の遷移URL組み立て（ベースURL + book_id等）は環境変数等の設定値を用いる想定とし、具体的なURL形式は本タスクでは固定値のテンプレートとして実装し、実際のCalibre-Web設定確定後に調整可能な構造とする。

**実装ファイル**: `mediavault-api/src/handlers/items.rs`（詳細取得ハンドラ）, `mediavault-api/src/models/item_file.rs`

## 単体テスト要件

### テストケース1: 正常系 - calibre_book_idの更新（TC-020-01） 🔵
**Given** `file_type=pdf` の既存 `item_files` レコードと `{ "calibre_book_id": "calibre-12345" }`
**When** `PATCH /items/:id/files/:file_id/calibre-link` を実行する
**Then** 200が返り、対象レコードの `calibre_book_id` が更新される

### テストケース2: file_type不一致での拒否 🔵
**Given** `file_type=photo` の既存 `item_files` レコード
**When** `PATCH /items/:id/files/:file_id/calibre-link` を実行する
**Then** `VALIDATION_ERROR`（400）が返り、レコードは更新されない

### テストケース3: file_id不存在・紐付け不一致 🔵
**Given** 存在しない `file_id`、または別の `item_id` に属する `file_id`
**When** `PATCH /items/:id/files/:file_id/calibre-link` を実行する
**Then** 404相当のエラーが返る

### テストケース4: 詳細APIレスポンスへのCalibre-Web情報付加（TC-020-02） 🟡
**Given** `calibre_book_id` が設定済みのPDFファイルを持つアイテム
**When** アイテム詳細取得APIを実行する
**Then** レスポンスの該当ファイル情報に `calibre_book_id`（およびCalibre-Web遷移用情報）が含まれる
