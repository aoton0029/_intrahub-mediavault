## タスク概要
`items`テーブルおよびメディア別詳細テーブルに対応するRustモデル（`Item`構造体）と、API入力用のDTO（`CreateItemRequest`, `UpdateItemRequest`）を実装する。Phase2全体のCRUDタスクの基盤となるドメインモデル層であり、`media_type` enumの妥当性検証・`title`非空検証などの基本バリデーションを含む。

## 実装詳細

### 1. Itemモデル定義 🔵
**信頼性**: 🔵 *database-schema.sqlのitemsテーブル定義より*

`items`テーブルの全カラム（id, media_type, title, original_title, description, cover_image_url, release_date, homepage_url, status, consumed_date, rating, is_favorite, source, external_id, created_at, updated_at）に対応する構造体を定義する。`media_type`, `item_status`, `item_source`はRust側でenumとして表現し、Postgres enumとのマッピングは`sqlx::Type`を用いる。

**実装ファイル**: `mediavault-api/src/models/item.rs`

### 2. CreateItemRequest定義 🔵
**信頼性**: 🔵 *api-endpoints.md POST /items リクエスト例より*

```json
{ "media_type": "anime", "title": "作品A", "details": {} }
```
`media_type`, `title`は必須。`original_title`, `description`, `cover_image_url`, `release_date`, `homepage_url`, `rating`, `is_favorite`, `details`(メディア別詳細のJSON)はoptional。`source`はサーバー側で`manual`固定、`external_id`はNULL固定とする（TASK-0009で利用）。

**実装ファイル**: `mediavault-api/src/models/item.rs`

### 3. UpdateItemRequest定義 🔵
**信頼性**: 🔵 *api-endpoints.md PATCH /items/:id リクエスト例より*

```json
{ "rating": 4.5, "is_favorite": true }
```
全フィールドを`Option<T>`とし、未指定フィールドは更新しない部分更新（PATCH semantics）として扱う。`media_type`, `source`, `external_id`は更新不可（変更不可フィールド）として除外する。

**実装ファイル**: `mediavault-api/src/models/item.rs`

### 4. media_type/title バリデーション 🔵
**信頼性**: 🔵 *TC-001-E01（media_type不正で400）, TC-001-B01（title空文字で400）より*

`validator`クレートまたは手動実装によるバリデーション関数を用意する。`media_type`は文字列入力をenumにパースし、失敗時は`VALIDATION_ERROR`を返す。`title`は`trim()`後の長さが0より大きいことを検証する。

**実装ファイル**: `mediavault-api/src/models/item.rs`, `mediavault-api/src/error.rs`（既存エラー型を再利用）
