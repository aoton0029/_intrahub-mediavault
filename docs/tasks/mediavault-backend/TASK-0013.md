## タスク概要
`DELETE /items/:id`エンドポイントを実装する。`items`テーブルからのレコード削除に伴い、`ON DELETE CASCADE`設定された関連テーブル（item_tags, item_categories, mylist_items, item_relations, item_links, item_files, item_trailers, item_groups, item_staff, メディア別詳細テーブル）が連動して削除されることを確認する。

## 依存タスク
- **前提タスク**: TASK-0008（itemsモデル・DTO）
- **後続タスク**: なし

## 完了条件
- [ ] `DELETE /items/:id`が指定itemを削除し、成功時204を返す
- [ ] 該当itemが存在しない場合、`ITEM_NOT_FOUND`（404）を返す
- [ ] カスケード削除により、関連する`item_tags`, `item_categories`, `mylist_items`, `item_relations`, `item_links`, `item_files`, `item_trailers`, `item_groups`, `item_staff`, メディア別詳細テーブルのレコードが自動的に削除される

## 実装詳細

### 1. DELETE /items/:id ハンドラ実装 🔵
**信頼性**: 🔵 *api-endpoints.md DELETE /items/:id より*

`mediavault-api/src/handlers/items.rs`に`delete_item`ハンドラを実装し、`DELETE FROM items WHERE id = $1`を実行する。`ON DELETE CASCADE`がDBスキーマで設定済みのため、アプリケーション側で個別に関連テーブルを削除する処理は不要。

**実装ファイル**: `mediavault-api/src/handlers/items.rs`

### 2. 削除件数による存在チェック 🔵
**信頼性**: 🔵 *TC-001-03（ITEM_NOT_FOUNDのケースも含む削除動作確認）より*

`DELETE`実行結果の`rows_affected()`が0の場合、`ITEM_NOT_FOUND`（404）を返す。

**実装ファイル**: `mediavault-api/src/repositories/item_repository.rs`

## 注意事項
- `item_relations`は`related_item_id`としても参照されるため、削除対象itemが他itemの`related_item_id`になっている場合もカスケード削除される（`item_relations.related_item_id`もON DELETE CASCADE設定）。
- カスケード削除はDB制約に依存するため、本タスクのテストはマイグレーション（TASK-0004）が正しく適用されていることを前提とする。
