## タスク概要
`mediavault-api/src/models/response.rs` に、設計文書 types.rs で定義された統一APIレスポンス型 `ApiOk<T>`, `ApiError`, `ApiErrorBody` を実装する。Axumの `IntoResponse` トレイトを実装し、各エラーコード（`VALIDATION_ERROR`, `ITEM_NOT_FOUND` 等）に対応するHTTPステータスコードでJSONレスポンスを返す共通エラーハンドラを作成する。以降の全エンドポイント実装（Phase 2以降）が一貫したレスポンス形式を返すための基盤となる。

## 実装詳細
### 1. レスポンス型の実装 🔵
**信頼性**: 🔵 *types.rs 423-441行目に構造体定義が明示されている*
`ApiOk<T> { success: bool, data: T }`、`ApiError { success: bool, error: ApiErrorBody }`、`ApiErrorBody { code: String, message: String }` を `serde::Serialize` 付きで実装する。`ApiOk::new(data)` 等のコンストラクタヘルパーを用意する。
**実装ファイル**: `backend/mediavault-api/src/models/response.rs`

### 2. エラーコード列挙とHTTPステータスマッピング 🟡
**信頼性**: 🟡 *types.rsにはエラーコード一覧の明示はなく、acceptance-criteria.md記載のステータス（400/401/404/422/500/502）から妥当な推測で設計*
`ApiErrorCode` enum（例: `ValidationError`, `Unauthorized`, `ItemNotFound`, `UnprocessableEntity`, `InternalError`, `ExternalApiError`）を定義し、それぞれを以下にマッピングする。
- `VALIDATION_ERROR` → 400 Bad Request
- `UNAUTHORIZED` → 401 Unauthorized
- `ITEM_NOT_FOUND` → 404 Not Found
- `UNPROCESSABLE_ENTITY` → 422 Unprocessable Entity
- `INTERNAL_ERROR` → 500 Internal Server Error
- `EXTERNAL_API_ERROR` → 502 Bad Gateway
**実装ファイル**: `backend/mediavault-api/src/models/response.rs`

### 3. IntoResponse実装 🟡
**信頼性**: 🟡 *Axumの一般的なエラーハンドリングパターンからの妥当な推測（設計文書に実装方法の明示はない）*
`impl IntoResponse for ApiError` を実装し、`ApiErrorCode` からHTTPステータスを決定して `(status, Json(self)).into_response()` を返す。`From<sqlx::Error>` 等の変換実装も用意し、ハンドラから `?` 演算子で簡潔にエラーを返せるようにする。
**実装ファイル**: `backend/mediavault-api/src/models/response.rs`
