## タスク概要

worker の全体を組み立てる。これまでのタスクで作った部品（api クライアント・パス解決・形式判定・OCR・抽出器）を常駐ループへ配線する。

### 2. 実行ループ 🔵

**信頼性**: 🔵 *[tech-stack.md](../tech-stack.md) §実行ループの骨子・[interfaces.py](../design/interfaces.py) より*

```python
while not shutdown_requested():
    claimed = client.claim(worker_id, settings.extractor_lease_seconds)
    if claimed is None:
        sleep(settings.extractor_poll_interval_sec)
        continue

    cancel_event = threading.Event()
    hb = start_heartbeat_thread(client, claimed, cancel_event, settings)
    try:
        path = resolve_file_ref(claimed.file_ref, settings)   # 開く前に検証（REQ-403）
        check_size_limit(path, settings)                      # 開く前に検証（EDGE-106）
        fmt = detect_format(path)                             # REQ-062・EDGE-005
        extractor = select_extractor(fmt)                     # REQ-062

        outcome = extractor.extract(path, ocr, progress)

        if cancel_event.is_set():                             # 二重の担保（REQ-207）
            client.cancelled(claimed.extraction_id, claimed.lease_token)
        else:
            client.complete(claimed.extraction_id, claimed.lease_token, outcome, now())
    except CancelledError:
        client.cancelled(...)
    except PermanentError as e:
        client.fail(..., ExtractionFailure(e.kind, str(e), retryable=False))
    except TransientError as e:
        client.fail(..., ExtractionFailure(e.kind, str(e), retryable=True))
    except InvalidLeaseTokenError:
        log.warning("lease失効。別workerが再claim済み")      # 再試行しない（EDGE-002）
    finally:
        hb.stop()
```

### 3. 同時実行数 🔵

**信頼性**: 🔵 *REQ-302・NFR-002・[tech-stack.md](../tech-stack.md) より*

`EXTRACTOR_MAX_CONCURRENCY` の既定は1。**MVPでは1のみ対応する** 🟡。2以上を設定した場合の挙動（並列ループを立てる）は実装せず、1以外は起動時エラーとするか警告して1として扱う。

OCRはCPU/GPUバウンドで並列度1が初期値のため、複雑さに見合わない。将来必要になったら実装する。

### 4. heartbeat スレッド 🔵

**信頼性**: 🔵 *REQ-023・REQ-066・[tech-stack.md](../tech-stack.md) §worker 実行モデルより*

**実装ファイル**: `extractor/src/mediavault_extractor/heartbeat.py`

daemon スレッド1本のみ。抽出本体はメインスレッドで同期実行する。

```python
class HeartbeatThread:
    def run(self) -> None:
        while not self._stop.is_set():
            try:
                result = self._client.heartbeat(
                    self._extraction_id, self._lease_token,
                    self._progress.current, self._progress.total, self._lease_seconds,
                )
                if result.cancel_requested:
                    self._cancel_event.set()      # メインスレッドへ伝播
            except InvalidLeaseTokenError:
                self._cancel_event.set()          # 再claim済み。中断させる 🟡
                return
            except TransientError:
                self._consecutive_failures += 1
                if self._consecutive_failures >= MAX_HEARTBEAT_FAILURES:
                    self._cancel_event.set()      # EDGE-008
                    return
            self._stop.wait(self._interval)
```

**3つの設計判断**:

1. **キャンセル伝播は `threading.Event` 1本** 🔵。共有状態を最小にする
2. **`InvalidLeaseTokenError` で `cancel_event` をセットする** 🟡: lease が失効し別 worker が再claimしている。メインスレッドの処理を続けても complete が拒否されるだけなので、早期に中断させる
3. **heartbeat 連続失敗で中断** 🟡（EDGE-008）: api 到達不能が続く場合、処理を続けても complete できない。lease 失効による再claimに委ねる

### 4b. 進捗の共有 🟡

**信頼性**: 🟡 *設計での具体化（要件に明記なし）*

メインスレッド（抽出器）が進捗を書き、heartbeat スレッドが読む。`ProgressReporter` Protocol（[interfaces.py](../design/interfaces.py)）の実装が両者の橋渡しをする。

```python
class SharedProgress:          # ProgressReporter を満たす
    def report(self, current: int, total: int) -> None:
        with self._lock:
            self._current, self._total = current, total
    def is_cancelled(self) -> bool:
        return self._cancel_event.is_set()
```

int の読み書きは GIL 下で原子的だが、2値の一貫性のため `Lock` で保護する。

### 5. エラー分類 🔵

**信頼性**: 🔵 *REQ-109・REQ-110・[dataflow.md](../design/dataflow.md) §worker 側のエラー分類より*

| 例外 | 送信内容 | api 側の遷移 |
|---|---|---|
| `CancelledError` | `cancelled` | `cancelled`（終端） |
| `PermanentError` | `fail(retryable=False)` | 即 `failed` |
| `TransientError` | `fail(retryable=True)` | `attempts < max` なら `queued` |
| `InvalidLeaseTokenError` | **何も送らない** | 別 worker が処理中 |

`InvalidLeaseTokenError` で `fail` を送ってはならない。別 worker が正常に処理している抽出を失敗させてしまう。

### 6. 構造化ログ 🔵

**信頼性**: 🔵 *REQ-071・NFR-401・PRD NFR-004より*

### 7. graceful shutdown 🟡

**信頼性**: 🟡 *常駐プロセスとして妥当な追加（要件に明記なし）*

SIGTERM を受けたら次の claim を行わず、処理中の抽出を完遂してから終了する。`docker compose restart` で処理中の抽出が中途半端に終わるのを防ぐ。

タイムアウト（例: 30秒）を超えたら強制終了し、lease 失効による再claimに委ねる。

## 注意事項

- **OCRエンジン初期化を claim の前に置く**（実装詳細1）。PRD §8.9 の受け入れ条件がこの順序を要求している
- **`InvalidLeaseTokenError` で `fail` を送らない**。別 worker が処理中の抽出を失敗させてしまう
- **キャンセル確認を二重に行う**。抽出器内（ページ境界）と complete 直前の両方。片方が漏れても成功確定を防ぐ
- heartbeat スレッドは daemon にする。メインスレッドが落ちたときにプロセスが残らないように
- `threading.Event` 以外の共有状態を増やさない。デバッグが難しくなる
- `EXTRACTOR_MAX_CONCURRENCY` は1のみ対応。2以上を黙って無視せず、起動時に警告またはエラーにする
- fake を多用するため、テストが実装の写しにならないよう注意する。「呼ばれた/呼ばれない」ではなく「送信された内容」を検証する箇所を作る
