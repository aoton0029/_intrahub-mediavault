### 2. DBドライバを含めない 🔵

**信頼性**: 🔵 *REQ-070・NFR-106・[tech-stack.md](../tech-stack.md) §設計方針より*

「DBへ直接接続しない」（PRD §5.1）を**依存レベルで強制する**。psycopg / asyncpg / SQLAlchemy 等を一切入れない。

これにより将来「ちょっとDBを見たい」という誘惑が技術的に不可能になる。完了条件のチェック項目として `uv tree` の出力を確認する。

### 3. 設定（pydantic-settings） 🔵

**信頼性**: 🔵 *[interfaces.py](../design/interfaces.py) `ExtractorSettings`・[tech-stack.md](../tech-stack.md) §主要な環境変数より*

**実装ファイル**: `extractor/src/mediavault_extractor/config.py`

[interfaces.py](../design/interfaces.py) の `ExtractorSettings` をそのまま実装する。`allowed_root()` メソッドを含める（[TASK-0018](TASK-0018.md) で使う）。

**未確定の既定値** 🟡: 以下は暫定値。[prep.md](../spec/prep.md) §確認事項で判断待ち、または NFR-003 の実測待ち。

| 変数 | 暫定値 | 確定時期 |
|---|---|---|
| `EXTRACTOR_OCR_FALLBACK_MIN_CHARS_PER_PAGE` | 50 | 実データ評価後 |
| `EXTRACTOR_POLL_INTERVAL_SEC` | 5.0 | 運用開始後 |
| `EXTRACTOR_HEARTBEAT_INTERVAL_SEC` | 30.0 | lease 期間と併せて |
| `EXTRACTOR_LEASE_SECONDS` | 300 | CPU OCR 実測後 |
| `EXTRACTOR_JOB_TIMEOUT_SEC` | 3600 | 同上 |
| `EXTRACTOR_MAX_FILE_BYTES` | 500MB | 蔵書の分布確認後 |
| `EXTRACTOR_MAX_PAGES` | 2000 | 同上 |

暫定値であることをコード内コメントに明記し、あとから変えやすくする。

### 4. structlog とマスキング 🔵

**信頼性**: 🔵 *NFR-104・REQ-405・[tech-stack.md](../tech-stack.md) §ログ方針より*

**実装ファイル**: `extractor/src/mediavault_extractor/logging.py`

JSON構造化出力。**マスキングは processor 1箇所に集約する**（各所で書き分けない）。

```python
def _mask_secrets(logger, method_name, event_dict):
    # INTERNAL_API_KEY の値が含まれていたら伏せる
    # content / text / image を含むキーは値を落とす
    return event_dict
```

出力しないもの: `INTERNAL_API_KEY`、抽出本文、画像、個人情報（REQ-405）。

記録するもの（NFR-401）: 抽出ID・ファイルID・処理形式・ページ数・処理時間・終了状態・OCRデバイス/エンジン/モデル。

### 5. Dockerfile 🔵

**信頼性**: 🔵 *[tech-stack.md](../tech-stack.md) §配布形態より*

**実装ファイル**: `extractor/Dockerfile`

Python 3.12 ベース、uv でインストール、常駐プロセスとして `python -m mediavault_extractor` を実行。

**yomitoku のモデル配布** 🟡: 初回実行時ダウンロードか、イメージ同梱か、ボリューム配置かを決める（[prep.md](../spec/prep.md) §推奨「yomitoku のモデル取得と配布方式の決定」）。本タスクでは方式を決め、Dockerfile に反映する。

### 6. docker-compose への追加 🔵

**信頼性**: 🔵 *[tech-stack.md](../tech-stack.md) §compose 追加イメージにひな型あり*

**実装ファイル**: `docker-compose.yml`（既存への追加）

```yaml
  mediavault-extractor:
    build: { context: ./extractor, dockerfile: Dockerfile }
    restart: unless-stopped
    environment:
      MEDIAVAULT_API_BASE_URL: http://mediavault-api:8080
      INTERNAL_API_KEY: ${INTERNAL_API_KEY:?INTERNAL_API_KEY is required}
      EXTRACTOR_LIBRARY_ROOT: /library
      EXTRACTOR_STORAGE_ROOT: /srv/mediavault
      EXTRACTOR_OCR_DEVICE: ${EXTRACTOR_OCR_DEVICE:-cpu}
    volumes:
      - ${MEDIAVAULT_STORAGE_SOURCE:-mediavault-storage}:/srv/mediavault:ro
      - ${LIBRARY_SOURCE:-shares}:/library:ro
    depends_on:
      mediavault-api: { condition: service_healthy }
    security_opt: [ "no-new-privileges:true" ]
    networks: [ mediavault-api ]
```

**重要な3点** 🔵:
- ボリュームは `:ro`（NFR-102・REQ-404）
- ネットワークは `mediavault-api` のみ。`media-db` へ接続しない（REQ-070 の物理的な担保）
- `INTERNAL_API_KEY` は必須（`:?` により未設定なら起動失敗）

### 7. ヘルスチェック 🔵

**信頼性**: 🔵 *NFR-403・REQ-303より*

**実装ファイル**: `extractor/src/mediavault_extractor/health.py`
