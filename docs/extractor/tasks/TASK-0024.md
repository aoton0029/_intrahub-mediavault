## 実装詳細

### 1. ツールの実装 🔵

**信頼性**: 🔵 *[mastra-integration.md](../../backend/mediavault-mcp/design/mastra-integration.md)・[api-tool-mapping.md](../../backend/mediavault-mcp/design/api-tool-mapping.md) より*

**実装ファイル**: `backend/mediavault-mcp/src/tools/`（既存ツールと同じ構成）

`GET /api/v1/items/{id}/text` を呼び、結果をエージェント向けに整形する。**公開APIを使う**（内部APIキーは不要）。

パラメータ: `item_id`（必須）、`file_id`（任意）、`chunk_index`（任意）、`chunk_size`（任意）

### 2. エラーの意味づけ 🔵

**信頼性**: 🔵 *NFR-501・NFR-503・[mastra-integration.md](../../backend/mediavault-mcp/design/mastra-integration.md) §エラー分類より*

api のHTTPエラーを、エージェントが次の行動を決められる形へ翻訳する。

| api レスポンス | mcp が返す意味 | メッセージに含める誘導 |
|---|---|---|
| `422 TEXT_NOT_EXTRACTED` | `not_extracted` | **`request_extraction` で抽出を依頼できる**（REQ-083） |
| `404 FILE_NOT_FOUND` | 材料が無い | 別の情報源を検討する |
| `404 ITEM_NOT_FOUND` | Item が無い | — |
| `409 AMBIGUOUS_FILE` | 対象が絞れない | `candidates` を提示し `file_id` の指定を促す |
| `400 VALIDATION_ERROR` | パラメータ不正 | 範囲を示す |
| 到達不能 | `MCP_API_UNREACHABLE` | 復旧待ち |

**`not_extracted` に解決策を含めることが REQ-083 の要求** 🔵。エージェントが「読めなかった」で止まらず、自分で抽出を依頼して再取得できるようにする。

### 3. AMBIGUOUS_FILE の候補提示 🔵

**信頼性**: 🔵 *REQ-115・NFR-502より*

api が返す `candidates`（`file_id` / `label` / `file_type`）をそのままエージェントへ渡す。エージェントが `file_id` を指定して再試行できる形にする。

**エラーで行き止まりにしない**。

### 4. 出典参照のための情報 🔵

**信頼性**: 🔵 *REQ-413・REQ-414・[user-stories.md](../spec/user-stories.md) ストーリー3.3より*

レスポンスに以下を必ず含める。

| フィールド | 用途 |
|---|---|
| `chunk.index` | 出典参照の一部（0起点連番） |
| `chunk.total_chunks` | ループ終了判定 |
| `chunk.label` | 人間向けの出典表示（`"p.42"`） |
| `extraction_version` | 保存済み出典の失効検知 |
| `file_id` | 出典参照の一部 |

エージェントは `(itemId, fileId, chunkIndex, extraction_version)` を出典として保存する。

### 5. ツール説明文 🔵

**信頼性**: 🔵 *mcp NFR-201・NFR-202（AIエージェント向け要件）より*

エージェントが正しく使えるよう、説明文に以下を明記する。

- `chunk_index` は**0起点の連番**であり、ページ番号ではない
- 全文を読むには `total_chunks` までループする必要がある
- `label` は表示用であり、識別子として使ってはならない
- `extraction_version` は保存して失効検知に使う

### 6. 既存 mcp のパターン踏襲 🔵

**信頼性**: 🔵 *既存 `backend/mediavault-mcp/src/tools/` の構成より*

既存26タスクで確立されたツール実装パターン（`ApiClient` 経由、`result` モジュールでの整形、wiremock によるテスト）に従う。新しいパターンを持ち込まない。

## AIエージェント向け要件

### 全文読解のループが成立する 🔵

**信頼性**: 🔵 *[user-stories.md](../spec/user-stories.md) ストーリー3.1より*

エージェントが `chunk_index` を 0 から `total_chunks - 1` まで進めて全文を読めること。ツール説明文でこの使い方を明示する。

### 出典が検証可能である 🔵

**信頼性**: 🔵 *REQ-413・REQ-414・[user-stories.md](../spec/user-stories.md) ストーリー3.2・3.3より*

`label` により人間が検証できる出典（`"p.42"`）を示せる。`extraction_version` により保存済み出典の失効を検知できる。

### 行き止まりを作らない 🔵

**信頼性**: 🔵 *NFR-503 より*

すべてのエラーで「次に何をすればよいか」が分かること。特に `not_extracted`（→ 抽出依頼）と `AMBIGUOUS_FILE`（→ 候補から選ぶ）は自己解決可能にする。

## 注意事項

- **公開APIを使う**。`get_item_text` は認証不要の `/api/v1/items/{id}/text` を呼ぶ。内部APIキーは使わない
- **`not_extracted` に誘導を含める**（REQ-083）。これがないとエージェントは「読めない」で止まる
- 既存 mcp のツール実装パターンに従う。26タスクで確立されたパターンがあるため、新しい方式を持ち込まない
- mcp のテストは DB 不要（wiremock 方式）。api を起動せずにテストできる
- `chunk_size` のデフォルトを mcp 側で埋めない。api 側の既定値に委ねることで、api の変更が自動的に反映される
- 本タスクは [TASK-0025](TASK-0025.md) と分けている。`get_item_text`（読む）と抽出系3ツール（操作する）で性質が異なり、前者だけでも価値が出るため
