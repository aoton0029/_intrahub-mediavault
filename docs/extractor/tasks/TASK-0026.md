## タスク概要

汎用 jobs の記述を api 側ドキュメントから除去し、抽出リソースの記述へ置き換える。

**リンク切れの解消が本タスクの実質的な価値** 🔵。`docs/backend/mediavault-api/jobs.md` は存在しないのに6ファイルから参照されており、将来の開発者やAIエージェントが存在しない仕様を前提に実装を始めるリスクがある（[user-stories.md](../spec/user-stories.md) ストーリー6.1）。

実装が完了した時点で書くことで、「設計と実装が食い違ったまま文書化する」ことを避ける。

## 実装詳細

### 1. extraction.md の新規作成 🔵

**信頼性**: 🔵 *REQ-091・[api-endpoints.md](../design/api-endpoints.md) より*

**実装ファイル**: `docs/backend/mediavault-api/extraction.md`（新規）

**`jobs.md` は作成しない**（REQ-091）。汎用ジョブの概念を復活させないため。

[api-endpoints.md](../design/api-endpoints.md) の内容を、既存の api ドキュメント（`item-files.md` 等）と同じ体裁へ整える。

含める内容:
- 公開API 3本（リクエスト/レスポンス/エラー/処理順序）
- 内部API 5本（worker 専用）
- 状態遷移図
- 冪等性の仕組み（部分UNIQUE index）
- `GET /items/{id}/text` との関係

### 2. index.md の改訂 🔵

**信頼性**: 🔵 *[api-endpoints.md](../design/api-endpoints.md) §エンドポイント一覧より*

**削除する行**:

| 箇所 | 内容 |
|---|---|
| エンドポイント一覧 | `GET /jobs`、`GET /jobs/{id}`、`POST /jobs/{id}/cancel` の3行 |
| エラーコード表 | `JOB_NOT_FOUND`、`JOB_ALREADY_FINISHED` の2行 |
| 目次 | `jobs.md` への目次行（worker連携の非同期ジョブ・未実装） |

**追加する行**:

| 箇所 | 内容 |
|---|---|
| エンドポイント一覧 | extraction 3本 |
| エラーコード表 | `EXTRACTION_NOT_FOUND` / `EXTRACTION_ALREADY_FINISHED` / `UNSUPPORTED_FILE_TYPE` / `INVALID_LEASE_TOKEN` |
| 目次 | `extraction.md` への目次行（抽出リソース・worker連携） |

**更新する行**:
- `GET /items/{id}/text` から「**未実装**」表記を外す
- `TEXT_NOT_EXTRACTED` / `AMBIGUOUS_FILE` から「**未実装**」表記を外す

### 3. internal-api.md の改訂 🔵

**信頼性**: 🔵 *REQ-029・[architecture.md](../design/architecture.md) D-6より*

**変更点**:
- タイトルとパス規約を `/api/v1/internal/*` へ（現在は `/internal/*`）
- 「バージョンプレフィックスなし」の記述を削除
- `POST /internal/jobs` の行を削除
- worker 内部API 5本（claim / heartbeat / complete / fail / cancelled）を追加
- 既存6ルートのパスを新規約へ更新

### 4. item-text.md の改訂 🔵

**信頼性**: 🔵 *REQ-090・設計ヒアリングQ2より*

3箇所を改訂する。

| 箇所 | 現在 | 改訂後 |
|---|---|---|
| 冒頭 | 「**未実装。**」 | 削除（実装済み） |
| §全文抽出との関係 | 「`extract_text` ジョブ（jobs.md）が担う」「payload は `{ item_file_id, path }`」 | 抽出リソース（extraction.md）への参照。payload の記述を削除 |
| §データモデルへの要求 | 「初期実装では `label` を常に `null` とし、区切り位置の保持は後続の課題とする」 | **撤回**。boundaries を保存し `label` を範囲表記で返す（D-5） |
| 状態対応表 | 「ジョブ `queued` / `running`」 | 「抽出 `queued` / `running`」 |
| 末尾 | 「ジョブの進捗確認は `GET /api/v1/jobs` を使う」 | `GET .../extraction` へ |

**`label` の記述改訂が特に重要** 🔵: 設計と実装が変わった箇所であり、古い記述が残ると実装と食い違う。

### 5. data-model.md の改訂 🔵

**信頼性**: 🔵 *REQ-040・REQ-041・[database-schema.sql](../design/database-schema.sql) より*

`item_file_extractions` と `item_file_texts` の2テーブルを追加する。`extraction_state` ENUM も記載する。

実際に適用した migration（[TASK-0001](TASK-0001.md)）の内容と一致させる。

### 6. PRD.md の改訂 🔵

**信頼性**: 🔵 *REQ-090・[requirements.md](../spec/requirements.md) §確定した設計判断より*

| §8.5 状態遷移 | 図の `queued/running/...` は維持。用語を「抽出」へ |
| §8.8 受け入れ条件 | 「ジョブ」→「抽出」。内容は維持 |
