### 1. migration ファイルの作成 🔵

**信頼性**: 🔵 *[database-schema.sql](../design/database-schema.sql) をそのまま使用*

既存 migration は `20260623000001_init_schema` の1本のみ。**init_schema は改変せず**、追加ファイルとして作る。

**実装ファイル**:
- `backend/mediavault-api/migrations/20260814000001_add_extraction.up.sql`
- `backend/mediavault-api/migrations/20260814000001_add_extraction.down.sql`

```sql
-- up.sql の骨子（完全版は design/database-schema.sql）
CREATE TYPE extraction_state AS ENUM (
    'queued', 'running', 'cancelling', 'succeeded', 'failed', 'cancelled'
);

CREATE TABLE item_file_extractions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    item_file_id UUID NOT NULL REFERENCES item_files(id) ON DELETE CASCADE,
    state extraction_state NOT NULL DEFAULT 'queued',
    attempts INTEGER NOT NULL DEFAULT 0,
    max_attempts INTEGER NOT NULL DEFAULT 3,
    progress_current INTEGER NOT NULL DEFAULT 0,
    progress_total INTEGER,
    claimed_by VARCHAR(255),
    lease_token UUID,
    lease_expires_at TIMESTAMP,
    error JSONB,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT chk_item_file_extractions_progress CHECK (...),
    CONSTRAINT chk_item_file_extractions_attempts CHECK (...),
    CONSTRAINT chk_item_file_extractions_lease CHECK (...)
);
```

### 2. 部分UNIQUE index 🔵

**信頼性**: 🔵 *REQ-044・[architecture.md](../design/architecture.md) D-1 より*

本要件で**最も重要な制約**。PRD §8.1 の `dedup_key` を置き換え、冪等性（REQ-101）の実装基盤となる。

```sql
CREATE UNIQUE INDEX uq_item_file_extractions_active
    ON item_file_extractions (item_file_id)
    WHERE state IN ('queued', 'running', 'cancelling');
```

終端状態（`succeeded` / `failed` / `cancelled`）は対象外のため、履歴として複数行が残せる（[architecture.md](../design/architecture.md) D-2）。

### 3. インデックス3件 🔵

**信頼性**: 🔵 *[database-schema.sql](../design/database-schema.sql) §インデックスより*

| index | 用途 |
|---|---|
| `idx_item_file_extractions_file_created (item_file_id, created_at DESC)` | GET .../extraction の最新1件取得（D-2） |
| `idx_item_file_extractions_claimable (created_at) WHERE state IN (...)` | claim の走査。部分indexにすることで履歴行が増えても走査量が増えない |
| `idx_item_file_extractions_state (state)` | 運用メトリクス集計（NFR-402） |

### 検証2: 部分UNIQUE index の動作 🔵

**信頼性**: 🔵 *REQ-044・[acceptance-criteria.md](../spec/acceptance-criteria.md) TC-001-B01 より*

**Given**: 同一 `item_file_id` に `state='queued'` の行が1件ある
**When**: 同じ `item_file_id` で `state='queued'` を INSERT する
**Then**: SQLSTATE 23505 で失敗する

**Given**: 同一 `item_file_id` に `state='succeeded'` の行が3件ある
**When**: 同じ `item_file_id` で `state='queued'` を INSERT する
**Then**: 成功する（終端状態は制約対象外）

### 検証3: CHECK 制約 🟡

**信頼性**: 🟡 *[database-schema.sql](../design/database-schema.sql) の CHECK 制約は要件に明記のない妥当な追加*

- `attempts > max_attempts` の UPDATE が失敗する
- `state='running'` で `lease_token IS NULL` の INSERT が失敗する
- `progress_current < 0` が失敗する

## 注意事項

- **日時型は `TIMESTAMP`**（`TIMESTAMPTZ` ではない）。既存 init_schema の全テーブルに合わせる
- **`update_updated_at_column()` を再定義しない**。`CREATE OR REPLACE` で上書きすると init_schema との所有関係が曖昧になる
- `max_attempts` の既定値 3 は暫定（[prep.md](../spec/prep.md) §確認事項）。migration で `DEFAULT 3` としておき、必要なら後続 migration で変更する
- migration のタイムスタンプは既存の `20260623000001` より後にする
