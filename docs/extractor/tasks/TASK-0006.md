## タスク概要

内部APIのパス規約を `/internal/*` から `/api/v1/internal/*` へ統一する。既存6ルート（items作成・検索・更新、groups upsert、episodes upsert、files登録）が対象。

mediavault-mcp の内部APIキー判定は元々 `/api/v1/internal/*` を前提としており、api 側を合わせることで**既存の不整合が解消される**。旧パスは残さない（設計ヒアリングQ3: 即時切替）。

worker 内部API 5本（[TASK-0011](TASK-0011.md)〜[TASK-0014](TASK-0014.md)）を追加する**前に**規約を統一しておくことで、不整合が5本ぶん拡大するのを防ぐ。これが本タスクを Phase 1 に置く理由である。

## 実装詳細

### 1. main.rs のルーター合成変更 🔵

**信頼性**: 🔵 *[architecture.md](../design/architecture.md) D-6・既存 `src/main.rs:64` の実測より*

**実装ファイル**: `backend/mediavault-api/src/main.rs`

現状:

```rust
let app = axum::Router::new()
    .nest("/api/v1", routes::build_router(state.clone()))
    .merge(routes::internal::build_internal_router(state))   // ← ルート直下
    .layer(cors);
```

変更後:

```rust
let app = axum::Router::new()
    .nest(
        "/api/v1",
        routes::build_router(state.clone())
            .merge(routes::internal::build_internal_router(state)),
    )
    .layer(cors);
```

**この変更が成立する理由** 🔵: `Router::merge` は各 Router に付与済みのレイヤーを保持する。`build_internal_router` は `.layer(axum::middleware::from_fn(api_key_auth))` を内部で適用しているため、merge 後も `api_key_auth` は内部ルートにのみ効く。公開ルートへ認証が波及することはない。

### 2. internal.rs のパス文字列 🔵

**信頼性**: 🔵 *既存 `src/routes/internal.rs:28` の実測より*

**変更しない**。`/internal/items` のまま置いておけば、`nest("/api/v1", ...)` により結果的に `/api/v1/internal/items` になる。

ただし**ドキュメントコメントは更新する**。現在のコメントは「バージョンプレフィックスを持たず」と書いており、変更後は事実と食い違う。

```rust
//! `/internal` 専用ルーター（内部REST API）
//!
//! 本ルーターは `build_router`（公開API）へ merge され、`/api/v1` 配下へ nest される。
//! 結果として公開パスは `/api/v1/internal/*` となる（REQ-029）。
//! `api_key_auth` ミドルウェアはこの Router にのみ適用され、merge 後も保持される。
```

### 3. main.rs のコメント修正 🔵

**信頼性**: 🔵 *既存コメントの事実との齟齬*

現在 `main.rs` に次のコメントがある。

```rust
// /internal/* は内部プロセス直結用のため
// バージョンプレフィックスを付与しない（REQ-402の境界を維持）。
```

この記述は変更後に誤りになるため、REQ-029 の決定内容へ書き換える。

### 4. `POST /internal/jobs` の扱い 🔵

**信頼性**: 🔵 *REQ-090・事前調査（実装が存在しない）より*

[internal-api.md](../../backend/mediavault-api/internal-api.md) の表に「未実装」として載っているのみで、`internal.rs` にルート定義は**存在しない**。コード変更は不要。ドキュメントからの削除は [TASK-0026](TASK-0026.md) で行う。
