## タスク概要

PDFからテキストを抽出する中核ロジック。テキストレイヤーがあるページはそれを使い、ないページ・品質が低いページだけOCRへフォールバックする（PRD FR-004）。

「品質基準を満たさないページ」の判定は設計ヒアリングQ4で**文字密度の閾値**と決めた（[architecture.md](../design/architecture.md) D-7）。文字数0のみを条件にすると、文字化けPDFや透かしテキストだけのスキャンPDFを取りこぼす。

あわせてページ境界（`boundaries`）の構築とキャンセル確認を行う。

`ocr` は Protocol として受け取る。テストでは fake に差し替える（[TASK-0019](TASK-0019.md) テストケース1）。

### 2. pypdfium2 によるページ処理 🔵

**信頼性**: 🔵 *[tech-stack.md](../tech-stack.md) §抽出ライブラリより*

pypdfium2 を選ぶ理由 🔵: **ライセンス**。高機能な PyMuPDF (fitz) は AGPL-3.0 であり、将来コードを公開する余地を残すなら避ける。pypdfium2 は Apache-2.0 / BSD-3-Clause で、ページ単位のテキスト取得とOCR用画像レンダリングを1ライブラリで賄える。

```python
pdf = pdfium.PdfDocument(path)
if len(pdf) > settings.extractor_max_pages:
    raise PermanentError(SIZE_LIMIT_EXCEEDED, ...)   # EDGE-106
```

**ページ数上限は開いた直後に検証する** 🔵。全ページ処理してから気づくのでは遅い。

### 3. ページごとの処理ループ 🔵

**信頼性**: 🔵 *PRD FR-004・REQ-105・REQ-106・[dataflow.md](../design/dataflow.md) フロー2より*

```python
for page_index, page in enumerate(pdf):
    # a. キャンセル確認（ページ境界でのみ）
    if progress.is_cancelled():
        raise CancelledError()

    # b. 埋め込みテキスト抽出
    text = page.get_textpage().get_text_bounded()

    # c. 品質判定 → 必要ならOCR
    if needs_ocr(text, page_area, settings.extractor_ocr_fallback_min_chars_per_page):
        image = page.render(scale=OCR_RENDER_SCALE).to_pil()
        text = ocr.ocr(image).text
        ocr_pages += 1
    else:
        embedded_pages += 1

    # d. 境界を記録
    boundaries.append(TextBoundary(start=cursor, end=cursor + len(text), label=f"p.{page_index+1}"))
    cursor += len(text)

    # e. 進捗報告
    progress.report(page_index + 1, len(pdf))
```

### 4. 文字密度によるOCR判定 🔵

**信頼性**: 🔵 *REQ-106・[architecture.md](../design/architecture.md) D-7・設計ヒアリングQ4より*

[interfaces.py](../design/interfaces.py) の `needs_ocr` を実装する。

```python
def needs_ocr(page_text, page_area_pt2, min_chars_per_page, a4_area_pt2=595*842) -> bool:
    if not page_text.strip():
        return True
    normalized = len(page_text) * (a4_area_pt2 / page_area_pt2)
    return normalized < min_chars_per_page
```

A4基準に正規化する理由 🔵: ページサイズが異なる文書（文庫本サイズ・A3見開き等）で同じ閾値を使えるようにするため。

**閾値 50 は暫定** 🟡（[prep.md](../spec/prep.md) §確認事項）。環境変数で調整可能にしてあり、実データでチューニングする。

### 5. 境界情報の構築 🔵

**信頼性**: 🔵 *REQ-068・[architecture.md](../design/architecture.md) D-5より*

`boundaries` は**正規化後の本文に対する文字オフセット**でなければならない。正規化（[TASK-0021](TASK-0021.md)）で文字数が変わるため、順序に注意が必要。

**設計判断** 🟡: ページごとに正規化してから連結し、境界を記録する。全体を連結してから正規化すると、境界位置がずれる。

```python
normalized_page_text = normalize(text)   # ページ単位で正規化
boundaries.append(TextBoundary(cursor, cursor + len(normalized_page_text), f"p.{n}"))
cursor += len(normalized_page_text)
```

`start` は含む / `end` は含まない（half-open）。単位は**文字**（バイトではない）。

### 6. キャンセル確認はページ境界のみ 🔵

**信頼性**: 🔵 *REQ-066・REQ-207・PRD FR-008「ページまたは章などの安全な区切りで」より*

ページの途中で中断すると `boundaries` が不整合になる。OCR処理中（数十秒かかりうる）は中断できないが、それでよい。次のページに入る前に必ず確認する。

### 7. extractor メタデータ 🟡

**信頼性**: 🟡 *REQ-043・[architecture.md](../design/architecture.md) D-8（記録粒度は設計での具体化）*

```python
method = (MIXED if ocr_pages and embedded_pages
          else OCR if ocr_pages else EMBEDDED_TEXT)
ExtractorMetadata(
    method=method,
    embedded_text_pages=embedded_pages,
    ocr_pages=ocr_pages,
```

### 8. extraction_version 🔵

**信頼性**: 🔵 *REQ-104・PRD FR-010より*

**変更が必要になる契機** 🟡: 正規化ロジックの変更、境界の取り方の変更、OCRエンジンの差し替え。バージョン文字列に何を含めるか（エンジン名を含めるか等）は実装時に決める。

## 注意事項

- **正規化はページ単位で行う**。全体を連結してから正規化すると `boundaries` の位置がずれる（実装詳細5）
- **キャンセル確認はページ境界のみ**。ページ途中で中断すると境界が不整合になる
- **部分結果を返さない**（テストケース10）。全ページOCR失敗時は例外を送出する
- 閾値 50 は暫定。環境変数で調整でき、実データでのチューニングを想定する
- OCR用レンダリングの `scale` はOCR精度と処理時間のトレードオフ。定数化して調整可能にする 🟡
- pypdfium2 のリソース解放（`PdfDocument.close()`）を忘れない。常駐プロセスでリークすると致命的
- fixture のPDFは小さいものを用意する（リポジトリサイズを抑えるため）
