## 実装詳細

### 1. 冪等な抽出作成 🔵

**信頼性**: 🔵 *REQ-044・REQ-101・[architecture.md](../design/architecture.md) D-1・[dataflow.md](../design/dataflow.md) フロー1より*

**実装ファイル**: `backend/mediavault-api/src/repositories/item_extraction_repository.rs`

本要件で最も重要な実装。**SELECT してから INSERT しない**。並列リクエストで両方が SELECT を通過する余地があるため、部分UNIQUE index に直接 INSERT を投げる。

```rust
pub enum CreateOutcome {
    Created(ItemFileExtraction),  // 201
    Existing(ItemFileExtraction), // 200（冪等）
}

pub async fn create_extraction(
    pool: &PgPool, item_file_id: Uuid,
) -> Result<CreateOutcome, ApiError> {
    let inserted = sqlx::query_as::<_, ItemFileExtraction>(
        "INSERT INTO item_file_extractions (item_file_id) VALUES ($1) RETURNING *",
    )
    .bind(item_file_id)
    .fetch_one(pool)
    .await;

    match inserted {
        Ok(row) => Ok(CreateOutcome::Created(row)),
        Err(e) if is_unique_violation(&e) => {
            // 既存の未完了行を返す（REQ-101）
            let existing = find_active_by_file(pool, item_file_id).await?;
            Ok(CreateOutcome::Existing(existing))
        }
        Err(e) => Err(db_error(e)),
    }
}
```

既存 `repositories/db_error_utils.rs` の `is_unique_violation`（SQLSTATE 23505）をそのまま使う。

### 2. 最新1件の取得 🔵

**信頼性**: 🔵 *[architecture.md](../design/architecture.md) D-2・REQ-002より*

履歴を残す設計のため、同一 `item_file_id` に複数行が存在しうる。

```sql
SELECT * FROM item_file_extractions
WHERE item_file_id = $1
ORDER BY created_at DESC
LIMIT 1
```

`idx_item_file_extractions_file_created` が効く。0件なら `EXTRACTION_NOT_FOUND`。

### 3. 未完了行の取得 🔵

**信頼性**: 🔵 *REQ-044・冪等化のために必要*

```sql
SELECT * FROM item_file_extractions
WHERE item_file_id = $1 AND state IN ('queued','running','cancelling')
```

部分UNIQUE index により最大1件。

### 4. キャンセル要求 🔵

**信頼性**: 🔵 *REQ-003・REQ-201・REQ-202・REQ-205・[api-endpoints.md](../design/api-endpoints.md) §cancel より*

状態別の遷移を1つの UPDATE で表現する。

| 現在 | 遷移後 |
|---|---|
| `queued` | `cancelled`（即座。worker が触っていない） |
| `running` | `cancelling`（worker の確認を待つ） |
| `cancelling` | 変化なし（冪等。EDGE-010） |
| 終端 | `409 EXTRACTION_ALREADY_FINISHED` |

```sql
UPDATE item_file_extractions
SET state = CASE state
        WHEN 'queued' THEN 'cancelled'::extraction_state
        WHEN 'running' THEN 'cancelling'::extraction_state
        ELSE state
    END,
    lease_token = CASE WHEN state = 'queued' THEN NULL ELSE lease_token END,
    lease_expires_at = CASE WHEN state = 'queued' THEN NULL ELSE lease_expires_at END
WHERE id = $1 AND state IN ('queued','running','cancelling')
RETURNING *
```

0行なら終端状態だったということなので、`find_latest_by_file` の結果を見て `EXTRACTION_ALREADY_FINISHED` を返す。

**注意**: `queued → cancelled` で `lease_token` を NULL にするのは、`chk_item_file_extractions_lease` 制約（`running`/`cancelling` は lease 必須、それ以外は不問）と整合させるため。

### 5. エラー変換 🔵

**信頼性**: 🔵 *既存 `item_file_repository.rs:13` の `db_error` と同一パターン*

```rust
fn db_error(err: sqlx::Error) -> ApiError {
    tracing::error!("item_file_extractions repository db error: {err}");
    ApiError::new(ApiErrorCode::InternalError, "抽出処理に失敗しました")
}
```

DB の内部情報をレスポンスへ漏らさない。

- DB統合テストは `#[ignore]` を付け、`cargo test --workspace --all-targets -- --include-ignored` で実行する（`backend/CLAUDE.md`）
