## 実装詳細

### 1. Protocol の実装 🔵

**信頼性**: 🔵 *[interfaces.py](../design/interfaces.py) `ExtractorApiClient` より*

**実装ファイル**: `extractor/src/mediavault_extractor/api_client.py`

[interfaces.py](../design/interfaces.py) の `ExtractorApiClient` Protocol を満たす具象クラス `HttpExtractorApiClient` を実装する。Protocol を分けておくことで、[TASK-0022](TASK-0022.md) の実行ループが fake クライアントでテストできる。

```python
class HttpExtractorApiClient:
    def __init__(self, base_url: str, api_key: str, timeout: float) -> None:
        self._client = httpx.Client(
            base_url=f"{base_url}/api/v1/internal",
            headers={"Authorization": api_key},
            timeout=timeout,
        )
```

**ベースURLに `/api/v1/internal` を含める** 🔵: [TASK-0006](TASK-0006.md) で移設したパス規約に合わせる。

**timeout を明示する** 🔵 *[tech-stack.md](../tech-stack.md) §HTTPクライアントより*: httpx の既定タイムアウトに任せない。api が応答しないときに worker が無限に待つのを防ぐ。

### 2. リトライ戦略 🔵

**信頼性**: 🔵 *REQ-109・[tech-stack.md](../tech-stack.md) §リトライより*

tenacity の `retry_if_exception_type` で**対象を限定する**。

| 状況 | リトライ | 理由 |
|---|---|---|
| 接続失敗・タイムアウト | する | 一時的（REQ-109） |
| `5xx` | する | api の一時障害 |
| `409 INVALID_LEASE_TOKEN` | **しない** | 再claimされている。何度送っても失敗する（EDGE-002） |
| `401 UNAUTHORIZED` | **しない** | 設定ミス。リトライしても直らない |
| `400` / `422` | **しない** | 送ったデータが不正。同じものを送っても同じ結果 |

**`INVALID_LEASE_TOKEN` をリトライしないことが重要** 🔵: リトライすると、別 worker が正常に処理している間に無駄なリクエストを送り続けることになる。

```python
@retry(
    retry=retry_if_exception_type((httpx.TransportError, ServerError)),
    wait=wait_exponential(multiplier=1, max=30),
    stop=stop_after_attempt(5),
)
def _request(self, method: str, path: str, json: dict | None) -> httpx.Response:
    ...
```

リトライ上限に達したら `TransientError` を送出する（[TASK-0022](TASK-0022.md) が `fail(retryable=True)` へ変換する）。

### 3. claim の `None` 表現 🟡

**信頼性**: 🟡 *[api-endpoints.md](../design/api-endpoints.md) §claim（`204` ではなく `data: null` とする設計判断）*

```python
def claim(self, worker_id: str, lease_seconds: int) -> ClaimedExtraction | None:
    resp = self._request("POST", "/extractions/claim",
                         {"worker_id": worker_id, "lease_seconds": lease_seconds})
    data = resp.json()["data"]
    if data is None:
        return None
    return _parse_claimed(data)
```

`200` + `data: null` を素直に `None` へ写す。ステータスコードによる分岐が不要になる。

### 4. complete のペイロード構築 🔵

**信頼性**: 🔵 *REQ-065・REQ-067・[api-endpoints.md](../design/api-endpoints.md) §complete より*

`ExtractionOutcome`（[TASK-0020](TASK-0020.md)〜[TASK-0021](TASK-0021.md) が生成）を JSON へ変換する。

```json
{
  "lease_token": "...",
  "content": "正規化済みの全文...",
  "boundaries": [{"start": 0, "end": 1200, "label": "p.1"}],
  "extraction_version": "pdf-v1",
  "extracted_at": "2026-08-14T09:45:00",
  "extractor": {
    "method": "mixed", "embedded_text_pages": 7, "ocr_pages": 3,
    "ocr": {"engine": "yomitoku", "device": "cpu", "model": "..."}
  }
}
```

**一括送信**（REQ-067・設計 D-4）。ページ単位の段階送信は行わない。

`device` は `cpu` / `gpu`（設定値の `cuda` ではない）。`OcrDeviceReport` enum を使うことで取り違えを型で防ぐ。

### 5. エラー分類 🔵

**信頼性**: 🔵 *[interfaces.py](../design/interfaces.py) の例外定義より*

| HTTPレスポンス | 送出する例外 |
|---|---|
| `409 INVALID_LEASE_TOKEN` | `InvalidLeaseTokenError` |
| `401` | `PermanentError(kind=INTERNAL)` — 設定ミス |
| `4xx`（上記以外） | `PermanentError` |
| リトライ上限到達 | `TransientError(kind=API_UNREACHABLE)` |

レスポンスの `error.code` を見て分類する。

### 6. ログ 🔵

**信頼性**: 🔵 *NFR-401・NFR-104より*

各リクエストで抽出ID・操作名・所要時間・結果を構造化ログへ記録する。**`content` とAPIキーは出さない**（[TASK-0016](TASK-0016.md) のマスキング processor が担保するが、そもそも渡さない）。

## 注意事項

- **`INVALID_LEASE_TOKEN` をリトライしない**。tenacity の `retry_if_exception_type` で対象を絞る設計にし、「デフォルトで全部リトライ」にしない
- ベースURLは `/api/v1/internal`。[TASK-0006](TASK-0006.md) の移設と揃える
- `OcrDeviceReport`（`cpu`/`gpu`）と `OcrDeviceSetting`（`cpu`/`cuda`）を混同しない。型を分けてあるのはこのため
- httpx の `MockTransport` を使えば api を起動せずにテストできる。統合テストは最小限に留める
- `httpx.Client` はコンテキストマネージャで閉じる。長時間動く常駐プロセスのため接続リークに注意
