抽出本文・境界情報・メタデータを保存し、抽出を `succeeded` へ遷移させる内部APIを実装する。

これらを「特別な分岐」ではなく**単一トランザクションと WHERE 条件**で実現するのが設計の要点（[architecture.md](../design/architecture.md) D-4）。

## 実装詳細

### 1. トランザクション構造 🔵

**信頼性**: 🔵 *REQ-025・[architecture.md](../design/architecture.md) D-4・[database-schema.sql](../design/database-schema.sql) §complete より*

**実装ファイル**: `backend/mediavault-api/src/repositories/item_extraction_repository.rs`（追加）

```rust
pub async fn complete_extraction(
    pool: &PgPool,
    extraction_id: Uuid,
    lease_token: Uuid,
    req: &CompleteRequest,
) -> Result<ItemFileExtraction, ApiError> {
    let mut tx = pool.begin().await.map_err(db_error)?;

    // 1) lease token 照合 + 状態確認（行ロック）
    let row: Option<(Uuid,)> = sqlx::query_as(
        "SELECT item_file_id FROM item_file_extractions
         WHERE id = $1 AND lease_token = $2 AND state = 'running'
         FOR UPDATE"
    ).bind(extraction_id).bind(lease_token).fetch_optional(&mut *tx).await?;

    let Some((item_file_id,)) = row else {
        return Err(ApiError::new(ApiErrorCode::InvalidLeaseToken, "..."));
    };

    // 2) item_file_texts を UPSERT（TASK-0004 の関数を &mut *tx で呼ぶ）
    item_file_text_repository::upsert_text(&mut *tx, item_file_id, req).await?;

    // 3) succeeded へ
    let updated = sqlx::query_as::<_, ItemFileExtraction>(
        "UPDATE item_file_extractions
         SET state = 'succeeded', lease_token = NULL, lease_expires_at = NULL,
             progress_current = COALESCE(progress_total, progress_current)
         WHERE id = $1 RETURNING *"
    ).bind(extraction_id).fetch_one(&mut *tx).await?;

    tx.commit().await.map_err(db_error)?;
    Ok(updated)
}
```

### 2. ステップ1の WHERE 条件が3つの要件を同時に満たす 🔵

**信頼性**: 🔵 *REQ-204・REQ-407・EDGE-002・EDGE-003・[dataflow.md](../design/dataflow.md) §データ整合性の保証より*

```sql
WHERE id = $1 AND lease_token = $2 AND state = 'running'
```

| 条件 | 満たす要件 |
|---|---|
| `lease_token = $2` | 古い worker が上書きできない（REQ-407・EDGE-002・PRD §8.8-4） |
| `state = 'running'` | キャンセル済み（`cancelling`）が成功にならない（REQ-204・EDGE-003・PRD §8.8-5） |
| `state = 'running'` | 終端状態が上書きされない（REQ-203） |

**特別な分岐を書かない**。0行だったら `409 INVALID_LEASE_TOKEN` を返すだけでよい。

`FOR UPDATE` により、同一抽出への並列 complete が直列化される。

### 3. 事前バリデーション 🔵

**信頼性**: 🔵 *REQ-408・EDGE-009・EDGE-107より*

トランザクション開始**前**に [TASK-0002](TASK-0002.md) の `validate_complete_request` を呼ぶ。

- `content` の**文字数**上限（`MAX_CONTENT_CHARS`）→ 超過なら `422 UNPROCESSABLE_ENTITY`
- boundaries の `0 <= start <= end <= char_length(content)` → 不正なら `400 VALIDATION_ERROR`

巨大な `content` をトランザクション内へ持ち込む前に弾くことで、DB のロック時間を短縮する。

### 4. UPSERT による置き換え 🔵

**信頼性**: 🔵 *REQ-103・TC-024-03より*

[TASK-0004](TASK-0004.md) の `upsert_text` を `&mut *tx` で呼ぶ。再抽出時に既存行が置き換わり、`item_file_texts` は常に1件を保つ。

`upsert_text` が `&mut PgConnection` を受け取る設計にしてあるのはこのため（`&PgPool` だと同一トランザクションに参加できない）。

### 5. progress の最終化 🟡

**信頼性**: 🟡 *成功時の見た目を整えるための妥当な追加（要件に明記なし）*

成功時に `progress_current = progress_total` とする。heartbeat の最終回が届く前に complete した場合、進捗が「8/10」のまま `succeeded` になるのを避ける。

### 6. ハンドラとルーター 🔵

**信頼性**: 🔵 *[api-endpoints.md](../design/api-endpoints.md) より*

```rust
.route("/internal/extractions/{id}/complete", post(complete_handler))
```

## 注意事項

- **`state = 'running'` を WHERE から外さない**。これがキャンセル済みの成功確定を防ぐ唯一の仕組み。「`cancelling` なら別のエラーを返そう」として条件を緩めると要件違反になる
- バリデーションはトランザクション**前**に行う。巨大な `content` を持ったままロックを保持しない
- `upsert_text` を `&PgPool` で呼ぶと別トランザクションになり、REQ-025 を満たさなくなる。`&mut *tx` を渡す
- 統合テスト4・5は PRD §8.8 の受け入れ条件そのもの。必ず実装する
- `sqlx::Transaction` のライフタイム扱いに注意。`&mut *tx` の再借用パターンを使う
