### 4. バリデーション関数 🔵

**信頼性**: 🔵 *[interfaces.rs](../design/interfaces.rs) §バリデーションより（上限値そのものは 🟡）*

既存 `parse_create_item_file_request`（`src/models/item_file.rs:82`）と同じ、DTO → 検証済み型への変換関数として実装する。

- `parse_item_text_query`: `chunk_index >= 0`、`1 <= chunk_size <= 20000`、既定値適用（EDGE-101・EDGE-102）
- `validate_complete_request`: `content` の**文字数**上限、boundaries の `start <= end <= char_length(content)`（REQ-408・EDGE-009・EDGE-107）
- `is_extractable(file_type)`: `Pdf` / `Image` のみ true（REQ-410）

### 5. label 合成 🔵

**信頼性**: 🔵 *[architecture.md](../design/architecture.md) D-5・設計ヒアリングQ2より*

```rust
pub fn compose_chunk_label(
    boundaries: &[TextBoundary], chunk_start: i64, chunk_end: i64,
) -> Option<String>
```

交差判定は half-open 区間（`b.start < chunk_end && b.end > chunk_start`）。0件→`None`、1件→そのラベル、2件以上→`"{先頭}-{末尾の数値部}"`。

補助関数 `numeric_suffix("p.42") -> Some("42")` により `"p.1-p.3"` ではなく `"p.1-3"` にする。

## 注意事項

- `ApiErrorCode` は enum の網羅マッチのため、variant を追加すると `code_and_status()` のコンパイルエラーで漏れが検出される。この性質を活かし、追加と対応表の記述を同時に行う
- `MAX_CONTENT_CHARS` は暫定値。定数として1箇所に定義し、後で変えやすくする
- `numeric_suffix` はバイト境界でスライスするため、マルチバイト文字を含むラベル（`"第3章"`）で panic しないよう `is_ascii_digit()` で判定する
- 既存 `models/response.rs` は 719行ある。追加箇所は enum 定義（52行付近）と `code_and_status()`（126行付近）の2箇所のみ
