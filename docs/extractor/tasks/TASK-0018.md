## 実装詳細

### 1. パス解決の4段階 🔵

**信頼性**: 🔵 *REQ-403・NFR-103・[interfaces.py](../design/interfaces.py) `resolve_file_ref` より*

**実装ファイル**: `extractor/src/mediavault_extractor/files.py`

**順序が仕様の一部**である。

```python
def resolve_file_ref(ref: FileRef, settings: ExtractorSettings) -> Path:
    # 1. root から許可ルートを引く（未知の root は enum パース時に失敗済み）
    allowed = settings.allowed_root(ref.root).resolve()

    # 2. 事前拒否: 絶対パス・".." を組み立て前に弾く
    candidate_rel = Path(ref.relative_path)
    if candidate_rel.is_absolute() or ".." in candidate_rel.parts:
        raise UnsafePathError(...)

    # 3. resolve() で symlink を展開
    resolved = (allowed / candidate_rel).resolve()

    # 4. 展開後に is_relative_to で判定
    if not resolved.is_relative_to(allowed):
        raise UnsafePathError(...)

    return resolved   # ここを通過して初めて開いてよい
```

**ステップ3と4の順序が要点** 🔵: `resolve()` は symlink を展開する。展開**前**に判定すると、許可ルート内の symlink が外部を指していても通ってしまう。

**「判定前に開かない」** 🔵: `resolve_file_ref` はファイルを開かない。呼び出し側は戻り値の `Path` を受け取ってから初めて `open()` する。

### 2. 事前拒否の二重化 🔵

**信頼性**: 🔵 *REQ-402（api 側でも検証。[TASK-0005](TASK-0005.md)）*

api 側（[TASK-0005](TASK-0005.md)）でも `..` を拒否しているが、worker 側でも独立に検証する。api が信頼できないという想定ではなく、**worker 単体でセキュリティ境界が閉じている**状態にするため。

### 3. サイズ・ページ数の事前検証 🔵

**信頼性**: 🔵 *EDGE-106・[tech-stack.md](../tech-stack.md) §セキュリティ「形式・サイズ・ページ数の上限を開く前に検証する」より*

```python
def check_size_limit(path: Path, settings: ExtractorSettings) -> None:
    size = path.stat().st_size
    if size > settings.extractor_max_file_bytes:
        raise PermanentError(ExtractionErrorKind.SIZE_LIMIT_EXCEEDED, ...)
```

`stat()` は開かずにサイズを取れる。ページ数は PDF を開く必要があるため、[TASK-0020](TASK-0020.md) でページ数取得直後に検証する。

**上限値は暫定** 🟡（[prep.md](../spec/prep.md) §確認事項）。

### 4. 形式判定 🔵

**信頼性**: 🔵 *REQ-062・PRD FR-003・[tech-stack.md](../tech-stack.md) §形式判定より*

**実装ファイル**: `extractor/src/mediavault_extractor/detect.py`

**拡張子だけで判断しない**（REQ-062）。puremagic でファイルシグネチャを読み、拡張子と併用する。

```python
def detect_format(path: Path) -> DetectedFormat:
    signature_type = _detect_by_signature(path)   # puremagic
    extension_type = FileType(_from_extension(path.suffix))
    return DetectedFormat(
        file_type=signature_type,
        mime_type=...,
        extension_mismatch=(signature_type != extension_type),
    )
```

**puremagic を選ぶ理由** 🔵 *[tech-stack.md](../tech-stack.md) より*: 純Python実装で libmagic のネイティブ依存が不要。`python-magic` に比べ Dockerfile が単純になる。

### 5. 拡張子とシグネチャの不一致 🔵

**信頼性**: 🔵 *EDGE-005・[tech-stack.md](../tech-stack.md)「拡張子とシグネチャの不一致を明示的なエラーとして扱う」より*

`.pdf` 拡張子だが実体がPNGといったケースを**黙って処理しない**。`PermanentError(UNSUPPORTED_FORMAT)` として扱う。

シグネチャを信じて処理する選択肢もあるが、DB上の `file_type`（拡張子由来）と実際の処理内容が食い違い、`extractor` メタデータの意味が壊れる。明示的なエラーにして、ユーザーに登録内容の修正を促す。

### 6. 未対応形式 🔵

**信頼性**: 🔵 *REQ-108・PRD FR-003より*

`pdf` / `image` 以外は `PermanentError(UNSUPPORTED_FORMAT)`。api 側でも弾いているが（[TASK-0007](TASK-0007.md)）、worker でも検証する。

## 注意事項

- **`resolve()` の後に判定する**。順序を逆にすると symlink 経由の脱出を防げない。テストケース4がこれを検出する
- **`resolve_file_ref` はファイルを開かない**。関数の責務を「安全なパスを返す」に限定し、開くのは呼び出し側にする。テストケース6でこれを固定する
- Windows 上での開発時、symlink の作成には権限が要る場合がある。テストは Linux コンテナ内で実行するか、`pytest.mark.skipif` で環境を判定する 🟡
- puremagic はシグネチャが読めない場合に空リストを返す。`IndexError` を握りつぶさず、未判定として扱う
- サイズ上限値は暫定。定数化して後から変えやすくする
