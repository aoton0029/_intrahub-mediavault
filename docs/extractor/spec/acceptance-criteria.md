## REQ-001 / REQ-004 / REQ-101 / REQ-102: 抽出リクエスト 🔵

**信頼性**: 🔵 *ヒアリングQ1・PRD §8.3より*

### Given（前提条件）
- Item が存在し、`file_type: pdf` の `item_file` が1件登録されている
- 当該ファイルの実体が共有ボリューム上に存在する

### When（実行条件）
- `POST /api/v1/items/{id}/files/{file_id}/extraction` を呼ぶ

### Then（期待結果）
- `201` と作成された抽出（`state: queued`）が返る
- `item_file_extractions` に1行作られ、`attempts: 0` である

### テストケース

#### 正常系

- [ ] **TC-001-01**: 新規抽出の作成 🔵
  - **入力**: 未抽出のPDFファイルへの `POST .../extraction`
  - **期待結果**: `201`、`state: queued`
  - **信頼性**: 🔵 *ヒアリングQ1より*

- [ ] **TC-001-02**: 未完了の抽出がある状態での再リクエストが冪等 🔵
  - **入力**: `queued` の抽出が存在する状態で同一の `POST`
  - **期待結果**: `200`、既存の抽出が返る。行数は増えない
  - **信頼性**: 🔵 *REQ-101・PRD §8.8より*

- [ ] **TC-001-03**: `running` 中の再リクエストも冪等 🔵
  - **入力**: `running` の抽出が存在する状態で同一の `POST`
  - **期待結果**: `200`、既存の抽出が返る
  - **信頼性**: 🔵 *REQ-101より*

- [ ] **TC-001-04**: 終端状態のあとの再リクエストは新規作成 🟡
  - **入力**: `succeeded` の抽出がある状態で `POST`
  - **期待結果**: `201`、新しい抽出が `queued` で作られる（再抽出）
  - **信頼性**: 🟡 *REQ-102・PRD FR-010から妥当な推測*

#### 異常系

- [ ] **TC-001-E01**: 存在しないファイル 🔵
  - **入力**: 未登録の `file_id`
  - **期待結果**: `404 FILE_NOT_FOUND`
  - **信頼性**: 🔵 *index.md エラーコード表より*

- [ ] **TC-001-E02**: 他Itemに属するファイル 🔵
  - **入力**: `item_id` と `file_id` の組み合わせが不整合
  - **期待結果**: `404 FILE_NOT_FOUND`
  - **信頼性**: 🔵 *REQ-004・item-text.md の同様の規定より*

- [ ] **TC-001-E03**: 抽出非対応の形式 🟡
  - **入力**: `file_type: video` のファイル
  - **期待結果**: `422 UNSUPPORTED_FILE_TYPE`。抽出行は作られない
  - **信頼性**: 🟡 *REQ-410から妥当な推測*

- [ ] **TC-001-E04**: 実体が存在しないファイル 🔵
  - **入力**: DBには登録されているがボリューム上に実体がない
  - **期待結果**: 作成前検証で失敗する（`422`）
  - **信頼性**: 🔵 *PRD §8.3「読み取り可能性を検証してからジョブを作成する」より*

- [ ] **TC-001-E05**: 不正なUUID 🔵
  - **入力**: `file_id` が UUID 形式でない
  - **期待結果**: `400 VALIDATION_ERROR`
  - **信頼性**: 🔵 *index.md より*

#### 境界値

- [ ] **TC-001-B01**: 未完了1件制約の同時実行 🔵
  - **入力**: 同一 `file_id` への `POST` を2並列で送る
  - **期待結果**: DBに未完了行が1件だけ。部分UNIQUE index 違反が適切に `200` へ変換される
  - **信頼性**: 🔵 *REQ-044より*

## REQ-003 / REQ-202 / REQ-205 / REQ-207: キャンセル 🔵

**信頼性**: 🔵 *PRD FR-008・§8.5・§8.8より*

### Given（前提条件）
- 抽出が `queued` または `running` である

### When（実行条件）
- `POST /api/v1/items/{id}/files/{file_id}/extraction/cancel` を呼ぶ

### Then（期待結果）
- `queued` の場合は即座に `cancelled`
- `running` の場合は `cancelling` へ遷移し、worker の確認後に `cancelled`
- いずれの場合も成功結果は確定されない

### テストケース

#### 正常系

- [ ] **TC-003-01**: `queued` の即時キャンセル 🔵
  - **入力**: `queued` の抽出への cancel
  - **期待結果**: `state: cancelled`（終端）
  - **信頼性**: 🔵 *PRD §8.5 状態遷移図より*

- [ ] **TC-003-02**: `running` のキャンセルが worker へ伝わる 🔵
  - **入力**: `running` の抽出への cancel
  - **期待結果**: `cancelling` へ遷移 → 次の heartbeat レスポンスに キャンセル要求が含まれる → worker が `cancelled` を送信 → `cancelled`
  - **信頼性**: 🔵 *PRD §8.8「キャンセル要求がworkerへ伝わり、終端状態へ遷移する」より*

- [ ] **TC-003-03**: worker がページ境界でキャンセルを検知して中断する 🔵
  - **入力**: 10ページPDFの3ページ目処理中にキャンセル
  - **期待結果**: 4ページ目に入る前に中断し、complete を送らない
  - **信頼性**: 🔵 *PRD FR-008・tech-stack.md 実行ループ骨子より*

#### 異常系

- [ ] **TC-003-E01**: 終端状態へのキャンセル 🟡
  - **入力**: `succeeded` の抽出への cancel
  - **期待結果**: `409 EXTRACTION_ALREADY_FINISHED`
  - **信頼性**: 🟡 *REQ-205・既存 `JOB_ALREADY_FINISHED` からの移植*

- [ ] **TC-003-E02**: キャンセル後の complete が拒否される 🔵
  - **入力**: `cancelling` 状態の抽出への内部API complete
  - **期待結果**: 拒否され、`succeeded` にならない。抽出結果も保存されない
  - **信頼性**: 🔵 *REQ-204・PRD §8.5「キャンセル済みジョブの抽出結果を成功として確定してはならない」より*

- [ ] **TC-003-E03**: 二重キャンセルが冪等 🟡
  - **入力**: `cancelling` の抽出へ再度 cancel
  - **期待結果**: エラーにせず現在の状態を返す
  - **信頼性**: 🟡 *EDGE-010から妥当な推測*

## REQ-020 / REQ-021 / REQ-022 / EDGE-001: claim 🔵

**信頼性**: 🔵 *PRD FR-001・§8.4・§8.8より*

### Given（前提条件）
- `queued` の抽出が1件存在する

### When（実行条件）
- worker が `POST /api/v1/internal/extractions/claim` を呼ぶ

### Then（期待結果）
- 抽出が `running` へ遷移し、lease token・lease期限・検証済みファイル参照が返る

### テストケース

#### 正常系

- [ ] **TC-020-01**: claim で lease token とファイル参照が返る 🔵
  - **入力**: `queued` が1件ある状態での claim
  - **期待結果**: `state: running`、`lease_token`、`lease_expires_at`、ファイル参照、`item_file_id`、`file_type`、ファイルサイズ
  - **信頼性**: 🔵 *REQ-021・REQ-022・PRD §8.4より*

- [ ] **TC-020-02**: 実行可能な抽出がない場合 🟡
  - **入力**: `queued` が0件の状態での claim
  - **期待結果**: 空のレスポンス（`204` または `data: null`）。worker はポーリング間隔だけ待つ
  - **信頼性**: 🟡 *tech-stack.md 実行ループ `if job is None: sleep(...)` から妥当な推測*

- [ ] **TC-020-03**: アップロード経路のファイル参照が解決できる 🟡
  - **入力**: `path` が `{item_id}/{uuid}.pdf` の相対パスであるファイル
  - **期待結果**: worker の許可ルート（`/srv/mediavault`）から解決可能な形で参照が返る
  - **信頼性**: 🟡 *item-files.md の2経路規約から妥当な推測。具体形式は設計フェーズで確定*

- [ ] **TC-020-04**: リンク経路のファイル参照が解決できる 🟡
  - **入力**: `path` が `/srv/anime/...` の絶対パスであるファイル
  - **期待結果**: worker の許可ルート（`/library`）から解決可能な形で参照が返る
  - **信頼性**: 🟡 *同上*

#### 異常系

- [ ] **TC-020-E01**: 無認証の claim が拒否される 🔵
  - **入力**: `Authorization` ヘッダなしでの claim
  - **期待結果**: `401 UNAUTHORIZED`
  - **信頼性**: 🔵 *PRD §8.8「内部APIを無認証で呼び出せない」より*

- [ ] **TC-020-E02**: 誤ったAPIキー 🔵
  - **入力**: `INTERNAL_API_KEY` と不一致の値
  - **期待結果**: `401 UNAUTHORIZED`
  - **信頼性**: 🔵 *index.md より*

- [ ] **TC-020-E03**: 公開APIから claim できない 🔵
  - **入力**: `/api/v1/extractions/claim` 等の公開パスからの呼び出し
  - **期待結果**: `404`（そもそも公開ルートに存在しない）
  - **信頼性**: 🔵 *REQ-406・PRD §8.4より*

#### 境界値

- [ ] **TC-020-B01**: 2台の worker が同じ抽出を claim できない 🔵
  - **入力**: `queued` 1件に対して2台の worker が同時に claim
  - **期待結果**: 片方だけが取得し、もう片方は空。同一抽出が二重実行されない
  - **信頼性**: 🔵 *PRD §8.8「2台のworkerが同じジョブを同時にclaimできない」より*

- [ ] **TC-020-B02**: lease 切れの抽出が再claimできる 🔵
  - **入力**: `lease_expires_at` を過ぎた `running` の抽出
  - **期待結果**: 再claimされ、`attempts` が加算される
  - **信頼性**: 🔵 *PRD §8.8「lease切れジョブを安全に再取得できる」・REQ-118より*

## REQ-024 / REQ-025 / REQ-065: complete 🔵

**信頼性**: 🔵 *PRD §8.2・§8.4・FR-007より*

### Given（前提条件）
- 抽出が `running` で、有効な lease token を保持している

### When（実行条件）
- worker が抽出本文・境界情報・メタデータとともに complete を呼ぶ

### Then（期待結果）
- `item_file_texts` が保存され、抽出が `succeeded` へ遷移する。両者は同一トランザクション

### テストケース

#### 正常系

- [ ] **TC-024-01**: 抽出結果保存と成功遷移が同時に確定する 🔵
  - **入力**: 有効な complete
  - **期待結果**: `item_file_texts` に行があり、抽出が `succeeded`。片方だけ成立する状態が発生しない
  - **信頼性**: 🔵 *PRD §8.8「抽出結果保存とジョブ成功が不整合にならない」より*

- [ ] **TC-024-02**: 報告項目がすべて保存される 🔵
  - **入力**: `content`、`boundaries`、`extraction_version`、`extracted_at`、抽出方式、OCRデバイス/エンジン/モデル
  - **期待結果**: すべて `item_file_texts` に永続化される
  - **信頼性**: 🔵 *PRD FR-007より*

- [ ] **TC-024-03**: 再抽出で既存行が置き換わる 🔵
  - **入力**: 既に `item_file_texts` がある `item_file_id` への complete
  - **期待結果**: 行が置き換えられ、`extraction_version` と `extracted_at` が更新される。行は1件のまま
  - **信頼性**: 🔵 *REQ-103・item-text.md より*

#### 異常系

- [ ] **TC-024-E01**: 古い lease token での complete が拒否される 🔵
  - **入力**: lease 失効後に再claimされた抽出へ、旧 token で complete
  - **期待結果**: `409 INVALID_LEASE_TOKEN`。結果は保存されない
  - **信頼性**: 🔵 *PRD §8.8「古いworkerからのcompleteが拒否される」・EDGE-002より*

- [ ] **TC-024-E02**: 終端状態への complete が拒否される 🔵
  - **入力**: `cancelled` の抽出への complete
  - **期待結果**: 拒否される
  - **信頼性**: 🔵 *REQ-203・REQ-204より*

- [ ] **TC-024-E03**: 保存サイズ上限超過 🟡
  - **入力**: 上限を超える `content`
  - **期待結果**: complete が拒否され、再試行不可のエラーとして記録される
  - **信頼性**: 🟡 *EDGE-009・PRD §8.7から妥当な推測*

#### 境界値

- [ ] **TC-024-B01**: boundaries の整合性検証 🟡
  - **入力**: `end` が本文長を超える boundaries
  - **期待結果**: 保存が拒否される
  - **信頼性**: 🟡 *EDGE-107から妥当な推測*

## REQ-005 〜 REQ-008 / REQ-115 〜 REQ-117: Item Text API 🔵

**信頼性**: 🔵 *item-text.md・PRD §8.6より*

### Given（前提条件）
- 対象ファイルの抽出が完了し、`item_file_texts` に本文がある

### When（実行条件）
- `GET /api/v1/items/{id}/text?chunk_index=0&chunk_size=4000` を呼ぶ

### Then（期待結果）
- 要求されたチャンクのみが返り、`total_chunks` と `extraction_version` が含まれる

### テストケース

#### 正常系

- [ ] **TC-005-01**: 先頭チャンクの取得 🔵
  - **入力**: `chunk_index=0`、`chunk_size=4000`、本文48000文字
  - **期待結果**: `total_chunks: 12`、`size: 4000`、先頭4000文字
  - **信頼性**: 🔵 *item-text.md サンプルレスポンスより*

- [ ] **TC-005-02**: `label` にページ番号が入る 🔵
  - **入力**: ページ境界に対応するチャンク
  - **期待結果**: `label: "p.1"` 等
  - **信頼性**: 🔵 *REQ-042・ヒアリングQ5より*

- [ ] **TC-005-03**: 境界に対応しないチャンクは `label: null` 🔵
  - **入力**: ページ境界と一致しないチャンク
  - **期待結果**: `label: null`
  - **信頼性**: 🔵 *item-text.md チャンク分割の規約より*

  - **期待結果**: `index` はページ番号ではなく 0,1,2,... の連番
  - **信頼性**: 🔵 *REQ-413・item-text.md 最重要規約より*

  - **入力**: 同一条件で2回取得
  - **期待結果**: 同じ `index` に同じ本文
  - **信頼性**: 🔵 *REQ-414・item-text.md より*

- [ ] **TC-005-06**: `file_id` 省略で抽出済み1件なら自動選択 🔵
  - **入力**: 抽出済みファイルが1件のItem
  - **期待結果**: そのファイルが対象になる
  - **信頼性**: 🔵 *item-text.md 主ファイルの解決より*
